# Публикация Читавука в Google Play

Справка для того, кто будет заводить приложение в Play Console. Составлена по
сборке **1.6.0 (versionCode 19)** от 28 июля 2026 года.

Читать сверху вниз: первый раздел — то, без чего публиковать нельзя, дальше
данные для заполнения форм.

---

## 1. Состояние готовности

Блокирующие пункты закрыты в сборке 1.6.0. Ниже — что было и как сейчас, чтобы
при проверке в Console было понятно, где смотреть.

### 1.1. Библиотека внутри приложения — закрыто

Каталог `frontend/assets/library/` (книги Роулинг и Библия, 32 МБ) исключён из
сборки: в `pubspec.yaml` его нет среди ассетов. Раздел «Бесплатная библиотека»
сам скрывается, когда ассетов нет, и главный экран предлагает открыть свой
файл. Сборка при этом похудела примерно на треть.

Проверить: `unzip -l frontend/build/app/outputs/flutter-apk/app-release.apk |
grep assets/library` — вывод должен быть пустым.

### 1.2. Политика конфиденциальности — закрыто

Опубликована по адресу **https://citavuk.ru/privacy**, доступна без входа. Этот
адрес и указывается в Play Console в поле «Политика конфиденциальности».
Исходный текст — `docs/privacy-policy.md`, страница — `web/src/pages/Privacy.tsx`,
копия внутри приложения — `frontend/lib/screens/privacy_screen.dart`.

### 1.3. Удаление аккаунта — закрыто

Play требует, чтобы удалить аккаунт можно было **из приложения и по веб-ссылке**.

| Где | Как |
|---|---|
| Приложение | «Ещё» → «Аккаунт и синхронизация» → «Удалить аккаунт» |
| Сайт | https://citavuk.ru/account → «Удалить аккаунт» |
| Сервер | `POST /v1/auth/account/delete`, каскадно сносит книги, слова, карточки, прогресс |

В Play Console поле называется «URL для запроса на удаление аккаунта» — туда
идёт **https://citavuk.ru/account**.

### 1.4. Вход через Google сломается после публикации — если не подготовиться

Это ломается у всех и заметно не сразу.

Play подписывает приложение **своим** ключом (Play App Signing), а не тем,
которым подписан загруженный файл. Google OAuth сверяет отпечаток
подписи. Значит, после публикации у приложения будет другой SHA-1, и вход через
Google перестанет работать, пока в Google Cloud Console не добавлен отпечаток
**ключа Play**, а не локального.

Порядок такой:

1. Загрузить сборку в Play Console (внутреннее тестирование).
2. Открыть **Play Console → Тестирование и релиз → Настройка → Целостность
   приложения → Подписание приложений**.
3. Скопировать оттуда SHA-1 сертификата подписи приложения.
4. Добавить его в Google Cloud Console → Credentials → OAuth 2.0 Client ID
   типа Android, package `com.srbskiread.srbski_read`.
5. Локальный отпечаток (см. 3.2) тоже оставить — им подписаны сборки с сайта.

Это единственный оставшийся шаг, который нельзя сделать заранее: SHA-1 ключа
Play появляется только после первой загрузки.

### 1.5. Мелочи — закрыто

- `usesCleartextTraffic` убран. Вместо него `network_security_config.xml`:
  HTTPS обязателен, исключение только для localhost и 10.0.2.2 (отладка).
- Отладочные символы снимаются штатно: для этого в Android SDK доустановлены
  `cmdline-tools`. Без них `flutter build appbundle` падает с «failed to strip
  debug symbols», хотя сам AAB уже собран.

**Идентификатор пакета менять поздно.** `com.srbskiread.srbski_read` остался от
прежнего названия проекта и с «Читавуком» не совпадает. Пользователь его не
видит, но после первой публикации он неизменяем навсегда: сменить можно только
заведя другое приложение с нуля. Если название пакета принципиально — решать
надо **до** загрузки.

### 2.1. Разрешения и что о них сказать

| Разрешение | Зачем |
|---|---|
| `INTERNET` | перевод, разбор слов, синхронизация |
| `POST_NOTIFICATIONS` | напоминания о повторении карточек |
| `RECEIVE_BOOT_COMPLETED` | восстановить напоминания после перезагрузки |
| `VIBRATE` | отклик в упражнениях курса |
| `USE_BIOMETRIC`, `USE_FINGERPRINT` | приходят из зависимостей, приложение их не использует |

Последняя строка — повод для проверки. Если биометрия действительно не нужна,
её стоит убрать через `tools:node="remove"` в манифесте: лишние разрешения в
карточке приложения снижают доверие.

Хранилище приложение не запрашивает: файлы открываются системным диалогом
выбора, а он разрешений не требует.

## 3. Подписание

### 3.1. Главное правило передачи

**Ключ подписи никому не передавайте.** Передавать нужно готовый файл `.aab` —
он уже подписан, и для загрузки в Play Console ключ не требуется.

Ключ подписи невосстановим. Потеряв его, вы не сможете выпустить обновление:
Google восстанавливает доступ только через Play App Signing, и только если вы в
нём зарегистрированы.

Что лежит в репозитории и **не должно уходить наружу**:

- `frontend/android/app/citavuk-release.jks` — хранилище ключа;
- `frontend/android/key.properties` — пароли к нему;
- `.env` в корне — ключ DeepL, пароль к базе, секреты OAuth.

Все три уже в `.gitignore`. Если понадобится передать ключ (например, вы
передаёте выпуск целиком), то только по зашифрованному каналу и никогда одним
сообщением с паролем.

### 3.2. Отпечатки текущего ключа

Ими подписаны сборки, которые лежат на citavuk.ru:

```
Владелец:  CN=Citavuk Release, O=Ivan Lindgren, C=RU
Алгоритм:  RSA 2048
Алиас:     CITAVUK
SHA-256:   91a3b25394a4342a384d9faf5cc89708f9c6c6967acc9fe9a65ce6f0a2718d70
SHA-1:     8d0e21b57e465a8ac83cfd11edc12c4814ded5ed
```

Проверить у себя:

```
"$ANDROID_HOME/build-tools/36.1.0/apksigner" verify --print-certs -v \
    frontend/build/app/outputs/flutter-apk/app-release.apk
```

## 4. Что заполнять в Play Console

### 4.1. Аккаунт

Регистрация разработчика — 25 долларов единоразово, платёж невозвратный.
Аккаунт бывает личный и организации; для организации нужен номер D-U-N-S, и
проверка занимает дольше. Google требует подтверждения личности документом и
адресом; на это уходит от нескольких дней.

**Аккаунт заводите на себя.** Доверенному человеку дайте доступ как
пользователю: Play Console → Пользователи и разрешения → Пригласить. Права
достаточно таких:

- «Просмотр сведений о приложении»;
- «Управление выпусками» для нужных дорожек;
- «Ответы на отзывы», если он будет вести поддержку.

Не давайте «Администратор аккаунта»: этой роли хватает, чтобы вывести
приложение из публикации и изменить платёжные данные.

### 4.2. Обязательный этап закрытого тестирования

Для аккаунтов физических лиц Google требует прогнать закрытое тестирование
перед выпуском в продакшен: не менее **12 тестировщиков**, непрерывно
**14 дней**. Тестировщиков нужно собрать заранее — на этом этапе застревают
дольше всего.

Правила Play меняются, поэтому текущее требование смотрите в самом Console, в
разделе публикации.

### 4.3. Карточка приложения

Что понадобится подготовить:

| Материал | Требование |
|---|---|
| Название | до 30 знаков, например «Читавук: сербский язык» |
| Краткое описание | до 80 знаков |
| Полное описание | до 4000 знаков |
| Иконка | 512×512 PNG |
| Обложка | 1024×500 PNG или JPEG |
| Скриншоты телефона | минимум 2, лучше 4–8 |
| Скриншоты планшета | если заявляете поддержку планшетов |
| Категория | Образование |

Текст для описания можно взять со страницы `https://citavuk.ru/downloads` и с
главной — они уже написаны под этот продукт.

### 4.4. Формы, которые заполняются один раз

**Безопасность данных.** Самая кропотливая форма. Указать нужно:

- собираются: адрес почты, имя (при регистрации и входе через провайдера);
- собираются: пользовательский контент — книги, слова, карточки, прогресс;
- данные передаются по шифрованному соединению;
- пользователь может запросить удаление данных;
- данные **не** используются для рекламы и не продаются.

Форма проверяется автоматически и сверяется с поведением приложения. Расхождение
приводит к блокировке обновлений, поэтому заполнять надо по факту, а не «как
безопаснее выглядит».

**Возрастной рейтинг.** Анкета. У обучающего приложения без насилия, азартных
игр и пользовательского общения выходит низкий рейтинг. Один вопрос требует
внимания: приложение позволяет открывать произвольные файлы и ссылки, и это
надо отметить честно.

**Целевая аудитория.** Выбрать «13 лет и старше». Если отметить более младшую
группу, включатся требования Families Policy: отдельная проверка, ограничения на
рекламу и обязательное согласие родителей.

**Реклама.** Рекламы в приложении нет — так и указать.

## 5. Порядок действий

Пункты 1–3 уже выполнены в текущей сборке; начинать надо с четвёртого.

1. ~~Убрать `assets/library` из сборки~~ — сделано.
2. ~~Опубликовать политику конфиденциальности и удаление аккаунта~~ — сделано,
   `https://citavuk.ru/privacy` и `https://citavuk.ru/account`.
3. ~~Собрать `app-release.aab`~~ — сделано, файл лежит в
   `frontend/build/app/outputs/bundle/release/app-release.aab` (80 МБ,
   версия 1.6.0, versionCode 19).
4. Завести аккаунт разработчика, дождаться проверки личности (25 долларов,
   несколько дней).
5. Создать приложение, заполнить карточку (4.3) и три формы (4.4).
   В поля политики и удаления аккаунта подставить адреса из раздела 2.
6. Загрузить `app-release.aab` на дорожку внутреннего тестирования.
7. Взять SHA-1 ключа Play и добавить в Google Cloud Console (пункт 1.4) —
   иначе вход через Google не заработает ни у одного тестировщика.
8. Проверить на живом устройстве: вход через Google, синхронизацию, курс,
   удаление аккаунта.
9. Провести закрытое тестирование: 12 тестировщиков, 14 дней подряд (4.2).
10. Выпустить в продакшен.

Каждая следующая загрузка требует увеличенного `versionCode`: правится
`version: 1.6.0+19` в `frontend/pubspec.yaml` (второе число).

## 6. Что передать доверенному человеку

Достаточно этого:

- файл `app-release.aab`;
- приглашение в Play Console с ролью из пункта 4.1;
- ссылку на этот документ;
- тексты и картинки для карточки приложения.

Не передавайте: `citavuk-release.jks`, `key.properties`, `.env`, доступ к VPS,
роль администратора аккаунта.

## 7. Как пересобрать

```
cd frontend
flutter build appbundle --release   # для Google Play
flutter build apk --release         # для сайта
```

Версия задаётся в `pubspec.yaml` в двух местах: `version: 1.6.0+19` вверху и
`inno_bundle.version` внизу (второе — для установщика Windows, оно не читается
из первого). `versionCode` после каждой публикации в Play обязан расти.
