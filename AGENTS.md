# Читавук — техническая документация для агентов

> «Читавук» (читать + **вук** = волк) — приложение-читалка для изучения сербского:
> читаешь текст, тапаешь по слову → перевод, разбор формы, начальная форма;
> сохраняешь слова в карточки (интервальное повторение); встроенная грамматика
> (падежи, времена, наклонения и грамматика фраз). Маскот — умный волк Читавук.

Этот файл — карта проекта для будущих агентов/разработчиков. Держи его в актуальном
состоянии при значимых изменениях.

Подробное описание архитектуры, потоков данных, платформенных различий, API,
сборки и типовых изменений находится в [`PROJECT_AGENT_GUIDE.md`](PROJECT_AGENT_GUIDE.md).

## 4. Архитектура разбора слова (ключевое)

`AnalysisRepository.analyzeToken()` (`analysis_repository.dart`):
1. **Авто-починка** «битых» букв: `LexiconDb.repair()` — если в слове есть «закорючка»
   (символ не из `[a-zšđžčć]`), подставляет диакритики и ищет существующую форму.
2. **Онлайн (если поднят бэкенд):** POST `/analyze` → CLASSLA даёт лемму, UPOS, feats,
   формы, перевод (с контекстным снятием омонимии).
3. **Офлайн/без сервера:** `LexiconDb.lookupForm()` → лемма/UPOS/feats из словаря;
   служебные слова приоритетнее знаменательных (`_best`, чтобы «da» не спрягалось как
   глагол); перевод — локальный словарь → прямой онлайн sr→ru (Google web endpoint).
Результат — типизированный `WordAnalysis` (surface/lemma/upos/feats/forms/translation).

## 5. Данные и словарь

- **`lexicon.db`** (read-only, бандл) — таблицы:
  - `lexicon(form, lemma, upos, feats, msd)` — `feats` это строка признаков UD
    (`Case=Nom|Gender=Masc|Number=Sing`), `msd` — XPOS (MULTEXT-East, напр. `Ncfsn`).
  - `dictionary(word, translation)` — небольшой sr→ru словарь.
  - Собирается `build_lexicon.py` из `data/ud/*.conllu` (UD_Serbian-SET, CC BY-SA):
    ~21 600 форм, ~9 150 лемм. Это компактная версия — её и бандлим.
- **`user.db`** (read-write, в documents dir) — отделён от словаря, чтобы обновление
  словаря не затирало данные. Таблицы: `books(…, folder)`, `vocabulary`,
  `reviews(vocab_id, ease, interval, reps, due_at, last_reviewed)` (SM-2 lite).
- **SrLex (опц., НЕ бандлится):** `download_srlex.py` качает SrLex (~1.2 ГБ) и строит
  словарь ~900 МБ (`lexicon_srlex.db`). Для мобильного бандла это нереально — годится
  только для серверного использования. Большие файлы в `.gitignore`.
- **Версия бандл-словаря:** при изменении `assets/lexicon.db` подними `_version` в
  `lexicon_db.dart`, чтобы перезалить копию из ассетов в кэш на устройстве.

## 6. Грамматический движок (`grammar_engine.dart`)

- `describe(upos, feats)` → объяснение «Почему так?» с русскими названиями
  (падеж + латинское имя: «Родительный (genitiv)»; местный = «Предложный/Местный»).
- `buildParadigms(...)` → склонение (7 падежей × число) для сущ./прил.,
  спряжение глаголов (prezent/perfekat/futur, а при наличии данных также
  аорист/имперфект). Точные формы — из лексикона; недостающие достраиваются
  осторожными правилами и помечаются `≈`. Подробные темы дополнительно
  объясняют плюсквамперфект и потенцијал.
- `humanFacts`, `posShort/posFull`, `formKeyRu`, `casesReference`, `ruleCards` —
  локализация и контент карточек правил.
- 7 сербских падежей; порядок: Nom, Gen, Dat, Acc, Voc, Ins, Loc.

## 8a. Go-сервер: аккаунты, синхронизация, перевод (`server/`)

Отдельный сервис на Go. Подробности — `server/README.md`, здесь только то, что
обязан знать агент, правящий клиент.

**Адрес.** `AppSettings.syncUrl` (по умолчанию `https://api.citavuk.ru`), отдельно
от `backendUrl`: разбор слов, новости и аудио пока на прежнем Python-сервисе, и
переносить их можно по частям. Неизвестные Go пути проксируются наверх, поэтому
у приложения один адрес.

**Redis/Valkey.** `REDIS_URL` необязателен. Когда он задан, Go использует Redis
как общий token-bucket для rate limit и как L1-кеш переводов перед PostgreSQL.
PostgreSQL остаётся источником истины. После сетевой ошибки circuit breaker на
30 секунд сразу переводит запросы на локальный limiter/PostgreSQL, поэтому
Redis не является точкой отказа. Ключи отделяются `CITAVUK_REDIS_PREFIX`, TTL
переводов задаётся `CITAVUK_REDIS_CACHE_TTL`.

**Аккаунт.** `AuthService` хранит токен сессии в SharedPreferences и
восстанавливает его при запуске **без обращения к сети** — приложение обязано
открываться офлайн. Недействительность выясняется при первом запросе, тогда
срабатывает `handleUnauthorized()`.

Поддержаны три способа входа:

- email + пароль: `POST /v1/auth/register` отвечает `202` и не создаёт сессию,
  пока пользователь не откроет одноразовую ссылку из письма Resend;
- Google: клиент получает ID token, сервер проверяет подпись, issuer, audience
  и `email_verified`; Flutter Android берёт публичный Web client ID через
  `GET /v1/auth/providers`, поэтому секреты и client ID не вшиваются вручную;
- Яндекс: серверный authorization-code flow через `/v1/auth/yandex/start`,
  `/callback`, `/complete`. Секрет Яндекса существует только в `.env` сервера.

**Вход на Windows и Linux** (`lib/services/desktop_oauth_io.dart`). Нативного
SDK Google там нет, поэтому приложение открывает системный браузер и принимает
ответ своим `HttpServer` на `127.0.0.1` со случайным свободным портом. Google —
`POST /v1/auth/google/desktop` (код + PKCE, обмен делает сервер своим
`GOOGLE_CLIENT_SECRET_DESKTOP`), Яндекс — тот же `/start`, но с
`returnTarget: "desktop"` и `returnUrl` на петлевой адрес.

Три вещи, которые здесь легко сломать:

1. **Свой сервер, не `flutter_web_auth_2`.** Тот вешает наблюдатель за
   жизненным циклом и на `AppLifecycleState.resumed` делает
   `_server.close(force: true)`. На телефоне это верно, на Windows `resumed`
   приходит просто при возврате фокуса окну — сокет закрывался почти сразу
   после открытия браузера, и ответ Google прилетал в никуда: в браузере
   оставался голый адрес возврата, в приложении — «вход отменён». Пакет
   остаётся только для Android (Custom Tabs + схема `citavuk://`).
2. **Только системный браузер, без webview.** В embedded webview Google вход
   запрещает (`disallowed_useragent`), и правильно: приложение видело бы
   набираемый пароль.
3. **`returnUrl` проверяется сервером** (`api.parseLoopbackURL`) и хранится
   рядом со `state`. Без проверки `/start` превращается в открытый редиректор,
   уводящий одноразовый код входа на чужой сайт.

В Google Cloud Console нужен клиент типа **Desktop app**: web-клиенту Google
запрещает возврат на петлевой адрес.

Миграция `0004_auth_providers.sql` добавляет `email_verified_at` и таблицы
одноразовых токенов. Сырые verification token, OAuth state и completion code
**никогда не хранятся** — в PostgreSQL лежит только SHA-256. В callback URL
нельзя класть Citavuk session token: используется короткоживущий одноразовый
completion code. Почту существующего аккаунта разрешено связать с OAuth только
после проверки адреса самим провайдером.

Конфигурация: `GOOGLE_CLIENT_ID_*`, `YANDEX_CLIENT_ID`,
`YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI`, `RESEND_API_KEY`,
`CITAVUK_EMAIL_FROM`, `CITAVUK_WEB_URL`,
`CITAVUK_EMAIL_VERIFICATION_TTL`. Полный список — `server/README.md` и
корневой `.env.example`.

**Синхронизация.** `SyncService`: отправить своё → забрать чужое → догрузить
тексты. У каждой записи `uuid`, `updated_at` и флаг `dirty`. Конфликты решаются
по времени: побеждает более позднее изменение.

Инварианты, которые нельзя ломать:

1. Удаление записи — **надгробие** (`deleted = 1`), а не `DELETE`. Иначе другое
   устройство вернёт удалённое обратно при следующей отправке.
2. Флаг `dirty` снимается **только после подтверждения сервером**. Снять раньше
   — потерять изменения при обрыве связи.
3. Любой запрос, показывающий данные пользователю, фильтрует `deleted = 0`.
4. Текст книги адресуется своим sha256 и качается **по требованию**, при
   открытии. Тот же инвариант, из-за которого главный экран не читает `content`.
5. **Адрес текста считают три реализации, и они обязаны совпадать байт в байт.**
   Хешируется НЕ JSON, а абзацы с префиксом длины: `<байт>
<абзац>` подряд.
   Через JSON нельзя: Go всегда экранирует U+2028/U+2029, а Dart и JavaScript —
   никогда, и книга с таким символом (обычное дело для текста из Word) не
   выгружалась бы вовсе. Длина обязательна — простого разделителя мало, любой
   символ встретится внутри абзаца и склеит разные книги.
   Парные наборы примеров: `server/internal/store/content_test.go`,
   `frontend/test/services/sync_content_test.dart`, `web/src/lib/content.test.ts`.

**Перевод.** Главный факт: DeepL хорош на связном тексте и **ненадёжен на
одиночных словах** (`kuća` → «собака», `кућа` → «"Адвокат дьявола"»). Поэтому
слово в читалке переводится внутри предложения с тегом `<w>`, а голое слово
уходит запасному провайдеру. Смещения слова отправляются в **байтах UTF-8**;
Dart считает в UTF-16, пересчёт делает `utf8ByteOffset` — без него на кириллице
пометится не то слово.

## 8b. Веб-версия на React (`web/`)

Сайт citavuk.ru. Отдельное приложение, не Flutter Web: тот собирает веб через
CanvasKit — несколько мегабайт wasm до первой отрисовки, текст рисуется на канве
и потому плохо выделяется и хуже читается дикторами. Приложение остаётся на
Flutter, там эти минусы не проявляются.

**Важно:** `frontend/web/` — служебная папка Flutter (`sqlite3.wasm`,
`sqflite_sw.js`). React живёт в `web/` в корне репозитория, рядом с `server/`.

Ключевые решения — подробности в `web/README.md`:

- **Свой роутер** вместо библиотеки: маршрутов меньше десятка, нужны только
  переход и параметр пути. Разбор путей покрыт тестами.
- **Смещения слова уходят в байтах UTF-8.** JavaScript индексирует строку в
  UTF-16, для кириллицы числа не совпадают. Пересчёт — `utf8ByteOffset`.
- **Ассеты пересобираются** скриптом `web/scripts/prepare-assets.py`: шрифты в
  WOFF2, картинки в WebP двух плотностей (12,1 МБ → 1,5 МБ). Результат в
  репозитории не хранится.
- **Тема применяется до первой отрисовки** скриптом в `index.html`, иначе на
  тёмной теме мигает светлый фон.
- **Каждая анимация спрашивает `useReducedMotion`.**

**Синхронизация** (`web/src/api/sync.ts`) повторяет модель приложения:
отправить своё → забрать чужое → догрузить тексты. В общем sync cursor идут
книги, словарь и SRS reviews. Хранилище — IndexedDB
(`web/src/lib/db.ts`), а не localStorage: тот ограничен ~5 МБ и синхронен, а
книги с других устройств его переполнят. Метаданные и текст лежат в разных
хранилищах — список книг не должен вытаскивать в память сами книги.

Инварианты те же, что в приложении: удаление оставляет надгробие, флаг `dirty`
снимается только после подтверждения сервером, текст качается при открытии
книги, а не при синхронизации. При снятии `dirty` обязательно сравнивается
отправленный `updated_at`, чтобы параллельная локальная правка не потерялась.

React-маршруты `/course` и `/course/lesson/:id` используют тот же
`frontend/assets/course/course_bundle.json`, атласы и звуки, что Flutter.
`web/scripts/prepare-course-assets.mjs` переносит их в production assets.
В React упражнения перемешиваются внутри уровня сложности при каждой попытке,
matching нельзя проверить до заполнения всех пар, а статус `completed` ставится
только при достижении `passThreshold`. Для свободного ввода используется
экранная клавиатура сербских спецсимволов. Пока исходный атлас неровный,
`CourseSprite` намеренно показывает один увеличенный кадр без анимации.
Маршруты `/listening` и `/listening/:id` работают с `/audio/*`; длинный
транскрипт рендерится лениво через `content-visibility`.

Авторизация веба живёт в `web/src/state/auth.tsx`. `/verify-email` завершает
регистрацию по ссылке из письма, `/auth/yandex` обменивает одноразовый код
callback на сессию. Не записывать токен сессии в query string: URL попадает в
историю, логи прокси и `Referer`.

Импорт библиотеки поддерживает TXT, Markdown, DOCX и PDF. Mammoth и PDF.js
подгружаются динамически. Текстовый слой PDF извлекается в браузере; PDF-скан
отправляется в `/documents/extract`, где Tesseract использует `srp` и
`srp_latn`. Не переносить OCR-модели в основной web-bundle.
При недоступном Space Tesseract.js обрабатывает не более 12 страниц одним
worker; лимит защищает вкладку от роста памяти.

**Worker PDF.js лежит в `public/pdf.worker.js`**, копируется при сборке
(`npm run prepare:worker`). Не возвращать сборку worker'а через Vite: тот даёт
имя с расширением `.mjs`, которого нет в `mime.types` nginx, файл уходит как
`application/octet-stream`, и браузер отказывается исполнять модуль. Хуже того,
имя содержит хеш и не меняется — один раз закешированный неверный ответ с
`immutable` не исправить ничем. Собирать сайт только через `npm run build`, а не
`vite build`: иначе worker в `dist/` не попадёт, и импорт PDF молча отвалится.

### Абзацы в PDF (`web/src/lib/reflow.ts`, `frontend/lib/utils/reflow.dart`)

PDF хранит строки страницы, а не абзацы. Наивный разбор давал крайности: либо
каждая зрительная строка становилась абзацем, либо целая страница склеивалась в
один кирпич. Абзацы восстанавливаются по признакам вёрстки — короткая последняя
строка, конец предложения, маркер списка, заголовок, перенос по слогам; заодно
выбрасываются колонтитулы (строка, повторяющаяся на ≥60% страниц) и номера
страниц.

**Правила обязаны совпадать в обеих реализациях**: адрес книги при
синхронизации считается от списка абзацев, и разное разбиение означает две
разные книги вместо одной. Парные наборы примеров —
`web/src/lib/reflow.test.ts` и `frontend/test/services/reflow_test.dart`.

Во Flutter текст берётся через `extractTextLines`, а строка собирается из
`wordCollection`: `extractText(layoutText: true)` иногда не ставит пробел между
соседними словами («предвиђено је120 минута»), потому что в PDF пробела и нет —
слова просто нарисованы рядом. По разбору на слова видно, что они разные.

### Читалка веба (`web/src/pages/Reader.tsx`)

Оформление задаётся `web/src/lib/readerSettings.ts` и повторяет
`ReaderSettings` приложения по именам полей: кегль, интерлиньяж, разрядка,
шрифт, отступ абзаца, красная строка, выключка, ширина колонки, цвет страницы,
уровень выделения основы слова.

- **Хранятся в localStorage, не в IndexedDB и не на сервере.** Настройки нужны
  синхронно при первой отрисовке, иначе книга мигнёт чужим шрифтом. Между
  устройствами они намеренно не переносятся: комфортный кегль на телефоне и на
  мониторе разный.
- **Разбор прочитанного обязан быть устойчив** (`sanitize`): в хранилище может
  оказаться что угодно, а читалка обязана открыться.
- **Отступ абзаца — переменная `--reader-gap`, а не `marginBottom` в строчном
  стиле.** Строчный перебивает любое правило и оставляет лишний отступ под
  последним абзацем.
- **Звук перелистывания синтезируется** (`web/src/lib/pageTurn.ts`), файла нет:
  шелест — это отфильтрованный шум, и кодом он короче, чем килобайтами. Контекст
  создаётся при первом воспроизведении: до действия пользователя браузер держит
  `AudioContext` в `suspended`.

### Папки библиотеки (`web/src/lib/folders.ts`)

Папка — это поле `folder` у книги, а не отдельная сущность. Поле с первого
выпуска ходит в протоколе синхронизации (`books.folder` в `0001_init.sql`),
поэтому раскладка едет между устройствами без новой таблицы и версии протокола.
Плата: пустую папку хранить не в чем, она живёт в localStorage этого браузера
до первой книги — и раздел говорит об этом прямо.

### Словарь и карточки (`web/src/pages/Cards.tsx`, `web/src/lib/srs.ts`)

Раздел `/cards` отвечает на вопрос «куда девается сохранённое слово». Расчёт
срока — копия `UserDb.gradeCard` из приложения, и **совпадать он обязан**:
карточки синхронизируются, и слово, оценённое на телефоне и в браузере, должно
получить один и тот же следующий срок.

### Дворец памяти (`web/src/pages/Palace.tsx`, `web/src/palace/scenes.tsx`)

Сцена — не картинка с невидимыми зонами поверх, а список предметов: предмет сам
себя рисует и сам является местом для слова. Иначе пришлось бы согласовывать
рисунок и координаты зон и однажды сдвинуть одно, забыв про другое.

Порядок обхода всегда один и тот же — в этом весь приём, перемешивать его
нельзя, хотя для обычного повторения перемешивание было бы нормой.

Дворцы синхронизируются наравне с книгами и словарём (`palaces` в `Changes`,
таблица из `0006_palaces.sql`). Решения, которые стоит знать:

- **Развеска хранится одним `jsonb`, а не таблицей «предмет — слово».**
  Отдельная таблица позволила бы слить два устройства по отдельным предметам, но
  это не то, чего человек хочет: дворец — цельная картина, и «половина
  расстановки с телефона, половина с компьютера» бессмысленна. Слияние идёт по
  времени изменения дворца целиком, как у книг.
- **`scene_id` сервер не проверяет.** Набор комнат меняется выпусками клиента, и
  сервер, знающий этот список, пришлось бы выкатывать раньше каждого такого
  выпуска.
- **Длинные значения укорачиваются, а не отвергаются** (`clip`). Ошибка в
  upsert прерывает всю посылку: одно слишком длинное поле навсегда сломало бы
  синхронизацию устройства, и починить это пользователь бы не смог. Обрезка идёт
  по границе символа — срез ровно по байту разрубил бы кириллицу.
- **Индекс `dirty` добавлен в версии 4 схемы IndexedDB.** Дворцы, построенные до
  синхронизации, полей `dirty`/`deleted` не имеют, а запись без ключа индекса в
  индекс не попадает — такой дворец никогда бы не уехал на сервер. Транзакция
  смены версии проходит по ним курсором и помечает к отправке.

### Материалы для поступления (`web/scripts/build-materials.py`)

Каталог тестов, решений и пособий сербских учреждений: ЗВКОВ (приём в гимназии)
и факультеты всех четырёх государственных университетов — Белградского,
Нови-Садского, Нишского, Крагуевацкого. Два уровня разделены полем `level`.

- **Файлы не хранятся.** Каталог — указатель: описание и ссылка на источник.
  Скачивание идёт по явному нажатию через `GET /v1/documents/fetch`.
- **Каждая ссылка проверяется при сборке** (код ответа, сигнатура `%PDF-`,
  размер). Битая ссылка на учебник хуже отсутствующей: она тратит время ровно
  тогда, когда человек готовится к экзамену.
- **Один генератор — два потребителя.** Скрипт пишет и `web/src/materials/`,
  и `frontend/assets/materials/`. Две копии, собранные по-разному, однажды
  покажут людям разное.
- Превью в вебе (`components/PdfStrip.tsx`) рисует первые 5 страниц **само,
  без нажатий**, но только когда карточка доехала до экрана и не более двух
  документов одновременно: иначе заход в раздел утянул бы сотни мегабайт чужого
  трафика и подвесил вкладку.
- **Адрес нормализуется при сборке** (`normalize_url`). Часть сайтов даёт ссылки
  с пробелами прямо в пути; браузер это чинит, а `http.client` отвергает запрос
  целиком, и на одной такой ссылке останавливалась вся сборка.
- **Предмет, заданный в описании источника, должен быть проверен по содержимому
  файла**, а не угадан по названию факультета. Сборник Технологического
  факультета Нови-Сада помечен химией потому, что открывается строкой
  «NASTAVNI PROGRAM HEMIJA».
- Источник, который по прямому адресу отдаёт HTML вместо PDF, в список не
  добавляется: проверка всё равно отбросит его файлы, а запросы на каждой
  сборке останутся. Такой случай — ИМИ ПМФ Крагуеваца, в `SOURCES` про него
  оставлен комментарий.

`/admin` — защищённая панель статистики, пользователей, инцидентов и курсов.
Роль приходит как `isAdmin` и всегда проверяется Go middleware. Курсы имеют
состояния draft/published/archived; клиентам отдаётся только published.
Основной курс React и Flutter ищут в
`GET /v1/course/bundle/sr_grammar_prosvirina`, затем используют локальный
bundle. Администраторы задаются `CITAVUK_ADMIN_EMAILS`.

Проверки: `npm run lint`, `npm run test`, `npm run build`.

### Выкатка и грабли на сервере

VPS `85.137.89.21` — **общая машина**: там же ISPmanager, чужие сайты, почта
(exim4/dovecot), DNS (BIND) и mysql. Скрипты трогают только `/opt/citavuk`,
`/var/www/citavuk`, `/var/www/citavuk-files` и свои файлы в `conf.d`.

- `server/deploy/deploy.sh [--nginx]` — Go-сервер.
- `web/deploy/deploy.sh [--nginx]` — сайт.
- `web/deploy/publish-apps.sh` — APK, установщик Windows, портативный zip, архив
  Linux и `latest.json` (манифест автообновления настольных сборок; текст «что
  нового» берётся из `frontend/deploy/release-notes.txt`).

Грабли, на которые уже наступали:

1. **`types { … }` в nginx ЗАМЕНЯЕТ таблицу типов, а не дополняет её.** Правка
   MIME для `.mjs` на уровне `server` увела `index.html` в
   `application/octet-stream`, и браузеры начали скачивать сайт вместо показа.
   Точечно чинится только через `default_type` в отдельном `location`.
   Поэтому `deploy.sh` проверяет **Content-Type**, а не только код ответа: по
   кодам такое незаметно, там честные 200.
2. **Простой `scp` конфига nginx затирает TLS-блок certbot** — сайт остаётся
   без HTTPS. `--nginx` делает копию, кладёт шаблон, заново запускает
   `certbot --nginx`, проверяет `nginx -t` и при неудаче возвращает прежний
   файл. На общей машине битый конфиг кладёт заодно почту и чужие сайты.
3. **Сборки приложений лежат вне `/var/www/citavuk`.** Выкатка сайта подменяет
   этот каталог целиком; файлы внутри исчезали бы при каждом деплое.
4. **«Не открывается citavuk.ru, ошибка сертификата» — почти всегда кеш DNS.**
   Апекс когда-то указывал на парковку reg.ru (`95.163.244.138`), TTL 86400, и
   старый ответ живёт в кеше провайдера сутки; на парковке сертификат чужой,
   отсюда и предупреждение. Прежде чем чинить TLS, сверь фактический адрес:
   `curl -sv https://citavuk.ru/` показывает, куда реально пошло соединение.
   Авторитетно проверять через `dig A citavuk.ru @ns1.reg.ru`.

### Сборка под Linux (`frontend/deploy/linux/`)

`./deploy/linux/build.sh` из каталога `frontend/` собирает приложение в
контейнере и кладёт `build/citavuk-linux-x64.tar.gz` — оттуда его забирает
`publish-apps.sh`.

- **Контейнер, а не машина разработчика.** Flutter собирает Linux только на
  Linux, а результат зависит от версии glibc того хозяина, где его собрали.
- **База — Ubuntu 22.04, а не последняя.** glibc 2.35: бинарник, собранный на
  24.04, на 22.04 не запустится вовсе («GLIBC_2.38 not found»), обратное
  направление работает. Плюс `desktop_webview_window` просит через pkg-config
  именно `webkit2gtk-4.0`, которого в 24.04 уже нет.
- **Список пакетов повторяет `linux/flutter/generated_plugins.cmake`**:
  gstreamer нужен `audioplayers_linux`, webkit2gtk — `desktop_webview_window`.
  Появился плагин — список надо дополнить, иначе сборка падает на конфигурации
  CMake.
- **Версия Flutter берётся из локальной установки.** Собирать релиз другой
  версией, чем та, которой прогнали тесты, — верный способ получить расхождение,
  которое найдётся только у пользователя.
- Установка на стороне пользователя — `install.sh` в архиве: всё уходит в
  `~/.local`, root не нужен.

## 9. Бэкенд (`backend/main.py`)

FastAPI, `lifespan` загружает CLASSLA (`classla.Pipeline('sr')`). Эндпоинт `/analyze`
синхронный (FastAPI крутит в threadpool, чтобы блокирующий перевод не вешал loop).
CORS открыт (нужно для Flutter web/desktop). Лексикон-фолбэк читает `../lexicon.db`
(колонки `upos`/`feats`). Перевод: словарь → `deep_translator` (Google).

Аудирование:
- `/audio/lessons` отдаёт `backend/audio_lessons.json` + RSS-подкасты
  `Learn Serbian Podcast` и `Može Kafa Podcast` (mp3 из enclosure).
- `/audio/transcript?url=...&duration=...` лениво вытаскивает полный транскрипт
  со страниц `serbianlanguagelessons.com` через `trafilatura` и строит примерные
  тайминги по длине фраз.
- `/audio/tts?text=...` озвучивает короткие реплики через `gTTS` и кэширует mp3
  в памяти процесса. Новые зависимости backend: `feedparser`, `trafilatura`, `gTTS`.
- `/documents/extract` принимает PDF/DOCX до 32 МБ. PDFium читает текстовый
  слой, а пустые страницы распознаёт Tesseract (`srp+srp_latn`). На запрос
  допускается до 80 OCR-страниц, чтобы бесплатный CPU Space не зависал.
- При наличии `REDIS_URL` новости, статьи, разборы, переводы, TTS, подкасты и
  транскрипты дополнительно попадают в общий TTL-кеш. Память процесса остаётся
  быстрым L1, а при недоступном Redis сервис сразу продолжает без него.

```
  services/   answer_evaluator, serbian_text, mastery_engine, загрузчики
  state/      LessonController, CourseController
  widgets/    ExerciseHost + по виджету на тип упражнения, CitavukSprite
  screens/    CoursePathScreen, LessonScreen
```

### Правила, которые легко нарушить

- **Контент не парсится из книги в рантайме.** Книга → `course_content/*.json`
  руками → валидатор → `frontend/assets/course/course_bundle.json`. Правка
  bundle бессмысленна: он перезаписывается.
- **Исходный JSON пишется кратко.** `normalize.go` дописывает `id`, `unitId`,
  `skillId`, `lessonId`, `difficulty`, `serbianScript` и наследует `sourceRef`
  от unit к упражнению до валидации. Все прежние правила проверяются уже на
  полных объектах. Таблица умолчаний — в `course_content/SCHEMA.md`.
- **Цель обучения от skill подставляется только когда она там одна.** Иначе
  правило «каждая цель покрыта упражнением» закрылось бы само собой; при
  нескольких целях автор перечисляет их в `lesson.objectives`.
- **`č`/`ć` и `dž`/`đ` не нормализуются.** `normalizeAnswer` трогает только
  пробелы, регистр, терминальную пунктуацию и разложенные диакритики.
  Схлопывание этих букв обессмыслит упражнения.
- **Порядок слов проверяется по-настоящему.** `sentence_builder` не принимает
  произвольную перестановку тех же токенов — только подпоследовательность
  допустимого порядка с пропуском необязательных токенов.
- **Разбиение на буквы должно совпадать в Go и Dart.** `splitLetters` есть в
  `tools/course_build/validate.go` и `lib/course/services/serbian_text.dart`.
  Правишь одно — правь второе, иначе валидатор и клиент разойдутся.
- **Исходные PNG лежат вне `frontend/`.** Иначе 15 МБ кадров попадут в APK.
  В приложение входит только `assets/animations/generated/`.
- **Прогресс переживает обновление контента.** `CourseController._reconcile`
  отбрасывает записи об исчезнувших уроках, но не стирает остальное;
  незавершённая попытка снимается при смене `contentChecksum`.

### Типы упражнений

`multiple_choice`, `matching`, `fill_blank`, `sentence_builder`,
`ending_picker`, `letter_unscramble`, `image_description`, плюс два для работы
с текстом:

- **`reading_qa`** — связный текст и вопросы к нему. Текст остаётся на экране,
  пока идут ответы: проверяется понимание прочитанного, а не память. Ответ
  засчитывается целиком.
- **`form_hunt`** — найти в тексте все формы заданного признака. Текст хранится
  списком токенов, а не строкой: делить сербский текст на слова пришлось бы
  одинаково в Go, Dart и TypeScript, и любое расхождение разошлось бы с
  проверкой ответа.

Добавление типа затрагивает четыре места: `tools/course_build/{model,validate}.go`,
`lib/course/models/exercise.dart` + виджет + `answer_evaluator.dart` +
`exercise_host.dart`, `web/src/course/{types.ts,data.ts}` и `ExerciseView` в
`web/src/pages/CourseLesson.tsx`.

### Тренажёрка

Практика по темам вне порядка курса: `lib/course/screens/trainer_screen.dart`
и `web/src/pages/Trainer.tsx` (маршрут `/trainer`, ссылка в шапке и подвале).
Тема — это skill, а не урок. Прогресс уроков тренажёрка **не пишет**: иначе
«пройденный» урок означал бы то разобранную теорию, то удачную серию ответов.
Экран прохождения переиспользуется (`LessonScreen`, `ExerciseView`), своя
копия разошлась бы с курсом на первой же правке.

### Команды

```
cd tools/course_build && go run .                    # валидация + сверка с лексиконом
cd tools/course_build && go run . -out frontend/assets/course/course_bundle.json
cd tools/course_build && go test ./...               # тесты ридера SQLite и сверки
cd tools/sprite_build  && go run .                   # пересборка спрайтов + QA
cd tools/sprite_build  && go run . -check            # atlas устарел?
cd tools/sound_build   && go run .                   # пересборка звуков
cd frontend && flutter test                          # 162 теста
```

Валидатор читает `lexicon.db` собственным минимальным ридером формата SQLite
(`tools/course_build/sqlite_reader.go`) — без CGO и внешних зависимостей.
Конфликт формы с лексиконом даёт предупреждение, отсутствие формы — нет:
словарь покрывает лишь часть языка.

Сборка bundle всегда идёт в strict-режиме: повреждённый контент в production
не попадёт. Модули Go лежат в своих каталогах и сами находят корень репозитория,
поэтому запускать можно откуда угодно.

### Что ещё не сделано

- Регистрация и PostgreSQL реализованы в `server/`; прогресс курса
  синхронизируется через `GET/PUT /v1/course/progress/{courseId}`. Локальная
  копия остаётся обязательной для офлайн-запуска.
- Итоговая контрольная — на карте курса стоит заглушка-карточка (`blueprint` пуст).
- `image_description`: режимы `choose` и `free` реализованы, `build`/`fill`
  требуют расширения схемы (у них нет полей tokens/blanks).
- Курс переписан целиком под программу из 7 частей: 8 units, 48 уроков,
  299 упражнений. Прежние `u_imenice_rod` и `u_padezi` удалены, их темы
  разошлись по `u_imenice`. См. таблицу в `course_content/SCHEMA.md`.
