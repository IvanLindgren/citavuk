# Читавук — техническая документация для агентов

## Авторские уроки преподавателей

- Серверная схема начинается с `0010_teacher_lessons.sql`: заявки и роль
  преподавателя, публичный профиль, уроки, неизменяемые ревизии, прогресс,
  письменные работы, жалобы и уведомления.
- Роль проверяет `requireTeacher` по актуальному статусу заявки, а не по флагу
  клиента. `approved` даёт редактор, `suspended` отбирает доступ сразу.
- Только бесплатные отдельные уроки. `unlisted` публикуется одобренным автором
  сразу, новая публичная ревизия проходит администратора. Старый публичный
  релиз не исчезает на время проверки нового.
- Контент — структурированный JSON. Теория не больше 6000 видимых знаков;
  допустимые видео нормализуются только для YouTube, VK Video, Rutube и Vimeo.
  Потоки видео сервер не извлекает и не проксирует.
- Изображения идут напрямую в S3 по presigned POST policy; ключи существуют
  только на сервере. Flutter кеширует открытые уроки в SharedPreferences и не
  содержит редактора.
- Web: `/teachers`, `/teachers/lessons/:id`, `/lessons`, `/lessons/:slug`,
  `/lesson/link/:token`; отдельная очередь администратора —
  `/admin/lessons`. Flutter: `CommunityLessonsScreen`,
  `CommunityLessonScreen`, `TeacherApplicationScreen`.
- Веб-редактор хранит исходник теории в `content.markdown`, а при каждом
  изменении пересобирает `content.theory`. **Не удалять `theory`:** это
  совместимый fallback для Flutter и ранее выпущенных клиентов. GFM разбирает
  `web/src/lib/lessonMarkdown.ts`; видео записывается расширением
  `@[video](https://...)`, выделенные кегль/шрифт — безопасными директивами
  `{size=24}...{/size}` и `{font=sans}...{/font}`.
- `LessonMarkdownEditor` — единый Markdown-холст с живым рендером и визуальным
  конструктором таблиц. `MarkdownLesson` используется и в предпросмотре, и в
  опубликованном уроке; сербские слова внутри форматированного текста всё ещё
  проходят через `WordReader`.
- Поля упражнений расширены обратно совместимо (`tokens`, `pairs`,
  `acceptedAnswers`, `questions`, `targetWords` и т. д.). Новые уроки получают
  отдельную форму и отдельный интерактив для каждого типа; старые записи только
  с `answer/referenceAnswer` открываются как свободный ответ.
- Кнопка «Пройти урок» не сохраняет и не публикует черновик: она передаёт его в
  тот же `LessonPlayer`, что обслуживает публичный маршрут. В preview письма
  преподавателю не отправляются.
- Публичный урок и предпросмотр идут одинаковыми фазами: теория, затем одно
  упражнение за раз, опциональный диалог и завершение. Flutter повторяет этот
  поток и должен поддерживать те же 11 типов упражнений; каталог и полные уроки
  приходят из `/v1/lessons` и кешируются, поэтому новый опубликованный урок не
  требует выпуска новой версии приложения.
- `AdminLessons` получает полную pending-ревизию, открывает её в том же
  `LessonPlayer` с режимом модератора и только после просмотра вызывает
  `reviewLessonRevision`. Одобрение сразу меняет опубликованную ревизию урока.

## Вукоток — экспериментальная лента (только web)

- Раздел называется **Вукоток**; в коде, API и базе он остался `micro_feed` —
  переименовывать таблицы и ручки ради названия раздела незачем.
- Web-маршрут `/vukotok` вынесен прямо в шапку отдельной кнопкой со значком
  волка. Прежний `/micro-feed` продолжает работать: он разослан в чате и стоит в
  закладках (`isVukotok` в `web/src/components/Header.tsx` знает оба). Flutter
  эту возможность не показывает и API ленты не вызывает.
- Миграция `0014_micro_feed.sql`: реестр источников, очередь импортов,
  модерируемые карточки, события/реакции, профиль интересов и pgvector HNSW для
  `vector(1536)`. Публичной становится только карточка, которую явно
  опубликовал администратор.
- Источники имеют `rights_mode`: `reuse`, `summary_only`, `manual_review`.
  Новостные RSS нельзя перепечатывать: модель делает новый пересказ и карточка
  всегда показывает ссылку/атрибуцию. Пользовательские книги не являются
  источником общей ленты.
- Миграция `0024_beginner_feed_sources.sql` регистрирует нишевые сербские RSS
  о путешествиях, культуре, архитектуре и еде для карточек A1-A2. Операторский
  `feedfill` умеет ограничивать партию конкретными `-sources`, `-max-cefr`,
  числом новых карточек `-add` и жёстким бюджетом `-max-calls`; при таком
  запуске старые черновики нужно отключать через
  `-publish-existing-drafts=false`.
- Production prompt и строгий валидатор находятся в `internal/feed/generator.go`;
  сбор RSS/MediaWiki с серверным allowlist — в `internal/feed/sources.go`.
- Холодная выдача: 50% trending, 30% A2–B1, 20% exploration. После трёх лайков:
  70% embedding, 20% теги, 10% exploration. Просмотры и быстрые пропуски
  исключаются на 14 дней.
- Во всех стратегиях CEFR является обязательным фильтром, а не только частью
  блока easy: сначала идут карточки ровно уровня читателя, затем более лёгкие и
  максимум одна ступень выше (A2 никогда не получает B2/C1). Для вошедшего
  актуальный `users.serbian_level` всегда главнее старого `cefr` профиля ленты.
- Web повторно использует `WordReader` и `/audio/tts`: перевод/разбор по тапу,
  транскрипция, дикторы и озвучка всей карточки не имеют отдельной реализации.
- Полная архитектура, API, источники и пример JSON: `docs/micro-feed.md`.
- Обложка урока хранится в `teacher_lessons.cover_url`, загружается тем же
  защищённым media relay, что изображения теории, и необязательна для старых
  записей. `DELETE /v1/teachers/lessons/:id` мягко архивирует даже уже
  опубликованный урок: прямые ссылки перестают работать, pending-ревизия
  снимается с модерации, а история остаётся в базе.
- `/audio/tts` принимает `voice=sophie|nicholas`. Web и Flutter сохраняют один
  выбор сербского диктора для карточек слов, диалогов, аудирования и
  аудиокниги; неизвестные значения сервер обязан отклонять.

## Объявления, награды и медиа

- Миграция `0012_announcements.sql` добавляет серверные объявления, состояния
  прочтения/скрытия/получения награды и центр уведомлений. Управление находится
  во вкладке «Объявления» web-админки; Flutter и web читают одинаковые
  `/v1/announcements` и `/v1/notifications`.
- Кампания первых 100 пользователей добавлена **черновиком**. Не публиковать её,
  пока в `web/public/img/citavuk-100-readers.svg` не появится финальная
  иллюстрация. Награда `reader_background_100` привязана к аккаунту и доступна
  в настройках читалки только после серверного `claimed_at`.
- Supabase S3 не поддерживает настройку bucket CORS. Браузер не грузит картинки
  прямо в presigned S3 URL: upload policy возвращает короткоживущий
  `/v1/media/upload`, Go проверяет владельца, MIME и SHA-256 и сам выполняет
  подписанный PUT в `/storage/v1/s3`. Прямой browser-to-S3 upload не возвращать.
- `/audio/tts` использует сербские neural voices через `edge-tts`, с gTTS как
  аварийным fallback. Карточка слова показывает фонемную транскрипцию без
  ударения и автоматически произносит слово. Встроенный режим аудиокниги web и
  Flutter хранит позицию, скорость и подсвечивает произносимое слово.
- Android release использует AGP 9.0.1, Gradle 9.1, NDK 28.2 и оптимизированный
  R8 (`minify` + `shrinkResources`). Пока плагины переходят на built-in Kotlin,
  `file_picker` получает legacy KGP точечно в `android/build.gradle.kts`.

> «Читавук» (читать + **вук** = волк) — приложение-читалка для изучения сербского:
> читаешь текст, тапаешь по слову → перевод, разбор формы, начальная форма;
> сохраняешь слова в карточки (интервальное повторение); встроенная грамматика
> (падежи, времена, наклонения и грамматика фраз). Маскот — умный волк Читавук.

Этот файл — карта проекта для будущих агентов/разработчиков. Держи его в актуальном
состоянии при значимых изменениях.

Подробное описание архитектуры, потоков данных, платформенных различий, API,
сборки и типовых изменений находится в [`PROJECT_AGENT_GUIDE.md`](PROJECT_AGENT_GUIDE.md).

## 4. Архитектура разбора слова (ключевое)

`AnalysisRepository.analyzeToken()` (`analysis_repository.dart`):
1. **Авто-починка** «битых» букв: `LexiconDb.repair()` — если в слове есть «закорючка»
   (символ не из `[a-zšđžčć]`), подставляет диакритики и ищет существующую форму.
2. **Онлайн (если поднят бэкенд):** POST `/analyze` → CLASSLA даёт лемму, UPOS, feats,
   формы, перевод (с контекстным снятием омонимии).
3. **Офлайн/без сервера:** `LexiconDb.lookupForm()` → лемма/UPOS/feats из словаря;
   служебные слова приоритетнее знаменательных (`_best`, чтобы «da» не спрягалось как
   глагол); перевод — локальный словарь → прямой онлайн sr→ru (Google web endpoint).
Результат — типизированный `WordAnalysis` (surface/lemma/upos/feats/forms/translation).

## 5. Данные и словарь

- **`lexicon.db`** (read-only, бандл) — таблицы:
  - `lexicon(form, lemma, upos, feats, msd)` — `feats` это строка признаков UD
    (`Case=Nom|Gender=Masc|Number=Sing`), `msd` — XPOS (MULTEXT-East, напр. `Ncfsn`).
  - `dictionary(word, translation)` — небольшой sr→ru словарь.
  - Собирается `build_lexicon.py` из `data/ud/*.conllu` (UD_Serbian-SET, CC BY-SA):
    ~21 600 форм, ~9 150 лемм. Это компактная версия — её и бандлим.
- **`user.db`** (read-write, в documents dir) — отделён от словаря, чтобы обновление
  словаря не затирало данные. Таблицы: `books(…, folder)`, `vocabulary`,
  `reviews(vocab_id, ease, interval, reps, due_at, last_reviewed)` (SM-2 lite).
- **SrLex (опц., НЕ бандлится):** `download_srlex.py` качает SrLex (~1.2 ГБ) и строит
  словарь ~900 МБ (`lexicon_srlex.db`). Для мобильного бандла это нереально — годится
  только для серверного использования. Большие файлы в `.gitignore`.
- **Версия бандл-словаря:** при изменении `assets/lexicon.db` подними `_version` в
  `lexicon_db.dart`, чтобы перезалить копию из ассетов в кэш на устройстве.

## 5a. Английский разбор (`english_engine.dart`, `internal/english/`)

Читавук про сербский, но в сербских учебниках английский работает
языком-посредником, и по такому слову тоже нажимают.

- **Словарь общий:** `tools/build_english_lexicon.py` собирает
  `english_lexicon.json` (18 433 леммы, 4 377 неправильных форм, ~360 КиБ) и
  кладёт **две байт-в-байт одинаковые копии** — `frontend/assets/english/` и
  `server/internal/english/data/`. Разойдись они, сайт и приложение показали бы
  для одного слова разную начальную форму.
- **Источники:** WordNet 3.0 (леммы, части речи, таблицы исключений `*.exc`) и
  Brown Corpus с universal tagset (частотность, служебные слова, модальные
  глаголы — WordNet знаменательными не ограничивается, он ими исчерпывается).
  Из корпуса берутся только счётчики и метки; текст никуда не переносится.
- **Форма не угадывается по окончанию, а проверяется** — то же правило, что в
  сербском движке: кандидат в начальную форму обязан найтись в словаре.
- **WordNet держит отпричастные прилагательные и отглагольные существительные
  отдельными леммами** (`walked`, `making`, `reading`, `quickly`). Такое слово
  разбирается как форма, но только для словообразующих суффиксов
  (-ing/-ed/-ly/-er/-est) и только если оно записано именно теми частями речи,
  которые этот суффикс порождает. `-s` в список не входит: иначе `news` стало
  бы множественным от `new`.
- **Язык определяется по предложению, а не по слову** (`language_router.dart`,
  `internal/english/detect.go`). Иначе нельзя: в сербской латинице `on`, `to`,
  `no`, `most`, `sam`, `list`, `bar` — обычные сербские слова, и все они
  одновременно английские. Внутри фразы неоднозначности почти нет
  («on je došao» против «on the table»).
- **Строки лексикона с `upos = 'X'` за сербский не считаются**: это иноязычные
  вставки из трибанка (там лежит и `the`), таких строк 145. Без этого правила
  английский текст не опознался бы английским никогда.
- Перевод английского слова идёт с `source: 'en'` — параметр появился и в
  `TranslationClient`, и в `/v1/translate`; по умолчанию по-прежнему `sr`.
- `/v1/analyze` принимает необязательное поле `sentence`. Старый клиент его не
  шлёт, и разбор остаётся сербским — контракт совместим.

## 5a. Разбор целой фразы и частотные данные

`POST /v1/analyze/sentence` разбирает фразу, а не слово. Смысл не в сумме
разборов: сербская форма сама по себе почти всегда неоднозначна («kući» — и
дательный, и местный), и выбрать между вариантами может только соседство.
`grammar.Analyze` собирает три вида групп — предложную (падеж выбирается по
таблице управления, **по порядку правил**, а не по порядку разборов слова),
глагольную (вспомогательный глагол с причастием даёт перфект, «bih» — условное,
«budeš» — футур II) и именную (согласование определения). Функция чистая и
проверяется на выдуманных разборах, без словаря вовсе.

Три файла данных из srLex (ReLDI, CC BY-SA 4.0), см. `tools/build_frequency.py`
и `tools/build_forms.py`:

- `frequency.tsv.gz` — 20 тысяч самых частых лемм по порядку. Ранг разводит
  омонимы в `bestReading`: «sam» — это «я есть» (`biti`, ранг 1), а не
  прилагательное «один» (ранг 88). Без этого перфект не собирался вовсе.
- `wordranks.tsv.gz` — 374 тысячи словоформ с рангом своей леммы. На нём стоит
  оценка сложности текста: свой словарь знает 21 тысячу форм, и по нему почти
  каждое слово книги считалось редким.
- `bigforms.tsv.gz` — все разборы форм двенадцати тысяч частых лемм. `LookupForm`
  склеивает их со своими: свои идут первыми (они точны и решают выбор
  прочтения), расширенные добирают охват. Без него «pišem» и «olovkom» не
  опознавались вообще.

Всё три хранятся не картами, а одним куском памяти с двоичным поиском
(`wordranks.go`, `bigforms.go`): в `map[string][]Form` те же данные заняли бы
около 200 МБ, а сервер стоит на общей машине.

## 5b. Уровень сербского

Уровень живёт **на аккаунте** (`users.serbian_level`), а не в разделе. Раньше
его спрашивал один Вукоток и хранил в профиле ленты, ключ которого — устройство
(`actor_key`): тот же человек отвечал заново в браузере, в телефоне и после
чистки хранилища, а прочие разделы о его уровне не знали.

- Пустая строка и `A1` — **разные вещи**: слив их, теряешь право спросить.
- `GET/PUT /v1/profile/level`, `GET/POST /v1/profile/level/test` (десять
  вопросов, по два на ступень; верные ответы наружу не уходят — проверяет
  сервер).
- `handleMicroFeed` переносит профиль гостя на аккаунт при входе
  (`AdoptMicroFeedGuestProfile`), иначе вход означал бы чистый лист.
- `POST /v1/analyze/text-level` оценивает сложность книги по редкости слов.
  Предупреждение срабатывает при разрыве **в две ступени**, а не в одну: читать
  на ступень выше как раз и полезно. Правило продублировано в клиентах
  (`tooHardFor`), чтобы не ходить на сервер за уже известным ответом.

## 5b. Начальная форма для слов вне лексикона

Лексикон хранит в среднем две формы на лемму, поэтому «kućom» в нём просто нет,
и слово показывалось **без основы**. Теперь начальная форма достраивается
правилом: от каждого кандидата строится парадигма, и разбор принимается, только
если из неё получилась ровно эта форма.

`GrammarEngine.lemmaCandidates/matchNoun/matchVerb` (Dart) повторяют
`server/internal/grammar/resolve.go` — правила обязаны совпадать, иначе сайт и
приложение назовут разную начальную форму. Генераторы форм переиспользуются
существующие (`_presentForms`, `_pastParticiple`, `_declension`), поэтому
парадигмы и разбор не могут разъехаться между собой.

Что уходит в словарь, спрашивается при сохранении: словоформа или начальная
форма. Для словоформы в `forms` карточки дополнительно кладутся «форма в
тексте» и «начальная форма» — они уже рисуются чипами и в словаре, и в
карточках.

## 6. Грамматический движок (`grammar_engine.dart`)

- `describe(upos, feats)` → объяснение «Почему так?» с русскими названиями
  (падеж + латинское имя: «Родительный (genitiv)»; местный = «Предложный/Местный»).
- `buildParadigms(...)` → склонение (7 падежей × число) для сущ./прил.,
  спряжение глаголов (prezent/perfekat/futur, а при наличии данных также
  аорист/имперфект). Точные формы — из лексикона; недостающие достраиваются
  осторожными правилами и помечаются `≈`. Подробные темы дополнительно
  объясняют плюсквамперфект и потенцијал.
- `humanFacts`, `posShort/posFull`, `formKeyRu`, `casesReference`, `ruleCards` —
  локализация и контент карточек правил.
- 7 сербских падежей; порядок: Nom, Gen, Dat, Acc, Voc, Ins, Loc.

### Что движок обязан покрывать (и почему именно так)

Правила реализованы дважды — `grammar_engine.dart` и
`server/internal/grammar/` — и обязаны совпадать: приложение разбирает слово
офлайн, сайт спрашивает сервер, и разойтись они могут только молча. Парные
наборы примеров: `frontend/test/services/declension_test.dart` и
`server/internal/grammar/declension_test.go`, `adjective_test.go`.

- **Три врсты существительных, а не одна.** Женский род на согласный
  (`noć`, `stvar`, `ljubav`, `kost`) — отдельный класс: все падежи, кроме
  именительного и винительного единственного, на -i, а творительный проходит
  йотование (`kost → košću`, `ljubav → ljubavlju`). После «р» йотования не
  бывает вовсе: `stvar → stvari`.
- **Мужской род на -a** (`tata`, `sudija`, `Nikola`) склоняется по женскому
  типу, а согласуется по мужскому.
- **Средний род расширяет основу**: `ime → imen-`, `tele → telet-`. Оба класса
  ЗАКРЫТЫЕ и по форме не выводятся — `-e` одинаково у `selo/polje` (расширения
  нет), `ime` и `tele`. Множественное у `-et-` собирательное (`telad`,
  `dugmad`) и склоняется по женскому типу — только из списка, правилом такое не
  достраивается.
- **Беглое «а»** выпадает везде, кроме именительного единственного и
  родительного множественного: `otac → oca`, но `staraca`. Правилом выводится
  `-ac` и многосложное `-ak`; `dan` и `znak` беглого «а» не имеют, и отличить их
  по форме нельзя — они в списке. У слов с беглым «а» звательный всегда на -e с
  чередованием: `starac → starče`, `momak → momče`.
- **Множественное `-ov-/-ev-` считается по СЛОГАМ, а не по буквам.** Слоговое
  «р» — слог (`prst`, `vrt`). По буквам получалось «sporti» и «danovi».
  Исключения (`dan`, `zub`, `gost`, `konj`, `prst`, `vuk`…) — списком: правило
  верное, но исключений у него столько, что без списка оно учит выдумкам.
- **Прилагательное склоняется и показывает ВИД.** Определённый и неопределённый
  (`dobar čovek` / `dobri čovek`, Gen `dobra` / `dobrog`) — то, чем сербское
  прилагательное отличается от русского сильнее всего. Различаются они только в
  мужском и среднем роде единственного числа; в женском и во множественном
  формы совпадают, и это факт языка, а не упрощение таблицы. Мягкая основа
  меняет «о» на «е» (`vrućeg`, `vrućem`) — но не в женском роде (`vrućoj`).
- **Степени сравнения** читаются из `Degree=Cmp|Sup` и достраиваются
  `Comparative`. Правило `-iji` верно для многосложных; односложные образуют
  компаратив йотованием, и у каждого чередование своё (`lep → lepši`,
  `jak → jači`, `mlad → mlađi`, `brz → brži`) — поэтому они перечислены
  списком, а не угаданы.
- **Именные формы глагола называются отдельно.** `VerbForm=Conv` — глаголски
  прилог (деепричастие), `VerbForm=Part|Voice=Pass` — трпни придев. Обе ветки в
  `Describe`/`describe` проверяются РАНЬШЕ падежа: у трпног придева падеж есть,
  и без этого «urađen» объяснялся бы как обычное прилагательное.
- **Не все глаголы на `-ati` спрягаются на `-am`.** `držati → držim`,
  `trčati → trčim`. Правило по окончанию основы напрашивается (почти у всех
  такая основа кончается на č/ž/š), но оно неверно: `slušati → slušam`. Класс
  лексический и задан списком — по той же причине, по которой `presentForms`
  молчит про `-sti`: неверная форма хуже отсутствующей.
- **Строка для показа и список форм — разные вещи.** Где норма допускает два
  варианта, `declension` склеивает их через «/» (`grad / grada`,
  `noću / noći`), а опознание словоформы перебирает `declensionForms`. Пока
  сравнение шло со склеенной строкой, `čoveka` не опознавалось винительным
  никогда.

## 8a. Go-сервер: аккаунты, синхронизация, перевод (`server/`)

Отдельный сервис на Go. Подробности — `server/README.md`, здесь только то, что
обязан знать агент, правящий клиент.

**Адрес.** `AppSettings.syncUrl` (по умолчанию `https://api.citavuk.ru`), отдельно
от `backendUrl`: разбор слов, новости и аудио пока на прежнем Python-сервисе, и
переносить их можно по частям. Неизвестные Go пути проксируются наверх, поэтому
у приложения один адрес.

**Redis/Valkey.** `REDIS_URL` необязателен. Когда он задан, Go использует Redis
как общий token-bucket для rate limit и как L1-кеш переводов перед PostgreSQL.
PostgreSQL остаётся источником истины. После сетевой ошибки circuit breaker на
30 секунд сразу переводит запросы на локальный limiter/PostgreSQL, поэтому
Redis не является точкой отказа. Ключи отделяются `CITAVUK_REDIS_PREFIX`, TTL
переводов задаётся `CITAVUK_REDIS_CACHE_TTL`.

Rate limiter уже распределён через Redis, таблицу PostgreSQL для каждого
запроса не добавлять. Защищённые маршруты используют ключ `user:<uuid>`,
публичные — `ip:<address>`. Для перевода поверх личных buckets есть общий
safety bucket, который защищает общую квоту провайдера; он проверяется после
личного лимита, чтобы уже заблокированный клиент не отнимал токены у остальных.

**Аккаунт.** `AuthService` хранит токен сессии в SharedPreferences и
восстанавливает его при запуске **без обращения к сети** — приложение обязано
открываться офлайн. Недействительность выясняется при первом запросе, тогда
срабатывает `handleUnauthorized()`.

Поддержаны три способа входа:

- email + пароль: `POST /v1/auth/register` отвечает `202` и не создаёт сессию,
  пока пользователь не откроет одноразовую ссылку из письма Resend;
- Google: клиент получает ID token, сервер проверяет подпись, issuer, audience
  и `email_verified`; Flutter Android берёт публичный Web client ID через
  `GET /v1/auth/providers`, поэтому секреты и client ID не вшиваются вручную;
- Яндекс: серверный authorization-code flow через `/v1/auth/yandex/start`,
  `/callback`, `/complete`. Секрет Яндекса существует только в `.env` сервера.

**Вход на Windows и Linux** (`lib/services/desktop_oauth_io.dart`). Нативного
SDK Google там нет, поэтому приложение открывает системный браузер и принимает
ответ своим `HttpServer` на `127.0.0.1` со случайным свободным портом. Google —
`POST /v1/auth/google/desktop` (код + PKCE, обмен делает сервер своим
`GOOGLE_CLIENT_SECRET_DESKTOP`), Яндекс — тот же `/start`, но с
`returnTarget: "desktop"` и `returnUrl` на петлевой адрес.

Три вещи, которые здесь легко сломать:

1. **Свой сервер, не `flutter_web_auth_2`.** Тот вешает наблюдатель за
   жизненным циклом и на `AppLifecycleState.resumed` делает
   `_server.close(force: true)`. На телефоне это верно, на Windows `resumed`
   приходит просто при возврате фокуса окну — сокет закрывался почти сразу
   после открытия браузера, и ответ Google прилетал в никуда: в браузере
   оставался голый адрес возврата, в приложении — «вход отменён». Пакет
   остаётся только для Android (Custom Tabs + схема `citavuk://`).
2. **Только системный браузер, без webview.** В embedded webview Google вход
   запрещает (`disallowed_useragent`), и правильно: приложение видело бы
   набираемый пароль.
3. **`returnUrl` проверяется сервером** (`api.parseLoopbackURL`) и хранится
   рядом со `state`. Без проверки `/start` превращается в открытый редиректор,
   уводящий одноразовый код входа на чужой сайт.

В Google Cloud Console нужен клиент типа **Desktop app**: web-клиенту Google
запрещает возврат на петлевой адрес.

Миграция `0004_auth_providers.sql` добавляет `email_verified_at` и таблицы
одноразовых токенов. Сырые verification token, OAuth state и completion code
**никогда не хранятся** — в PostgreSQL лежит только SHA-256. В callback URL
нельзя класть Citavuk session token: используется короткоживущий одноразовый
completion code. Почту существующего аккаунта разрешено связать с OAuth только
после проверки адреса самим провайдером.

Конфигурация: `GOOGLE_CLIENT_ID_*`, `YANDEX_CLIENT_ID`,
`YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI`, `RESEND_API_KEY`,
`CITAVUK_EMAIL_FROM`, `CITAVUK_WEB_URL`,
`CITAVUK_EMAIL_VERIFICATION_TTL`. Полный список — `server/README.md` и
корневой `.env.example`.

Парольная регистрация дополнительно сверяет домен с vendored CC0-блоклистом
`server/internal/store/disposable_email_blocklist.conf` (более 8 тысяч
доменов). Список зафиксирован на commit источника в `disposable_email.go`; при
обновлении менять данные, commit в комментарии и тесты вместе. Ручной список из
нескольких известных сервисов недостаточен: одноразовые провайдеры постоянно
меняют домены.

**Синхронизация.** `SyncService`: отправить своё → забрать чужое → догрузить
тексты. У каждой записи `uuid`, `updated_at` и флаг `dirty`. Конфликты решаются
по времени: побеждает более позднее изменение.

Инварианты, которые нельзя ломать:

1. Удаление записи — **надгробие** (`deleted = 1`), а не `DELETE`. Иначе другое
   устройство вернёт удалённое обратно при следующей отправке.
2. Флаг `dirty` снимается **только после подтверждения сервером**. Снять раньше
   — потерять изменения при обрыве связи.
3. Любой запрос, показывающий данные пользователю, фильтрует `deleted = 0`.
4. Текст книги адресуется своим sha256 и качается **по требованию**, при
   открытии. Тот же инвариант, из-за которого главный экран не читает `content`.
5. **Адрес текста считают три реализации, и они обязаны совпадать байт в байт.**
   Хешируется НЕ JSON, а абзацы с префиксом длины: `<байт>
<абзац>` подряд.
   Через JSON нельзя: Go всегда экранирует U+2028/U+2029, а Dart и JavaScript —
   никогда, и книга с таким символом (обычное дело для текста из Word) не
   выгружалась бы вовсе. Длина обязательна — простого разделителя мало, любой
   символ встретится внутри абзаца и склеит разные книги.
   Парные наборы примеров: `server/internal/store/content_test.go`,
   `frontend/test/services/sync_content_test.dart`, `web/src/lib/content.test.ts`.

**Перевод.** Главный факт: DeepL хорош на связном тексте и **ненадёжен на
одиночных словах** (`kuća` → «собака», `кућа` → «"Адвокат дьявола"»). Поэтому
слово в читалке переводится внутри предложения с тегом `<w>`, а голое слово
уходит запасному провайдеру. Смещения слова отправляются в **байтах UTF-8**;
Dart считает в UTF-16, пересчёт делает `utf8ByteOffset` — без него на кириллице
пометится не то слово.

Это самая дорогая операция в приложении: на каждое нажатие уходит целое
предложение, а у DeepL Free 500 000 знаков в месяц на всех — примерно четыре
тысячи нажатий, то есть один активный читатель. Поэтому один ответ `InContext`
раскладывается в общий кеш **по трём ключам**, и каждый экономит в своём случае:

| Ключ | Значение | Что экономит |
|---|---|---|
| помеченное предложение (`<w>…</w>`) | ответ DeepL как есть | повторное нажатие на то же слово: из одной записи восстанавливаются и фраза, и слово |
| предложение | перевод предложения | запрос «перевести всю фразу» |
| слово | выровненный фрагмент | всё остальное: предложения не повторяются почти никогда, а сербские слова — постоянно |

Словарная запись — главная из трёх: когда DeepL откажет (месячный предел или
недоступность), запасной путь возьмёт из неё перевод, **выровненный настоящим
DeepL**, вместо ненадёжного перевода одиночного слова. Признак `aligned` при
этом не выставляется: слово выровнено в другом предложении, и клиент честно
показывает, что контекст чужой. Кеш общий на всех пользователей, поэтому вторым
и сотым читателем одной книги квота не тратится вовсе.

## 8b. Веб-версия на React (`web/`)

Сайт citavuk.ru. Отдельное приложение, не Flutter Web: тот собирает веб через
CanvasKit — несколько мегабайт wasm до первой отрисовки, текст рисуется на канве
и потому плохо выделяется и хуже читается дикторами. Приложение остаётся на
Flutter, там эти минусы не проявляются.

**Важно:** `frontend/web/` — служебная папка Flutter (`sqlite3.wasm`,
`sqflite_sw.js`). React живёт в `web/` в корне репозитория, рядом с `server/`.

Ключевые решения — подробности в `web/README.md`:

- **Свой роутер** вместо библиотеки: маршрутов меньше десятка, нужны только
  переход и параметр пути. Разбор путей покрыт тестами.
- **Смещения слова уходят в байтах UTF-8.** JavaScript индексирует строку в
  UTF-16, для кириллицы числа не совпадают. Пересчёт — `utf8ByteOffset`.
- **Ассеты пересобираются** скриптом `web/scripts/prepare-assets.py`: шрифты в
  WOFF2, картинки в WebP двух плотностей (12,1 МБ → 1,5 МБ). Результат в
  репозитории не хранится.
- **Тема применяется до первой отрисовки** скриптом в `index.html`, иначе на
  тёмной теме мигает светлый фон.
- **Каждая анимация спрашивает `useReducedMotion`.**

**Синхронизация** (`web/src/api/sync.ts`) повторяет модель приложения:
отправить своё → забрать чужое → догрузить тексты. В общем sync cursor идут
книги, словарь и SRS reviews. Хранилище — IndexedDB
(`web/src/lib/db.ts`), а не localStorage: тот ограничен ~5 МБ и синхронен, а
книги с других устройств его переполнят. Метаданные и текст лежат в разных
хранилищах — список книг не должен вытаскивать в память сами книги.

Инварианты те же, что в приложении: удаление оставляет надгробие, флаг `dirty`
снимается только после подтверждения сервером, текст качается при открытии
книги, а не при синхронизации. При снятии `dirty` обязательно сравнивается
отправленный `updated_at`, чтобы параллельная локальная правка не потерялась.

React-маршруты `/course` и `/course/lesson/:id` используют тот же
`frontend/assets/course/course_bundle.json`, атласы и звуки, что Flutter.
`web/scripts/prepare-course-assets.mjs` переносит их в production assets.
В React упражнения перемешиваются внутри уровня сложности при каждой попытке,
matching нельзя проверить до заполнения всех пар, а статус `completed` ставится
только при достижении `passThreshold`. Для свободного ввода используется
экранная клавиатура сербских спецсимволов. Пока исходный атлас неровный,
`CourseSprite` намеренно показывает один увеличенный кадр без анимации.

Курс обязан открываться без сети. Во Flutter `CourseContentLoader` сначала
показывает встроенный bundle, а серверную публикацию проверяет в фоне; валидная
публикация применяется при следующем открытии. На React серверный запрос
ограничен коротким таймаутом и параллельно загружается bundled JSON. Не
возвращать последовательность «сначала сеть, затем asset»: при недоступном API
первый урок выглядит как чёрный экран.

Страницы курса являются lazy chunks. `main.tsx` слушает `vite:preloadError` и
один раз обновляет устаревшую вкладку, а `PageErrorBoundary` показывает
восстановление вместо пустого фона. `web/deploy/deploy.sh` сохраняет
хешированные assets предыдущих сборок 14 дней. Не удалять их сразу после
подмены `index.html`: открытая до выкладки вкладка может запросить chunk только
после клика по «Курс».

Маршруты `/listening` и `/listening/:id` получают каталог из Go
`/audio/lessons`. Настоящие расшифровки лежат статикой в
`web/public/transcripts/`, сопоставление аудио с файлом — `index.json`.
`web/scripts/transcribe-podcasts.py` отправляет само аудио в Groq
`whisper-large-v3-turbo` и сохраняет пословные тайминги; MP3 режется по кадрам,
M4A конвертируется через указанный `--ffmpeg`. Никогда не возвращать старый
алгоритм «описание RSS → фразы → время пропорционально длине»: такой текст не
совпадает с речью. Если транскрипта нет, `cues` должны быть пустыми, а аудио
доступным. Длинный транскрипт рендерится лениво через `content-visibility`.

Авторизация веба живёт в `web/src/state/auth.tsx`. `/verify-email` завершает
регистрацию по ссылке из письма, `/auth/yandex` обменивает одноразовый код
callback на сессию. Не записывать токен сессии в query string: URL попадает в
историю, логи прокси и `Referer`.

Временные события веба живут на `/events`; конкретное событие открывается
отдельным lazy route и может требовать аккаунт. «Одиссея» (`/events/odyssey`)
доступна с 1 августа до 1 сентября 2026 года. Её 24 песни собираются скриптом
`web/scripts/prepare-odyssey-event.py` из public-domain перевода Томо Маретича
1915 года, переводятся в сербскую кириллицу и бандлятся отдельным JSON-чанком.
Прогресс хранится локально по `account.id` и объединяется с серверным документом
`event-odyssey-2026` через `/v1/course/progress/{courseId}`. Песни закрываются
только по порядку; все 24 открывают тему читалки `odyssey`. Тема не применяется,
если награда не принадлежит текущему аккаунту. Мобильное меню разделов —
сгруппированная двухколоночная панель, а не длинный вертикальный список.

Импорт библиотеки поддерживает TXT, Markdown, DOCX и PDF. Mammoth и PDF.js
подгружаются динамически. Текстовый слой PDF извлекается в браузере; PDF-скан
отправляется в `/documents/extract`, где Tesseract использует `srp` и
`srp_latn`. Не переносить OCR-модели в основной web-bundle.
При недоступном Space Tesseract.js обрабатывает не более 12 страниц одним
worker; лимит защищает вкладку от роста памяти.

**Worker PDF.js лежит в `public/pdf.worker.js`**, копируется при сборке
(`npm run prepare:worker`). Не возвращать сборку worker'а через Vite: тот даёт
имя с расширением `.mjs`, которого нет в `mime.types` nginx, файл уходит как
`application/octet-stream`, и браузер отказывается исполнять модуль. Хуже того,
имя содержит хеш и не меняется — один раз закешированный неверный ответ с
`immutable` не исправить ничем. Собирать сайт только через `npm run build`, а не
`vite build`: иначе worker в `dist/` не попадёт, и импорт PDF молча отвалится.

### Пререндер сайта (`web/scripts/prerender.mjs`)

Статические разделы отрисовываются headless-браузером на сборке и сохраняются
плоскими файлами: `/course` → `dist/course.html`. Раскладка именно плоская —
`dist/course/` уже занят ассетами курса, и вариант с каталогом ломает страницу
(см. комментарий в `web/deploy/nginx-site.conf`). nginx разводит их правилом
`try_files $uri $uri.html /index.html`.

Один документ для человека и для робота: разделение по User-Agent — клоакинг,
и делать его нельзя. Список адресов берётся из `dist/sitemap.xml`, второго
списка маршрутов заводить не нужно — он разойдётся с первым.

Уроки преподавателей публикуются между выкладками сайта, поэтому их карту
(`/sitemap-lessons.xml`) и разметку `/lessons/{slug}` отдаёт Go: он берёт
`index.html` из `CITAVUK_WEB_ROOT` и подставляет заголовок, описание,
канонический адрес и текст теории. Заготовка перечитывается по времени
изменения файла — иначе после выкладки сайта сервер отдавал бы ссылки на
удалённые бандлы. Несуществующий урок обязан отвечать 404, а не 200 с пустой
страницей: «мягкие 404» подрывают доверие поисковика к разделу.

Заголовок кеширования стоит в `location /`, а не только в блоке `\.html$`:
`try_files` отдаёт `$uri.html` внутренним переходом, не перезаходя в подбор
`location`.

### Картинки и таблицы в книге (`web/src/lib/blocks.ts`, `frontend/lib/models/book_block.dart`)

Книга хранится списком абзацев-строк, и эту модель трогать нельзя: её адрес при
синхронизации считается от абзацев байт в байт тремя реализациями, а протокол
синхронизации знает только `string[]`. Поэтому картинка и таблица остаются
абзацами, но с меткой в начале — `U+0000citavuk:image` и `U+0000citavuk:table`.
Этого символа в тексте книги не бывает никогда.

- **Формат обязан совпадать в обеих реализациях.** Книга с картинкой,
  добавленная в браузере, открывается в приложении и наоборот. Парные наборы
  примеров — `web/src/lib/blocks.test.ts` и
  `frontend/test/models/book_block_test.dart`.
- Ячейки таблицы разделяются табуляцией, ряды — переводом строки, и внутри
  ячейки ни того ни другого быть не может: `cleanCell` заменяет их пробелом.
  Экранирование было бы лишней сложностью — в ячейке книжной таблицы перенос
  строки это вёрстка, а не смысл.
- **Разбор обязан быть устойчивым.** Битая метка показывается обычным текстом,
  а не роняет читалку: абзац приходит из хранилища и с чужого устройства.
- Ячейки таблицы остаются разбираемыми по нажатию, но **контекстом служит текст
  ячейки, а не абзац**: сам абзац там — служебная метка, и разбор по ней выбрал
  бы неверный язык. Номер ячейки нужен подсветке, иначе одинаковое слово
  подсветится сразу во всех ячейках.
- **Flutter `Table` падает на рядах разной длины**, а в книжной таблице они
  бывают неровными (объединённые ячейки исходного документа). Короткие ряды
  добираются пустыми при показе, а не при разборе: данные должны остаться
  такими, какими их записал другой клиент.
- Вес абзаца на странице считается отдельно (`pageWeight` / `_pageWeight`):
  длина метки не говорит ни о чём, адрес картинки бывает длиннее абзаца.
- **Извлекаются только из DOCX и HTML** (`web/src/lib/formats/htmlBlocks.ts`;
  DOCX идёт через `mammoth.convertToHtml`, а не `extractRawText`). У PDF нет
  структуры документа, а `reflowDocumentWithLayout` склеивает строки страниц в
  абзацы и не отдаёт соответствия «страница → абзац», поэтому вставить картинку
  на её место там пока нечем. FB2 и EPUB держат картинки отдельными файлами
  внутри архива.

Картинки уезжают в тот же S3, что и изображения уроков, но **ключ считается от
sha256 содержимого**, а не назначается случайно (`media.BookImagePolicy`). Иначе
одна и та же книга, добавленная на двух устройствах, получила бы разные адреса
картинок, разный адрес содержимого — и стала бы двумя разными книгами. Владелец
остаётся в пути: общий ключ по хешу дал бы дедупликацию, но вместе с ней и
возможность подложить под чужой известный хеш другую картинку.

Отсюда следует, что **картинки требуют аккаунта**: без него адрес взять неоткуда,
а заменить временный после входа нельзя — адрес книги уже посчитан.

### Перевод документа на сербский (`server/internal/api/document_translate_handlers.go`)

Импорт документа не на сербском предлагает выбор: оставить как есть или
перевести. Язык определяет `serbian.CheckDocument` (веб спрашивает сервер,
Flutter решает местным `LanguageDetector` — импорт обязан работать офлайн).

- **Провайдер выбирается по объёму.** У DeepL Free 500 000 знаков в месяц НА ВСЁ
  приложение, а книга на двести страниц — это примерно 400 000. Один перевод
  книги съел бы месячную квоту, и в читалке перестали бы переводиться слова: та
  же квота обслуживает разбор слова в предложении. Поэтому до 20 000 знаков —
  DeepL, дальше — запасной бесплатный провайдер. Выбор делается один раз на
  документ: переводчики по-разному передают имена и термины, и смена посреди
  книги видна невооружённым глазом.
- **Заявка и куски, а не один запрос.** Книга переводится минуты: единственный
  запрос упёрся бы в таймаут прокси, не показал бы хода работ и при обрыве связи
  потерял бы всё вместе с суточным пределом.
- **Предел «одна книга в сутки» проверяется и записывается ОДНИМ оператором**
  (`StartDocumentTranslation`). Раздельные «посчитать» и «вставить» дали бы
  гонку: два устройства прошли бы проверку одновременно. Окно скользящее, а не
  календарный день, — иначе две книги в 23:59 и 00:01 формально не нарушают
  правило. Счётчик знаков увеличивается ДО перевода по той же причине.
- **Предел тратит переведённый текст, а не заведённая заявка.** Против предела
  считаются только заявки с `translated_chars > 0` (`countedAgainstLimit`), а
  отказ переводчика возвращает засчитанный авансом объём
  (`ReleaseTranslatedChars`). Иначе исчерпанная месячная квота DeepL забирала бы
  у человека ещё и сутки: перевода нет, а день потрачен, и узнаёт он об этом,
  только когда пробует снова. Возврат идёт по `context.WithoutCancel` — к моменту
  отказа вкладка вполне может быть уже закрыта. Заявка, оборвавшаяся на середине,
  предел всё-таки тратит: квота провайдера на переведённые куски израсходована.
- **Что переводить, решает клиент**: только он знает, где текст, а где адрес
  картинки или ячейка таблицы. Сервер переводит присланный список строк один в
  один, и **ответ обязан быть той же длины** — сдвиг хотя бы на один элемент
  развалил бы весь остаток книги, и заметно это стало бы не сразу.
- Запасной провайдер склеивает абзацы через перевод строки ради числа запросов,
  но разделитель он сохраняет не всегда. Поэтому результат проверяется по числу
  строк, и при расхождении кусок переводится абзац за абзацем
  (`translateWithFallback`). Без этой проверки сбой был бы незаметен и
  катастрофичен.
- Длинный текст уходит запасному провайдеру телом POST, а не в адресе: кириллица
  кодируется тремя байтами на букву, и тысяча знаков даёт адрес в шесть
  килобайт.

### Повторение письмом (`web/src/lib/writing.ts`, `frontend/lib/utils/writing.dart`)

Карточка показывает перевод, человек пишет сербское слово от руки на холсте,
затем открывает ответ и **сам** говорит, вспомнил или нет.

- **Проверяет человек, а не программа, и это осознанное решение.** Открытое
  распознавание рукописного текста без модели невозможно, а единственная готовая
  (ML Kit Digital Ink) существует только на Android и iOS — ни в браузере, ни на
  Windows с Linux её нет. Сравнение с очертанием шрифта отвергало бы нормальный
  почерк, а ложный отказ в упражнении на память — худшее, что может случиться:
  человек начинает подгонять почерк под программу вместо того, чтобы вспоминать
  слово.
- **Только слова, не фразы** (`writable`). Правила отбора обязаны совпадать в
  обеих реализациях: карточки синхронизируются.
- Расписание общее с обычными карточками — это те же карточки, показанные иначе.
  Заводить им отдельные сроки значило бы показывать одно слово дважды в день.
- На телефоне пишут по одной букве, на десктопе и в браузере — слово целиком
  (`writeLetterByLetter`): узкий холст телефона слово из восьми букв либо не
  вмещает, либо делает буквы такими мелкими, что упражнение теряет смысл.
- Холст рисует не только линию, но и хранит штрихи списком точек: без этого не
  сделать отмену последнего штриха и перерисовку при повороте экрана.
  Во Flutter `shouldRepaint` возвращает `true` всегда — список принадлежит
  контроллеру и меняется на месте, поэтому любое сравнение полей дало бы
  «ничего не изменилось».

### Абзацы в PDF (`web/src/lib/reflow.ts`, `frontend/lib/utils/reflow.dart`)

PDF хранит строки страницы, а не абзацы. Наивный разбор давал крайности: либо
каждая зрительная строка становилась абзацем, либо целая страница склеивалась в
один кирпич. Абзацы восстанавливаются по признакам вёрстки — короткая последняя
строка, конец предложения, маркер списка, заголовок, перенос по слогам; заодно
выбрасываются колонтитулы (строка, повторяющаяся на ≥60% страниц) и номера
страниц.

**Правила обязаны совпадать в обеих реализациях**: адрес книги при
синхронизации считается от списка абзацев, и разное разбиение означает две
разные книги вместо одной. Парные наборы примеров —
`web/src/lib/reflow.test.ts` и `frontend/test/services/reflow_test.dart`.

Во Flutter текст берётся через `extractTextLines`, а строка собирается из
`wordCollection`: `extractText(layoutText: true)` иногда не ставит пробел между
соседними словами («предвиђено је120 минута»), потому что в PDF пробела и нет —
слова просто нарисованы рядом. По разбору на слова видно, что они разные.

### Читалка веба (`web/src/pages/Reader.tsx`)

Оформление задаётся `web/src/lib/readerSettings.ts` и повторяет
`ReaderSettings` приложения по именам полей: кегль, интерлиньяж, разрядка,
шрифт, отступ абзаца, красная строка, выключка, ширина колонки, цвет страницы,
уровень выделения основы слова и режим `flow = pages | scroll`.

Непрерывный web-режим строится через `react-virtuoso` с `useWindowScroll`:
логические страницы остаются единицами прогресса и обсуждений, но в DOM
находится только видимое окно. Не заменять его на `pages.map(...)` — книга на
тысячи страниц снова повесит вкладку. Длинные токены обязаны переноситься через
`overflow-wrap`, а контейнер страницы — иметь `min-width: 0` и не создавать
горизонтальную прокрутку на мобильном.

Карточка слова и панель перевода выделенной фразы из `WordReader` рендерятся
через React Portal непосредственно в `document.body`. Не возвращать их внутрь
`motion.article`: CSS `transform` страницы меняет containing block для
`position: fixed`, и координаты `getBoundingClientRect()` тогда дополнительно
смещаются относительно листа вместо viewport.

- **Хранятся в localStorage, не в IndexedDB и не на сервере.** Настройки нужны
  синхронно при первой отрисовке, иначе книга мигнёт чужим шрифтом. Между
  устройствами они намеренно не переносятся: комфортный кегль на телефоне и на
  мониторе разный.
- **Разбор прочитанного обязан быть устойчив** (`sanitize`): в хранилище может
  оказаться что угодно, а читалка обязана открыться.
- **Отступ абзаца — переменная `--reader-gap`, а не `marginBottom` в строчном
  стиле.** Строчный перебивает любое правило и оставляет лишний отступ под
  последним абзацем.
- **Звук перелистывания синтезируется** (`web/src/lib/pageTurn.ts`), файла нет:
  шелест — это отфильтрованный шум, и кодом он короче, чем килобайтами. Контекст
  создаётся при первом воспроизведении: до действия пользователя браузер держит
  `AudioContext` в `suspended`.

### Папки библиотеки (`web/src/lib/folders.ts`)

Папка — это поле `folder` у книги, а не отдельная сущность. Поле с первого
выпуска ходит в протоколе синхронизации (`books.folder` в `0001_init.sql`),
поэтому раскладка едет между устройствами без новой таблицы и версии протокола.
Плата: пустую папку хранить не в чем, она живёт в localStorage этого браузера
до первой книги — и раздел говорит об этом прямо.

### Словарь и карточки (`web/src/pages/Cards.tsx`, `web/src/lib/srs.ts`)

Раздел `/cards` отвечает на вопрос «куда девается сохранённое слово». Расчёт
срока — копия `UserDb.gradeCard` из приложения, и **совпадать он обязан**:
карточки синхронизируются, и слово, оценённое на телефоне и в браузере, должно
получить один и тот же следующий срок.

### Дворец памяти (`web/src/pages/Palace.tsx`, `web/src/palace/scenes.tsx`, `frontend/lib/screens/palace_screen.dart`)

Сцена — не картинка с невидимыми зонами поверх, а список предметов: предмет сам
себя рисует и сам является местом для слова. Иначе пришлось бы согласовывать
рисунок и координаты зон и однажды сдвинуть одно, забыв про другое.

**Комнаты для Flutter выгружаются, а не рисуются заново.** Источник один —
React-сцены; `web/scripts/export-palace.tsx` рендерит из них
`frontend/assets/palace/<id>.svg` и `frontend/lib/palace/scenes.dart`. Перерисовка
вручную означала бы две картинки, которые разъедутся при первой же правке, и
слово повисло бы в воздухе рядом со своим предметом. Правка комнаты в React
требует повторного запуска скрипта.

**Порядок обхода — тот, в котором слова расставляли** (`walkOrder`, поле `at` у
пина). Маршрут обязан быть постоянным: в этом весь приём, вспоминается не слово,
а место и путь к нему, и перемешивать его нельзя, хотя для обычного повторения
перемешивание было бы нормой. Постоянным был и прежний порядок — порядок
предметов в сцене, — но он был чужим: человек расставляет слова осознанно,
сначала то, с чего начнёт. Развеска без `at` (сделанная до появления поля)
обходится по-старому и идёт первой — этот маршрут человек уже выучил, и менять
его задним числом нельзя. Замена слова на том же предмете `at` не сдвигает: это
правка ошибки, а не перестройка маршрута.

`at` обязан переживать синхронизацию (`PalacePin.At` на сервере), иначе телефон
и браузер обходили бы один дворец в разном порядке. Порядок реализован трижды —
`web/src/lib/palace.ts`, `frontend/lib/services/palace_store.dart` и тесты к обоим
написаны на одних и тех же примерах.

Дворцы синхронизируются наравне с книгами и словарём (`palaces` в `Changes`,
таблица из `0006_palaces.sql`). Решения, которые стоит знать:

- **Развеска хранится одним `jsonb`, а не таблицей «предмет — слово».**
  Отдельная таблица позволила бы слить два устройства по отдельным предметам, но
  это не то, чего человек хочет: дворец — цельная картина, и «половина
  расстановки с телефона, половина с компьютера» бессмысленна. Слияние идёт по
  времени изменения дворца целиком, как у книг.
- **`scene_id` сервер не проверяет.** Набор комнат меняется выпусками клиента, и
  сервер, знающий этот список, пришлось бы выкатывать раньше каждого такого
  выпуска.
- **Длинные значения укорачиваются, а не отвергаются** (`clip`). Ошибка в
  upsert прерывает всю посылку: одно слишком длинное поле навсегда сломало бы
  синхронизацию устройства, и починить это пользователь бы не смог. Обрезка идёт
  по границе символа — срез ровно по байту разрубил бы кириллицу.
- **Индекс `dirty` добавлен в версии 4 схемы IndexedDB.** Дворцы, построенные до
  синхронизации, полей `dirty`/`deleted` не имеют, а запись без ключа индекса в
  индекс не попадает — такой дворец никогда бы не уехал на сервер. Транзакция
  смены версии проходит по ним курсором и помечает к отправке.

### Страницы читалки (`web/src/lib/pages.ts`, `frontend/lib/utils/pages.dart`)

Разбиение реализовано дважды и обязано совпадать знак в знак: одна и та же
книга должна листаться одинаково на телефоне и в браузере, иначе «я остановился
на двенадцатой странице» значит на разных устройствах разное.

- **Длинный абзац режется по границам предложений.** Прежнее правило «страница
  всегда кончается на границе абзаца» ломалось на книгах из публичной
  библиотеки, где глава нередко идёт одним куском: недобранная страница
  выталкивалась досрочно, а следом шла страница на десятки тысяч знаков, на
  которой телефон тормозил. Опасение, ради которого правило существовало
  («предложение окажется на двух страницах и перевод слова потеряет контекст»),
  соблюдается: разрыв проходит между предложениями.
- **Куски выравниваются по длине через двоичный поиск предела.** Набивка под
  завязку оставляет огрызок — абзац на 15 800 знаков давал одиннадцать страниц
  по 1422 и двенадцатую на 157. Поделить длину поровну тоже не выходит: куски
  набираются целыми предложениями и в цель не попадают. Поэтому число кусков
  определяется набивкой под завязку, а затем ищется наименьший предел, при
  котором кусков столько же, — при нём самый большой кусок минимален.
- **Прогресс по-прежнему хранится в абзацах.** Страница помнит, с какого абзаца
  началась; при разрыве длинного абзаца несколько страниц подряд ссылаются на
  один и тот же абзац, и это верно — прогресс указывает именно в него.

### Экран, который не гаснет (`frontend/lib/widgets/keep_awake.dart`)

Чтение и прослушивание — те редкие занятия, при которых экрана не касаются
минутами. Удержание сделано обёрткой, а не вызовом в каждом экране, по одной
причине: оно обязано сниматься, а экран закрывается не только кнопкой «назад»,
но и исключением при построении. Забытый снаружи вызов оставил бы телефон
гореть до перезапуска приложения.

Выключатель (`AppSettings.keepScreenOn`) лежит в панели настроек чтения, но
живёт в общих настройках: он действует и в плеере, а тот про настройки чтения
не знает. Батарея — расходуемый ресурс, и решение о ней остаётся за человеком.

### Меню «ещё» во Flutter (`frontend/lib/widgets/more_menu_sheet.dart`)

Пунктов набралось четырнадцать, и плоским списком они читались плохо:
одинаковые строки одинаковой длины, глазу не за что зацепиться. Длинный список
вдобавок сам по себе выглядит как «здесь сложно» — впечатление, которого
приложению для начинающих следует избегать. Разделы сокращают область поиска:
человек сначала выбирает «читать» или «учиться» — это он знает про себя
заранее, — и дальше видит три-четыре пункта вместо четырнадцати.

Действие вызывается ПОСЛЕ закрытия шторки: почти каждый пункт открывает новый
экран, и открывать его поверх закрывающейся шторки — значит показать, как она
уезжает вниз из-под уже открытого экрана.

### Вукоток: карточка (`web/src/pages/MicroFeed.tsx`, `server/internal/feed/`)

- **Внутри карточки не скроллится ничего.** Текст в 100–150 слов на телефон не
  помещается, и раньше он лежал во вложенном скроллере внутри `snap-y
  snap-mandatory`. На компьютере положение спасал обработчик колеса, а у
  касания такого обработчика нет: палец попадал во вложенный скроллер, и свайп
  к следующей карточке срабатывал через раз. Теперь на экране крючок (`hookOf`,
  режет по границе предложения), а полный текст открывается шторкой поверх
  ленты. Пока шторка открыта, лента не листается вовсе.
- **Картинку забирает сервер, а не браузер.** Прямая ссылка в вёрстке
  рассказала бы чужому сайту, кто из наших читателей открыл карточку: туда ушли
  бы IP, Referer и cookie для того домена. Ручка принимает не адрес, а
  идентификатор карточки (`/v1/micro-feed/{id}/image`) и берёт адрес из своей же
  базы: ручка, принимающая адрес от браузера, была бы открытым прокси.
- **Адрес картинки из источника проверяется дважды** — при разборе и перед
  запросом (`feed.AllowedImageURL`, отдельный от `sourceHosts` список хостов).
  Он приходит из чужого XML, то есть это данные, которым нельзя верить.
- **Адрес хранится и у заготовки** (`micro_feed_imports.image_url`): карточку
  делает языковая модель, а она картинку не видит и передать не может.
- **На широком экране карточка — телефон посреди страницы** (`lg:[aspect-ratio:9/16]`
  плюс размытая та же картинка подложкой). Растянутая на весь монитор лента ничем
  не напоминала то, ради чего сделана: строка уезжала на полметра вправо, а
  картинка превращалась в фон рабочего стола.
- **На телефоне шапки сайта над лентой нет** (`hidden lg:block` вокруг `Header`
  в `App.tsx`, `h-dvh` у ленты): полоса навигации сверху оставляла раздел
  «страницей сайта с видео». Выход из ленты — значок волка в её собственной шапке.
- **Иллюстрация есть примерно у каждой четвёртой карточки**: в новостных RSS
  картинок нет вовсе, они приходят только из Википедии. У остальных верх
  занимает `PlainCover` — буква названия крупной плашкой. Чёрная половина экрана
  читалась как незагрузившаяся картинка, а не как задумка.
- **Сложные слова — кнопки, а не подписи.** Раньше это был `<span>` с подсказкой
  в `title`: на телефоне такая подсказка не показывается вовсе, и разобранные
  для читателя слова нельзя было ни прочитать целиком, ни забрать в словарь.
  Нажатие кладёт слово в словарь вместе с транскрипцией.
- **Озвучка режется на куски** (`lib/speech.ts`). `/audio/tts` отвечает 400 на
  текст длиннее 400 символов, а в карточке их 700–1100 — кнопка не работала
  вовсе: запрос уходил, приходила пустая ошибка, значок молча возвращался назад.
  Режется по границе предложения: пауза на стыке слышна всегда, и на точке она
  звучит как пауза между фразами, а посреди фразы — как заедание. Следующий
  кусок грузится, пока звучит текущий. Карточка, ушедшая с экрана, замолкает.

### Задания уроков (`web/src/components/LessonExerciseEditor.tsx`)

- **Правильный вариант держится за номером, а не за текстом.** Сравнение по
  тексту (`correct === option`) ломалось дважды: новое задание начинается с двух
  ПУСТЫХ вариантов, а пустые тексты неразличимы — отметка на них была запрещена
  явной проверкой, и до набора текста нажатие на точку не делало ничего вообще;
  два одинаковых варианта зажигали обе точки. Наружу по-прежнему отдаётся текст,
  формат задания не менялся.
- **Имя группы радиокнопок берётся из `useId()`, а не из подписи списка.** В
  задании «текст и вопросы» подпись у всех списков одна — «Ответы», поэтому все
  вопросы урока оказывались одной группой: отметка во втором вопросе снимала
  отметку в первом.
- **Наборы заданий** (`lib/exerciseBulk.ts`): десять слов на один приём — обычная
  работа, и десять заходов «добавить → выбрать тип → заполнить» ради одной
  меняющейся строки не нужны. Плохая строка не отменяет остальные: из десяти
  строк с опечаткой получаются девять заданий и одно замечание с номером строки.

### Всплывающие слои веба (`web/src/lib/overlay.ts`)

- **Замок прокрутки — счётчик, а не флаг** (`useScrollLock`). Каждый слой
  запоминал прежнее значение `body.style.overflow` сам, и два слоя внахлёст
  ломали друг друга: закрывался верхний и отпускал прокрутку под всё ещё
  открытым нижним, а обратный порядок оставлял страницу заблокированной до
  перезагрузки.
- **Фокус удерживается внутри слоя** (`useFocusTrap`) и возвращается на
  открывшую кнопку. Без этого Tab уводил из шторки в ссылки ПОД ней: человек с
  клавиатуры оказывался в контенте, которого не видит. Шторки помечены
  `role="dialog"` + `aria-modal` — иначе скринридер продолжает читать страницу
  под слоем.
- **Панель «Ещё» открывается кликом, а не наведением.** У `onMouseEnter` нет
  клавиатурного соответствия, и до трёх колонок ссылок нельзя было добраться
  табом вовсе. Вдобавок `onMouseLeave` закрывал панель, когда курсор шёл к
  дальней колонке по диагонали и на миг выходил за границу.

- **Слои разбора выше всех шторок**: панель «перевести выделенное» — `z-[85]`,
  карточка слова — `z-[90]`. Разбор вызывается ИЗ шторки (Вукоток, урок), и на
  прежнем `z-40` панель уходила под ту самую шторку, в которой её и вызвали.
  Новым слоям приложения выше `z-[80]` подниматься нельзя.
- **Подложка шторки закрывается только своим нажатием.** Выделение фразы,
  доведённое пальцем до края шторки, отпускалось уже на подложке — `click`
  всплывал до общего предка, и шторка захлопывалась вместо показа перевода.
  Признак пишется в `onPointerDown` (`event.target === event.currentTarget`).

### Карточка слова — одна на весь сайт (`WordReader.tsx`)

Разбор и перевод грузит `useWordLookup`, показывает `WordCard`. Вне читалки для
этого есть `WordLookupCard`: он нужен там, где текст выводится своей вёрсткой —
в караоке подкаста строка подсвечивается по ходу звука, и заменить её на
`WordReader` целиком нельзя.

Своей карточки заводить нельзя. У подкаста такая была: без разбора формы, без
таблиц склонения, без произношения и без выбора, что сохранить в словарь. Одно и
то же действие давало разный результат в зависимости от раздела, и это выглядит
поломкой, а не задумкой.

Заголовки Вукотока (карточка и шторка) — тоже `WordReader` внутри
`div role="heading"`, а не `h2`: внутри `WordReader` абзацы, а абзац внутри
заголовка — невалидная разметка.

### Возвратный глагол и частица «se» (`internal/grammar/reflexive.go`)

`se` — клитика: своего ударения у неё нет, и место ей отводит не глагол, а
фраза — второе, сразу за первым ударным словом. Поэтому «On se zove Marko»
выглядит так, будто частица при «on», а на деле это глагол «zvati se».

- `AttachSe` ищет частицу **в пределах своей части предложения**: в «Vratio se
  kući, a brat je ostao» приписать её `ostao` нельзя. Границы — знаки препинания
  и союзы из `clauseOpeners`; союз входит в свою часть слева, иначе объяснение
  «клитика вторая после `da`» теряет первое слово.
- Ответ `/v1/analyze` несёт `reflexive` только для `VERB`/`AUX`. Рядом с
  существительным («kuća se prodaje») частица к нему не относится.
- `SeSpan` расширяет границы слова для переводчика: «zove» отдельно — «зовёт», а
  «zove se» — «называется». Только вплотную стоящую частицу: помеченный фрагмент
  обязан быть сплошным, иначе выравнивание внутри фразы теряет смысл. Делает это
  `withSeParticle` в обработчике `/v1/translate/context` — значит, приложение
  получает то же самое без своей правки.
- Клиент ищет частицу в тексте **сам** (`particleStart`) по признакам
  `before`/`adjacent`. Пересылать байтовые смещения Go в индексы JavaScript
  значит пересчитывать UTF-8 в UTF-16 в обе стороны и ошибиться на кириллице.
- Имя собственное со строчной буквы не бывает: `bestReading` понижает `PROPN`
  для строчного написания. Без этого «se» разбиралось как имя (в словаре есть и
  такая строка), и самая частая частица языка описывалась карточкой «имя
  собственное, именительный падеж».

### Словари из Викисловаря (`tools/build_wiktionary.py`)

Один скрипт кладёт в `frontend/assets/lexicon.db` две таблицы, а
`lexicon_export.py` отправляет их серверу (`accents.tsv.gz`, `verbs.tsv.gz`).

- **`accents`** — ударное написание в обоих алфавитах и транскрипция с тоном.
  Оба алфавита нужны рядом: книга бывает и латинской, и кириллической, а в
  Вукотоке письмо переключается на ходу.
- **`verb_forms`** — словоформа глагола → начальная форма. Свой лексикон
  разрежен, целых глаголов вроде «bližiti» в нём нет вовсе, и без этого списка
  частица «se» не находила своего глагола в первом же предложении книги.

Грабли, на которые уже наступили:

- **`ć` в разложенном виде — это `c` плюс акут**, тот же знак, что и долгое
  восходящее ударение. Снимать знаки без проверки нельзя: «kuća» превращалась в
  «kuca» (другое слово), и весь словарь съезжал на соседние статьи. Знак
  считается ударением только на гласной или слоговом «r».
- **Причастие на -o/-la/-lo/-li/-le** Викисловарь даёт только в мужском роде и
  только внутри составных времён («bȕdēm bližio»). Остальные достраиваются от
  начальной формы правилом — без этого самой частой формы прошедшего времени в
  словаре не было вовсе.
- Лицензия CC BY-SA 4.0 обязывает называть источник: он лежит в `accents_meta`,
  в `lexicon.AccentSource` и показывается в карточке разбора.
- При смене содержимого `lexicon.db` **обязательно растёт `_version`** в
  `lexicon_db.dart`: иначе на уже установленных приложениях останется старая
  копия в кэше и новых таблиц там просто не будет.

### Ударение в транскрипции (`serbianPronunciation.ts`, `.dart`)

Ударение показывается **жирным прямо в транскрипции** (`serbianIpaParts` →
`before` / `stressed` / `after`). Подписью словами его объяснять нельзя: сначала
там стояло «без ударения» (читалось как «ударения в слове нет» — в сербском оно
есть всегда), потом «ударение не на последнем слоге» — это рассуждение о
произношении, а не произношение.

Место ударения по написанию не восстанавливается: ударений четыре (краткое и
долгое, восходящее и нисходящее), словаря ударений в проекте нет. Но в одно- и
двусложном слове место определяется однозначно и без словаря — ударение никогда
не падает на последний слог, твёрдая норма литературного сербского. Там оно и
отмечается; в словах длиннее транскрипция остаётся без выделения, потому что
пустое место честнее уверенной ошибки.

Вершина слога — гласный либо слоговое `r` между согласными («prst», «krv»); без
второго правила такие слова выходят вовсе без слогов.

### Вукоток: анкета и сохранённое

- **Анкета встаёт ДО ленты, а не поверх неё.** Подбор строится по поведению, а
  поведения при первом заходе нет: новому читателю лента показывала
  «популярное вперемешку с лёгким» и ждала сигналов. На чужом языке это дорогая
  цена — карточку читают минуту, и первые десять неподходящих отбивают желание
  вернуться. Ответы едут вместе с лентой (`preferences` в `/v1/micro-feed`),
  иначе решение «показывать ли опрос» принимается с опозданием.
- **Названное и накопленное живут в разных колонках.** `refreshMicroFeedProfile`
  ПЕРЕСОБИРАЕТ `preferred_tags` заново, и ответы анкеты в той же колонке стёрло
  бы первое же действие читателя. Отсюда `declared_categories` и `onboarded_at`.
- **Отказ — тоже ответ.** «Показывайте всё подряд» пишется как пройденная
  анкета с пустым списком: иначе опрос встречал бы человека при каждом заходе.
- **Названные темы работают, ПОКА нет поведения** (`strategy: declared`). У
  «тёплого» читателя подбор знает о нём больше, чем он сказал о себе в первую
  минуту, и анкета уходит в подстраховку.
- **Лайк — ещё и закладка** (`/v1/micro-feed/liked`). Раньше он был только
  сигналом подбора: нажал — карточка уехала вверх, и найти её было негде. На
  чужом языке лайк чаще всего значит «вернусь и разберу».
- **Список тем один на весь сервер**: `store.MicroFeedCategories`, CHECK на
  колонке, `ValidateItem` и приглашение модели. Разъезд тише всего: карточка
  проходит проверку, а база её не принимает — или тема есть, но модель о ней не
  знает и её карточки отбраковываются по одной.

### Читавук в вебе гладится (`Mascot.tsx`)

Нажатие на маскота меняет позу и показывает ответ — как `wolf_mascot.dart` в
приложении с самого начала. Это единственное место, где продукт про грамматику
позволяет себе просто порадовать, и терять его на вебе незачем. Слухао — орёл, и
поглаживание к нему не относится: позу «zdravo» он бы всё равно не показал.

### Высота шапки — переменная, а не число (`--header-height`)

Шапка ужимается при прокрутке (64 → 56) и может нести полосу поддержки, которая
на телефоне занимает две-три строки. Полоса прогресса книги была прибита к
`top-16` и почти никогда с шапкой не совпадала: висела в воздухе или оказывалась
посреди неё. Со стороны это читалось как отрыв красной черты и подтормаживание
шапки — она свою высоту анимирует, а прибитая полоса за ней не поспевала.
`Header` ставит настоящую высоту в `--header-height` через ResizeObserver; всё,
что обязано стоять вплотную под шапкой, держится за неё.

### Теория урока — лист, а не полотно

Теория лежит на той же поверхности, что книга в читалке (`paper-grain` +
`--bg-raised`), а длина строки ограничена **в знаках** (`max-w-[62ch]`), а не в
пикселях: кегль задаёт автор урока, и ограничение в пикселях при крупном шрифте
снова давало бы длинную строку. Раньше теория шла сплошным текстом прямо по фону
страницы в контейнере `max-w-5xl` — на широком мониторе строка тянулась почти на
тысячу пикселей. Предпросмотр в `LessonMarkdownEditor` использует ТУ ЖЕ ширину:
предпросмотр, выглядящий иначе, хуже, чем никакого.

### Поисковая выдача: пререндер, карта сайта, IndexNow

- **Список разделов в `scripts/build-sitemap.py` — источник правды и для карты
  сайта, И ДЛЯ ПРЕРЕНДЕРА.** Раздел, забытый там, своего HTML не получает, и
  nginx отдаёт на его адресе `index.html` — побайтовую копию главной с её
  заголовком. Для робота без JS это дубль. Так было с `/lessons`, `/about`,
  `/privacy` и `/vukotok`: четыре копии одной страницы.
- **Переименованный адрес отдаёт 301, а не второй рабочий адрес.** `/micro-feed`
  → `/vukotok` в `deploy/nginx-site.conf`. Два адреса с одинаковым содержимым
  делят вес страницы, а `canonical` здесь не спасает: прежний адрес не
  пререндерится и без JS отдаёт копию главной. Редирект решает вопрос до всякого
  JS и сохраняет чужие ссылки.
- **`useSeo({ canonical })`** нужен там, где у страницы всё же два адреса.
- **Показы автоматических браузеров в ленту не идут** (`navigator.webdriver` в
  `api/microFeed.ts`). Пререндер прогоняет Вукоток на каждой сборке, и без этой
  проверки каждая выкатка подмешивала бы в рекомендации «дочитывания» робота.
- **IndexNow** (`scripts/indexnow.mjs`, шаг в `deploy/deploy.sh`) зовёт роботов
  сразу после выкатки, вместо ожидания от суток до недель. **Google протокол не
  поддерживает** — он тестировал его с 2021 года и не внедрил; участники —
  Яндекс, Bing, Naver, Seznam. Ключ лежит файлом в `public/` и секретом не
  является: он публичный по устройству протокола, чужой сайт им не подтвердить.
  Оповещение идёт ПОСЛЕ проверок выкатки — звать робота на страницу, которая
  может не открыться, значит получить в индексе ошибку вместо страницы.

### Вукоток: обсуждение (`micro_feed_comments`)

- **Читают все, пишут только вошедшие.** У всей остальной ленты действующее
  лицо — `actor_key`, годный и для гостя по ключу из localStorage. Здесь так
  нельзя: анонимная запись, видимая всем, — приглашение для спама, а модератор
  в проекте один и он же автор.
- **Счётчик лежит на карточке** (`comments_count`), а не считается на лету:
  сортировка «популярного» идёт по всем опубликованным карточкам, и подзапрос на
  каждую строку превратил бы выдачу ленты в перебор таблицы комментариев.
- **Удаление мягкое** (`deleted_at`): жёсткое лишало бы возможности разобраться
  в жалобе задним числом. Свою реплику удаляет автор, любую — администратор.
- **Пауза между своими репликами — 10 секунд.** Это не ограничение частоты, а
  защита от двойного нажатия и спама в одну строку; настоящий заслон — вход.
- `normalizeComment` схлопывает пустые строки подряд: реплика из тридцати
  переводов строки — самый дешёвый способ занять весь экран обсуждения, и
  запрещать это отдельным правилом незачем, достаточно не хранить того, чего
  человек не писал.

### Вукоток: кто такой «читатель» (`visitor_token.go`)

- **Идентификатор гостя выдаёт СЕРВЕР и подписывает HMAC.** Пока его придумывал
  браузер, любой UUID принимался за нового читателя: лайк накручивался сменой
  строки в запросе, а профиль подбора засорялся чужими действиями. Токен
  приходит вместе с лентой (`visitorToken` в ответе `/v1/micro-feed`), клиент
  только хранит его в localStorage. Ключ выводится из `DatabaseURL` —
  отдельной переменной окружения нет намеренно: ещё один обязательный секрет
  это ещё один способ развернуть сервер неправильно.
- **Подписи мало, поэтому публичные счётчики растут только от вошедших.**
  Токен выдаётся любому, кто попросит, — набрать пачку по-прежнему можно, и
  «популярное» подпись не защищает. Реакция гостя сохраняется и формирует ЕГО
  подбор (лайк ставит меньшинство, требовать вход ради рекомендаций значило бы
  оставить большинство без них), но в `likes_count`/`dislikes_count` не идёт.
  Аккаунт стоит подтверждённой почты — это единственная граница, которая здесь
  держит.
- Миграция `0019_micro_feed_counts_from_accounts.sql` пересчитывает счётчики по
  строкам с `user_id`. Реакции гостей она НЕ удаляет: это обнулило бы
  рекомендации всем, кто читает без входа.

### Вукоток: подбор (`ListMicroFeed`, `refreshMicroFeedProfile`)

- **Веса сигналов: комментарий 6, лайк 6, «читать дальше» 2, дочитывание 1.**
  Разрыв шестикратный намеренно: дочитывание делает подбор возможным для тех,
  кто не нажимает ничего, но приравнивать молчаливое «прочитал» к сказанному
  «нравится» неверно — шесть дочитанных карточек весят один лайк. Комментарий
  стоит написанной фразы на чужом языке, то есть дороже лайка, и меньше него
  весить не может.
- **Дизлайк закрывает тему сразу** (вес 3 при пороге 3), пролистывание — с
  третьего раза (вес 1): пролистать можно и по случайности, а дизлайк — это
  сказанное вслух «не показывать похожее», и просить повторить его трижды
  значит не слушать с первого раза. Тема при этом отодвигается, а не
  вычёркивается — см. ниже.
- **Обсуждаемое поднимается в «популярном»**: `comments_count*10` внутри
  логарифма против `likes_count*3`. Карточка, вокруг которой спорят, интереснее
  той, которую молча лайкнули. Дизлайки вычитаются снаружи логарифма — внутри
  него они почти ничего не значили бы.
- **Профиль строится по поведению, а не по лайкам.** Лайк ставит меньшинство:
  большинство листает, дочитывает то, что зацепило, и не нажимает ничего. Пока
  «тёплым» читатель становился после трёх лайков, а профиль собирался только из
  них, такой читатель оставался холодным навсегда — подбор для него не
  включался никогда, сколько бы он ни читал. Дочитывания и пролистывания
  записывались с самого начала и не использовались.
- **Веса по цене действия**: лайк 3, «читать дальше» 2, дочитывание 1. Вес
  выражен повторами строки — pgvector умеет усреднять векторы, но не взвешивать.
  `view` и `impression` в профиль не входят намеренно: карточка попала на экран
  не потому, что читатель её выбрал, и считать это одобрением значит
  подстраивать ленту под собственную выдачу.
- **Профиль пересобирается заново**, а не дополняется: не уползает после снятого
  лайка, и одна случайная карточка в начале не определяет ленту навсегда.
- **Отталкивающие темы отодвигаются, но не вычёркиваются** (`avoided_tags`, порог
  — три пролистывания, дизлайк считается за два). Вычеркнуть значило бы запереть
  человека в том, что он читал в первый вечер: интерес меняется, а узнать об
  этом иначе, чем изредка показав тему снова, нельзя. В режиме `explore` порядок
  не трогается — он и существует ради непохожего.
- **Соседние карточки одной темы растаскиваются** (`spreadCategories`). Порция
  собирается из нескольких выборок, каждая со своей сортировкой, поэтому пять
  новостей подряд — обычный исход. Порядок внутри темы сохраняется: подбор
  решает, ЧТО показать, перестановка — только когда.
- В SQL перестройки профиля ветки `UNION ALL` с `ORDER BY … LIMIT` обязаны быть
  в скобках: без них ограничение относится ко всему объединению.

### Вукоток: наполнение (`server/cmd/feedfill`)

Наполнитель — намеренно отдельная команда оператора: запуск сервера никогда не
начинает платную генерацию сам.

- **Карточка получает embedding при создании.** Наполнитель сохранял `nil`, и
  из 477 опубликованных карточек профиль был у двух: рекомендатель подбирал
  похожее вслепую, а раздел выглядел работающим. Неудача расчёта карточку не
  отменяет — доступность ленты важнее качества подбора, — а `-backfill-embeddings`
  досчитывает пропущенное.
- **Профиль читателя становится «тёплым» после трёх лайков** (`microFeedProfile`).
  До этого лента идёт «холодной»: популярное, простое и случайное.

### Диалоги преподавателей (`web/src/components/LessonDialogueEditor.tsx`)

Диалог — граф, а редактируется он списком: список помещается на телефон, а граф
нет. Невыносимым редактор делали три вещи, и все три исправлены.

- **Ответы ссылались на «Реплику N», где N — место в списке.** Удаление одной
  реплики съезжало все номера. Теперь реплики называются по говорящему и началу
  фразы (`nodeLabel`), а удаление снимает ссылки на удалённую реплику сразу —
  иначе диалог оборвался бы посреди разговора, и узнал бы об этом ученик.
- **Проверить написанное было нечем.** Диалог проигрывается прямо в редакторе
  тем же компонентом `Dialogue`, что и у ученика: предпросмотр, выглядящий
  иначе, хуже, чем никакого.
- **Тупики и недостижимые реплики не были видны.** `checkDialogue` перечисляет
  их; ошибки идут раньше предупреждений. Цикл ошибкой не считается — «вернуться
  к началу» обычный ход сценария, поэтому обход помечает посещённые, а не
  запрещает повторы.

На страницу `/dialogues` попадают диалоги **только публичных** уроков
(`ListPublicDialogues`): урок «по ссылке» автор публичным не делал, и выносить
его в общий список значило бы решить за него.

### Материалы для поступления (`web/scripts/build-materials.py`)

Каталог тестов, решений и пособий сербских учреждений: ЗВКОВ (приём в гимназии)
и факультеты всех четырёх государственных университетов — Белградского,
Нови-Садского, Нишского, Крагуевацкого. Два уровня разделены полем `level`.

- **Файлы не хранятся.** Каталог — указатель: описание и ссылка на источник.
  Скачивание идёт по явному нажатию через `GET /v1/documents/fetch`.
- **Каждая ссылка проверяется при сборке** (код ответа, сигнатура `%PDF-`,
  размер). Битая ссылка на учебник хуже отсутствующей: она тратит время ровно
  тогда, когда человек готовится к экзамену.
- **Один генератор — два потребителя.** Скрипт пишет и `web/src/materials/`,
  и `frontend/assets/materials/`. Две копии, собранные по-разному, однажды
  покажут людям разное.
- Превью в вебе (`components/PdfStrip.tsx`) рисует первые 5 страниц **само,
  без нажатий**, но только когда карточка доехала до экрана и не более двух
  документов одновременно: иначе заход в раздел утянул бы сотни мегабайт чужого
  трафика и подвесил вкладку.
- **Адрес нормализуется при сборке** (`normalize_url`). Часть сайтов даёт ссылки
  с пробелами прямо в пути; браузер это чинит, а `http.client` отвергает запрос
  целиком, и на одной такой ссылке останавливалась вся сборка.
- **Предмет, заданный в описании источника, должен быть проверен по содержимому
  файла**, а не угадан по названию факультета. Сборник Технологического
  факультета Нови-Сада помечен химией потому, что открывается строкой
  «NASTAVNI PROGRAM HEMIJA».
- Источник, который по прямому адресу отдаёт HTML вместо PDF, в список не
  добавляется: проверка всё равно отбросит его файлы, а запросы на каждой
  сборке останутся. Такой случай — ИМИ ПМФ Крагуеваца, в `SOURCES` про него
  оставлен комментарий.

### Публичная библиотека (`tools/build_public_library.py`)

`/public-library` и `PublicLibraryScreen` используют один каталог
`web/public/public-library/catalog.json`. В нём только метаданные и адреса:
тексты лежат отдельными TXT и загружаются **только после выбора одной книги**.
Не объединять каталог и тексты в один JSON — это снова заставит браузер держать
в памяти всю библиотеку при открытии списка.

Сейчас в каталог входят произведения из общественного достояния, полученные с
сербского Викизворника. Обложки не генерируются: скрипт скачивает реальные
титульные страницы, портреты и фотографии через Wikimedia Commons API,
сохраняет `coverSourceUrl`, автора и лицензию и только механически обрезает
изображение в WebP. Перед добавлением нового материала обязательно проверить
срок авторских прав или свободную лицензию; файлы из
`frontend/assets/library/` в релиз не входят, потому что там есть защищённые
книги.

Внешние подборки имеют `externalUrl` и пустой `textUrl`: карточка открывает
первоисточник и не притворяется книгой Читавука. Так подключена подборка
учебников, которой поделилась darina. Не копировать содержимое внешнего Google
Drive без отдельной проверки прав.

Flutter получает каталог с `https://citavuk.ru/public-library/catalog.json`,
поэтому при выпуске приложений сайт выкладывается раньше файлов приложений.
Открытая книга сохраняется в обычную пользовательскую БД с `sourceKey` /
`filepath` вида `public:<id>` и дальше читается и синхронизируется как импорт.

### Общие ссылки и обсуждение страниц

Серверные таблицы и API находятся в `0009_shared_books.sql`,
`shared_books.go` и `share_handlers.go`. Одна книга владельца получает один
стабильный токен: повторное нажатие «Поделиться» не должно дробить обсуждение.

Веб-компонент `ShareBook` и Flutter-шторка создают ссылку, но волк появляется
рядом с читалкой только после явного нажатия на кнопку с иконкой цепочки.
Instagram не имеет общего web-intent: клиент копирует ссылку и только затем
открывает Instagram. Остальные сети используют штатные share URL.

Обсуждение находится не на посадочной `/shared/:token`, а на **каждой странице
обычной читалки**. Ключ ветки — индекс первого абзаца текущей логической
страницы (`pageStarts[page]` / `_pageStartPara[page]`). Не использовать номер
страницы: он меняется от ширины и кегля и не совпадёт между телефоном и вебом.
Проверку «только по-сербски» выполняет сервер.

`/admin` — защищённая панель статистики, пользователей, инцидентов и курсов.
Роль приходит как `isAdmin` и всегда проверяется Go middleware. Курсы имеют
состояния draft/published/archived; клиентам отдаётся только published.
Основной курс React и Flutter ищут в
`GET /v1/course/bundle/sr_grammar_prosvirina`, затем используют локальный
bundle. Администраторы задаются `CITAVUK_ADMIN_EMAILS`.

Проверки: `npm run lint`, `npm run test`, `npm run build`.

### Выкатка и грабли на сервере

VPS `85.137.89.21` — **общая машина**: там же ISPmanager, чужие сайты, почта
(exim4/dovecot), DNS (BIND) и mysql. Скрипты трогают только `/opt/citavuk`,
`/var/www/citavuk`, `/var/www/citavuk-files` и свои файлы в `conf.d`.

- `server/deploy/deploy.sh [--nginx]` — Go-сервер.
- `web/deploy/deploy.sh [--nginx]` — сайт.
- `web/deploy/publish-apps.sh` — APK, установщик Windows, портативный zip, архив
  Linux и `latest.json` (манифест автообновления настольных сборок; текст «что
  нового» берётся из `frontend/deploy/release-notes.txt`).

Грабли, на которые уже наступали:

1. **`types { … }` в nginx ЗАМЕНЯЕТ таблицу типов, а не дополняет её.** Правка
   MIME для `.mjs` на уровне `server` увела `index.html` в
   `application/octet-stream`, и браузеры начали скачивать сайт вместо показа.
   Точечно чинится только через `default_type` в отдельном `location`.
   Поэтому `deploy.sh` проверяет **Content-Type**, а не только код ответа: по
   кодам такое незаметно, там честные 200.
2. **Простой `scp` конфига nginx затирает TLS-блок certbot** — сайт остаётся
   без HTTPS. `--nginx` делает копию, кладёт шаблон, заново запускает
   `certbot --nginx`, проверяет `nginx -t` и при неудаче возвращает прежний
   файл. На общей машине битый конфиг кладёт заодно почту и чужие сайты.
3. **Сборки приложений лежат вне `/var/www/citavuk`.** Выкатка сайта подменяет
   этот каталог целиком; файлы внутри исчезали бы при каждом деплое.
4. **«Не открывается citavuk.ru, ошибка сертификата» — почти всегда кеш DNS.**
   Апекс когда-то указывал на парковку reg.ru (`95.163.244.138`), TTL 86400, и
   старый ответ живёт в кеше провайдера сутки; на парковке сертификат чужой,
   отсюда и предупреждение. Прежде чем чинить TLS, сверь фактический адрес:
   `curl -sv https://citavuk.ru/` показывает, куда реально пошло соединение.
   Авторитетно проверять через `dig A citavuk.ru @ns1.reg.ru`.

### Сборка под Linux (`frontend/deploy/linux/`)

`./deploy/linux/build.sh` из каталога `frontend/` собирает приложение в
контейнере и кладёт `build/citavuk-linux-x64.tar.gz` — оттуда его забирает
`publish-apps.sh`.

- **Контейнер, а не машина разработчика.** Flutter собирает Linux только на
  Linux, а результат зависит от версии glibc того хозяина, где его собрали.
- **База — Ubuntu 22.04, а не последняя.** glibc 2.35: бинарник, собранный на
  24.04, на 22.04 не запустится вовсе («GLIBC_2.38 not found»), обратное
  направление работает. Плюс `desktop_webview_window` просит через pkg-config
  именно `webkit2gtk-4.0`, которого в 24.04 уже нет.
- **Список пакетов повторяет `linux/flutter/generated_plugins.cmake`**:
  gstreamer нужен `audioplayers_linux`, webkit2gtk — `desktop_webview_window`.
  Появился плагин — список надо дополнить, иначе сборка падает на конфигурации
  CMake.
- **Версия Flutter берётся из локальной установки.** Собирать релиз другой
  версией, чем та, которой прогнали тесты, — верный способ получить расхождение,
  которое найдётся только у пользователя.
- Установка на стороне пользователя — `install.sh` в архиве: всё уходит в
  `~/.local`, root не нужен.

## 9. Бэкенд (`backend/main.py`)

FastAPI, `lifespan` загружает CLASSLA (`classla.Pipeline('sr')`). Эндпоинт `/analyze`
синхронный (FastAPI крутит в threadpool, чтобы блокирующий перевод не вешал loop).
CORS открыт (нужно для Flutter web/desktop). Лексикон-фолбэк читает `../lexicon.db`
(колонки `upos`/`feats`). Перевод: словарь → `deep_translator` (Google).

Swagger/OpenAPI в проде отключён; локально включается
`CITAVUK_ENABLE_DOCS=1`. Дорогие ручки ограничены per-IP token bucket.
`/img` и `/article` принимают только домены новостных лент и проверяют DNS и
каждый редирект; не заменять это обычным `urlopen`, иначе вернётся SSRF.
Разбор кешируется Redis → локальный `analysis_cache.py` → CLASSLA. SQLite-кеш
переживает перезапуск процесса, но без постоянного диска Space может исчезнуть
при пересборке, поэтому Redis остаётся основным межпроцессным кешем.

Аудирование:
- Go `/audio/lessons` читает RSS `Learn Serbian` и `Može Kafa`, но отдаёт
  реплики только при наличии файла в `web/public/transcripts/index.json`.
- Go `/audio/transcript?url=...` разрешает только JSON внутри
  `https://citavuk.ru/transcripts/`; это не открытый прокси.
- Python пока обслуживает `/audio/proxy` и `/audio/tts`; TTS кэшируется.
- Генерация реальных реплик:
  `GROQ_API_KEY=... python web/scripts/transcribe-podcasts.py --limit 0
  --feed learn-serbian --feed moze-kafa --ffmpeg /path/to/ffmpeg`.
  После генерации обязательно:
  `python web/scripts/transcribe-podcasts.py --normalize-only`.
- `/documents/extract` принимает PDF/DOCX до 32 МБ. PDFium читает текстовый
  слой, а пустые страницы распознаёт Tesseract (`srp+srp_latn`). На запрос
  допускается до 80 OCR-страниц, чтобы бесплатный CPU Space не зависал.
- При наличии `REDIS_URL` новости, статьи, разборы, переводы, TTS, подкасты и
  транскрипты дополнительно попадают в общий TTL-кеш. Память процесса остаётся
  быстрым L1, а при недоступном Redis сервис сразу продолжает без него.

## 9a. Архитектура системы целиком

Citavuk — монорепозиторий, но не монолит. В production одновременно работают
четыре контура, а общие форматы и данные связывают их между собой.

| Контур | Код | Состояние | Ответственность |
|---|---|---|---|
| Flutter | `frontend/` | SQLite `user.db`, SharedPreferences, bundled assets | Android, Windows, Linux и macOS: библиотека, читалка, курс, офлайн-режим |
| React | `web/` | IndexedDB, localStorage, static assets | Сайт `citavuk.ru`: браузерная читалка, курс, события, импорт и публичные разделы |
| Go API | `server/` | PostgreSQL, необязательный Redis/Valkey | Аккаунты, сессии, синхронизация, перевод, прогресс, общий rate limit и reverse proxy |
| Python NLP | `backend/` | CLASSLA, SQLite/Redis-кеши | Морфология, новости, извлечение документов, TTS и оставшиеся тяжёлые ручки |

### Границы и адреса

- Пользовательские клиенты ходят в `https://api.citavuk.ru`. Go обслуживает
  собственные `/v1/*` и часть `/audio/*`, а неизвестные старые пути проксирует в
  Python upstream. Не вшивать адрес Hugging Face в новый клиентский код.
- React-сайт и его статические файлы отдаёт nginx из `/var/www/citavuk`.
  Go-сервис запущен отдельно из `/opt/citavuk`; релизные архивы приложений лежат
  в `/var/www/citavuk-files`.
- PostgreSQL — источник истины для аккаунтов и синхронизации. Redis ускоряет
  rate limit и кеши, но не должен быть точкой отказа. Локальные базы клиентов
  обязательны: чтение, курс и уже загруженные данные должны открываться офлайн.

### Основные потоки данных

**Вход и сессия**

```text
Flutter AuthService / React AuthProvider
  -> Go /v1/auth/*
  -> PostgreSQL (users, sessions, одноразовые hashed-токены)
  -> Resend или OAuth-провайдер при необходимости
  -> bearer token в локальном хранилище клиента
```

Клиент восстанавливает локальную сессию без сетевого запроса. `401` при первом
защищённом запросе инвалидирует её. Нельзя переносить session token в URL,
логи, аналитику или синхронизируемый документ.

**Синхронизация пользовательских данных**

```text
SQLite user.db / IndexedDB
  -> POST /v1/sync/push (только dirty-записи и tombstones)
  -> GET /v1/sync/changes?since=cursor
  -> локальное слияние по updated_at
  -> загрузка текста выбранной книги по contentSha
```

Текст не входит в общий список изменений. Его sha256 одинаково считают Go,
Dart и TypeScript по длине UTF-8 каждого абзаца и самим байтам. Любое изменение
этого формата является изменением протокола и требует парных тестов во всех
трёх реализациях.

**Разбор слова и перевод**

```text
Reader / WordReader
  -> UTF-16 offset переводится в UTF-8 byte offset
  -> Go /v1/analyze или /v1/translate/context
  -> личный rate-limit user:<uuid> (для гостя ip:<address>)
  -> кеш PostgreSQL/Redis
  -> Python CLASSLA или DeepL/fallback
  -> WordAnalysis / TranslationResult
  -> локальный словарь как офлайн-fallback во Flutter
```

Не отправлять отдельное сербское слово в DeepL без контекста. Для слова в
предложении используется `<w>` и байтовые смещения; для голого слова — запасной
провайдер. Изменение смещений проверяется кириллическими примерами.

**Курс, диалоги и события**

```text
course_content/*.json
  -> tools/course_build (нормализация и строгая валидация)
  -> frontend/assets/course/course_bundle.json
  -> Flutter bundle + web/scripts/prepare-course-assets.mjs
  -> локальный прогресс
  -> /v1/course/progress/{courseId} после входа
```

Сервер хранит JSON-документ прогресса и не знает все клиентские поля. Поэтому
новое поле должно переживать чтение старым клиентом, а слияние обязано сохранять
неизвестные или параллельно изменённые части. Событие «Одиссея» использует тот
же транспорт с отдельным id `event-odyssey-2026`, но собственную локальную
схему и доступ только для аккаунта.

**Публичный контент и статические ассеты**

- Генераторы (`tools/build_public_library.py`, `web/scripts/build-materials.py`,
  `web/scripts/prepare-odyssey-event.py`) отвечают за воспроизводимость,
  лицензии, метаданные и проверку источников. Не править их результат вручную,
  если рядом есть исходник или генератор.
- Каталоги содержат только метаданные. Книги, PDF, транскрипты и песни грузятся
  после выбора, чтобы стартовая страница не вытаскивала весь корпус в память.
- Vite lazy chunks, PDF worker и хешированные assets являются частью контракта
  деплоя. Старые chunks сохраняются 14 дней для вкладок, открытых до релиза.

| Sync-поле | Go store/API + Dart + TypeScript | tombstone, dirty ack, `updated_at`, парные contract-тесты |
| Настройки читалки | Dart `ReaderSettings` + web `readerSettings.ts` | sanitize, старый localStorage, обе читалки и контраст |
| Новый тип упражнения | Go course builder + Dart + TypeScript | модель, валидатор, renderer, evaluator, общий bundle |
| Аудиоурок | Go podcast API + `web/public/transcripts/` | реальный transcript, Range/proxy, отсутствие transcript |
| Генерируемый контент | соответствующий script + output | источник, лицензия, детерминизм, размер production bundle |

## 9b. Как вносить изменения в код

### 1. Определить поверхность и контракт

1. Выполнить `git status --short` и сохранить чужие незавершённые изменения.
2. Найти точку входа через `rg`: маршрут/экран, вызываемый service/API, модель и
   место хранения. Не начинать с правки одного компонента без чтения соседних
   слоёв.
3. Решить, меняется ли только UI или также сетевой контракт, локальная схема,
   общий bundle, прогресс, синхронизация либо генератор ассетов.
4. Найти парные реализации. Особенно опасны: Dart/TypeScript reflow и content
   hash, SRS, разбиение сербских букв, course models, reader settings и UTF-8
   offsets.
5. До редактирования записать инварианты данных: офлайн-запуск, tombstones,
   `dirty` только после ack, lazy content, совместимость со старым клиентом.

### 2. Реализовать минимальный вертикальный сценарий

- Модель и валидация должны появляться до UI, API и миграция — до клиента,
  который на них полагается. Для необязательной серверной функции оставлять
  локальный fallback.
- Пользовательский ввод валидировать на границе. URL проверять allowlist и DNS,
  файлы — по размеру и сигнатуре, JSON — по типам и лимитам. Ошибки сети не
  должны уничтожать локальные данные или снимать `dirty`.
- Новый экран переиспользует существующие `request`, `WordReader`, auth state,
  sync и дизайн-токены. Не создавать второй HTTP-клиент, вторую реализацию
  перевода или отдельный механизм сессий.
- Для временного события отдельно задаются стабильный id, временное окно,
  guest gate, локальная схема прогресса, merge с сервером и правило награды.
- Генерируемые файлы получать штатным скриптом. В коммит включать только те
  outputs, которые реально нужны runtime и намеренно отслеживаются Git.

### 3. Покрыть риски тестами

- Чистую логику проверять unit-тестами рядом с модулем.
- Маршруты и сериализацию проверять contract-тестами на старом и новом payload.
- Миграции проверять на базе предыдущей версии, а не только на пустой БД.
- Авторизацию проверять как минимум в трёх состояниях: гость, обычный аккаунт,
  истёкшая/отозванная сессия; admin-функции ещё и обычным аккаунтом.
- Responsive UI проверять на desktop и узком viewport, включая длинный русский
  текст, меню, отсутствие горизонтального overflow и модальные слои.
- Внешний контент проверять по фактическому файлу/ответу и фиксировать источник
  и лицензию. Наличие URL само по себе не является проверкой.

### 4. Запустить проверки по затронутой зоне

| Зона | Минимальные команды |
|---|---|
| React | `cd web; npm run lint; npm test; npm run build` |
| Go API | `cd server; gofmt -w <изменённые .go>; go test ./...; go vet ./...; go build ./...` |
| Python | `python -m py_compile backend/main.py backend/urlguard.py backend/ratelimit.py backend/analysis_cache.py` и релевантные `unittest` |
| Flutter | `cd frontend; flutter test; dart analyze lib; flutter build windows --debug` |
| Course content | `cd tools/course_build; go test ./...; go run . -out ../../frontend/assets/course/course_bundle.json` |
| Английский словарь | `python tools/build_english_lexicon.py` — нужны `nltk`, `regex` и корпуса `wordnet`/`brown`/`universal_tagset`. ⚠️ venv лежит внутри репозитория, и защитный хук nltk блокирует свои же импорты из текущего каталога: скрипт сам уходит во временный каталог, руками интерпретатор запускать только оттуда же |
| Сайт + приложение | проверки React и Flutter; при изменении API также полный набор Go |

После добавления или удаления Flutter-пакета перед проверками обязательно
`flutter clean` и `flutter pub get`. Предупреждение Vite о размере чанка не
равно ошибке, но новый крупный экран должен оставаться lazy. Пропущенную из-за
отсутствия БД, ключа или платформы проверку явно указывать в отчёте.

### 5. Проверить diff и выпустить

1. Выполнить `git diff --check`, просмотреть `git diff --stat` и полный diff
   изменённых контрактов, миграций, конфигурации и generated manifests.
2. Не коммитить `.env`, OAuth secrets, SSH-ключи, signing key, модели CLASSLA,
   `node_modules`, `dist` и локальные базы/кеши.
3. Коммит должен содержать один завершённый сценарий вместе с тестами,
   миграциями, runtime-ассетами и актуализацией `AGENTS.md`/README.
4. Серверный контракт выкладывать до клиента. Статику сайта — до публикации
   приложений, если приложение скачивает каталог или assets с `citavuk.ru`.
5. Сайт: `cd web && ./deploy/deploy.sh`. Флаг `--nginx` использовать только
   при осознанном изменении vhost. Go: `cd server && ./deploy/deploy.sh`.
   Приложения публикуются отдельно через `web/deploy/publish-apps.sh`.
6. После деплоя проверить публичные URL, Content-Type, lazy route, гостевой и
   авторизованный сценарии, консоль браузера и один узкий viewport.
7. Только после успешных проверок отправлять коммит в GitHub. Не делать
   force-push общей ветки и не переписывать чужую историю.

## 10a. Курс грамматики (`lib/course/`)

Раздел «Грамматика» на главной — игровой курс, а не список карточек. Старый
`GrammarCardsScreen` остался справочником и открывается из шапки курса.
`GrammarScreen` из читалки и `GrammarEngine` не затронуты.

### Слои

```
course_content/           исходный контент (JSON, редактируется руками)
tools/course_build/       Go: валидация + сборка bundle
tools/sprite_build/       Go: удаление фона, atlas, manifest
animations/source/        исходные PNG-кадры (НЕ входят в приложение)
animations/qa/            листы визуальной проверки спрайтов
frontend/lib/course/
  models/     Exercise (sealed), Course/Unit/Skill/Lesson, Answer, progress
  services/   answer_evaluator, serbian_text, mastery_engine, загрузчики
  state/      LessonController, CourseController
  widgets/    ExerciseHost + по виджету на тип упражнения, CitavukSprite
  screens/    CoursePathScreen, LessonScreen
```

### Правила, которые легко нарушить

- **Контент не парсится из книги в рантайме.** Книга → `course_content/*.json`
  руками → валидатор → `frontend/assets/course/course_bundle.json`. Правка
  bundle бессмысленна: он перезаписывается.
- **Исходный JSON пишется кратко.** `normalize.go` дописывает `id`, `unitId`,
  `skillId`, `lessonId`, `difficulty`, `serbianScript` и наследует `sourceRef`
  от unit к упражнению до валидации. Все прежние правила проверяются уже на
  полных объектах. Таблица умолчаний — в `course_content/SCHEMA.md`.
- **Цель обучения от skill подставляется только когда она там одна.** Иначе
  правило «каждая цель покрыта упражнением» закрылось бы само собой; при
  нескольких целях автор перечисляет их в `lesson.objectives`.
- **`č`/`ć` и `dž`/`đ` не нормализуются.** `normalizeAnswer` трогает только
  пробелы, регистр, терминальную пунктуацию и разложенные диакритики.
  Схлопывание этих букв обессмыслит упражнения.
- **Порядок слов проверяется по-настоящему.** `sentence_builder` не принимает
  произвольную перестановку тех же токенов — только подпоследовательность
  допустимого порядка с пропуском необязательных токенов.
- **Разбиение на буквы должно совпадать в Go и Dart.** `splitLetters` есть в
  `tools/course_build/validate.go` и `lib/course/services/serbian_text.dart`.
  Правишь одно — правь второе, иначе валидатор и клиент разойдутся.
- **Исходные PNG лежат вне `frontend/`.** Иначе 15 МБ кадров попадут в APK.
  В приложение входит только `assets/animations/generated/`.
- **Прогресс переживает обновление контента.** `CourseController._reconcile`
  отбрасывает записи об исчезнувших уроках, но не стирает остальное;
  незавершённая попытка снимается при смене `contentChecksum`.
- **Игровые диалоги используют тот же документ прогресса.** Общие сценарии
  лежат в `frontend/assets/course/dialogues/`; React копирует их через
  `prepare-course-assets.mjs`. Поле `dialogues` хранит текущий узел, историю
  выборов, статус и `updatedAt`. При слиянии клиентов побеждает более новая
  запись конкретного диалога. На React диалоги живут в отдельном разделе
  `/dialogues`, первый сценарий открывается по `/dialogues/drinkit`; старый
  `/course/dialogue/drinkit` оставлен только для совместимости ссылок. В курсе
  должна оставаться компактная кнопка на раздел, а не сам каталог диалогов.
  Реплики рендерятся через `WordReader`, поэтому перевод и сохранение слов не
  должны дублировать механизм читалки. Озвучка идёт через `/audio/tts`.
  Первый сценарий доступен гостю локально, а после входа синхронизируется через обычный
  `/v1/course/progress/{courseId}`.

### Типы упражнений

`multiple_choice`, `matching`, `fill_blank`, `sentence_builder`,
`ending_picker`, `letter_unscramble`, `image_description`, плюс два для работы
с текстом:

- **`reading_qa`** — связный текст и вопросы к нему. Текст остаётся на экране,
  пока идут ответы: проверяется понимание прочитанного, а не память. Ответ
  засчитывается целиком.
- **`form_hunt`** — найти в тексте все формы заданного признака. Текст хранится
  списком токенов, а не строкой: делить сербский текст на слова пришлось бы
  одинаково в Go, Dart и TypeScript, и любое расхождение разошлось бы с
  проверкой ответа.

Добавление типа затрагивает четыре места: `tools/course_build/{model,validate}.go`,
`lib/course/models/exercise.dart` + виджет + `answer_evaluator.dart` +
`exercise_host.dart`, `web/src/course/{types.ts,data.ts}` и `ExerciseView` в
`web/src/pages/CourseLesson.tsx`.

### Тренажёрка

Практика по темам вне порядка курса: `lib/course/screens/trainer_screen.dart`
и `web/src/pages/Trainer.tsx` (маршрут `/trainer`, ссылка в шапке и подвале).
Тема — это skill, а не урок. Прогресс уроков тренажёрка **не пишет**: иначе
«пройденный» урок означал бы то разобранную теорию, то удачную серию ответов.
Экран прохождения переиспользуется (`LessonScreen`, `ExerciseView`), своя
копия разошлась бы с курсом на первой же правке.

### Команды

```
cd tools/course_build && go run .                    # валидация + сверка с лексиконом
cd tools/course_build && go run . -out frontend/assets/course/course_bundle.json
cd tools/course_build && go test ./...               # тесты ридера SQLite и сверки
cd tools/sprite_build  && go run .                   # пересборка спрайтов + QA
cd tools/sprite_build  && go run . -check            # atlas устарел?
cd tools/sound_build   && go run .                   # пересборка звуков
cd frontend && flutter test                          # 162 теста
```

Валидатор читает `lexicon.db` собственным минимальным ридером формата SQLite
(`tools/course_build/sqlite_reader.go`) — без CGO и внешних зависимостей.
Конфликт формы с лексиконом даёт предупреждение, отсутствие формы — нет:
словарь покрывает лишь часть языка.

Сборка bundle всегда идёт в strict-режиме: повреждённый контент в production
не попадёт. Модули Go лежат в своих каталогах и сами находят корень репозитория,
поэтому запускать можно откуда угодно.

### Что ещё не сделано

- Регистрация и PostgreSQL реализованы в `server/`; прогресс курса
  синхронизируется через `GET/PUT /v1/course/progress/{courseId}`. Локальная
  копия остаётся обязательной для офлайн-запуска.
- Итоговая контрольная — на карте курса стоит заглушка-карточка (`blueprint` пуст).
- `image_description`: режимы `choose` и `free` реализованы, `build`/`fill`
  требуют расширения схемы (у них нет полей tokens/blanks).
- Курс переписан целиком под программу из 7 частей: 8 units, 48 уроков,
  299 упражнений. Прежние `u_imenice_rod` и `u_padezi` удалены, их темы
  разошлись по `u_imenice`. См. таблицу в `course_content/SCHEMA.md`.
