# Руководство преподавателя: контент курса грамматики

Документ для человека, который проверяет и правит учебный материал. Знание
Dart и Go не требуется — нужен текстовый редактор и одна команда в терминале.

## Главное правило

Исходный Markdown книги — это **OCR скана**, а не выверенный текст. В нём
систематически:

- обрезан левый край строк (`твительные` вместо `Существительные`);
- искажены сербские слова (`sfudepf—sfudenti` вместо `student—studenti`);
- перемешаны строки таблиц спряжения;
- нечитаема кириллическая колонка алфавита.

Поэтому **ни одна сербская словоформа в курсе не должна приниматься на веру
из книги**. Книга отвечает на вопрос «какое правило здесь изучается и как оно
подано», а конкретная форма проверяется по словарю. Автоматически созданный
контент имеет статус `machine_checked`; `teacher_reviewed` ставит только
человек.

## Где что лежит

```
course_content/
  course.json          индекс курса: версия, настройки, порядок разделов
  units/u_*.json       один файл на раздел — это и есть учебный материал
  SCHEMA.md            описание всех полей и правил валидации
  TEACHER_GUIDE.md     этот файл
```

Собранный файл `frontend/assets/course/course_bundle.json` **править нельзя** —
он генерируется. Правки вносятся в `course_content/units/*.json`.

## Как найти тему

Разделы перечислены в `course.json` в поле `units`. Каждый ID соответствует
файлу: `u_padezi` → `course_content/units/u_padezi.json`.

Внутри файла структура читается сверху вниз:

```
unit (раздел)
  skills (темы)
    objectives (учебные цели)
    lessons (уроки)
      intro (вступление)
      exercises (упражнения)
```

## Как проверить правило по источнику

У каждого упражнения и вступления есть блок `sourceRef`:

```json
"sourceRef": {
  "sourceBook": "Просвирина О. А. и др. Сербский язык. — М.: ВКН, 2018",
  "sourceHeading": "5.2.3. ПАДЕЖИ • PADEŽI",
  "sourceAnchor": "md:838-922",
  "sourceEditionOrFileHash": "sha256:bf73a749...",
  "contentVersion": "1.0.0",
  "reviewStatus": "machine_checked"
}
```

`sourceAnchor` — это **диапазон строк** исходного Markdown. `md:838-922`
означает строки 838–922. Открой книгу в редакторе с нумерацией строк и перейди
на строку 838.

`sourceEditionOrFileHash` — отпечаток файла книги. Если книгу заменили на
другую версию, валидатор предупредит о несовпадении: анкоры могли съехать.

## Как изменить формулировку или ответ

Все поля — обычный текст в JSON. Что чаще всего требует правки:

| Поле | Что это |
|------|---------|
| `prompt` | формулировка задания |
| `explanation` | объяснение, которое видно после проверки ответа |
| `hint` | подсказка до ответа |
| `options[].text` | варианты ответа |
| `options[].correct` | какой вариант правильный (`true` ровно у одного) |
| `fullForm` | полная правильная словоформа |
| `acceptedOrders` | допустимые порядки слов в предложении |
| `acceptedAnswers` | допустимые варианты ввода |

Если у неправильного варианта заполнены `misconceptionId` и `feedbackKey` —
это диагноз типичной ошибки. Ставь их у тех вариантов, которые отражают
реальное заблуждение (падеж перепутан, `č` вместо `ć`), а не у случайных.

### Правило про диакритику

`č` и `ć`, `dž` и `đ` — **разные буквы**, движок их не приравнивает. Проверяй,
что в ответе стоит именно нужная. Ответ на кириллице по умолчанию не
засчитывается: это настраивается флагом `acceptBothScripts` в `course.json`.

## Как отметить проверенное

В `sourceRef` поменяй статус и укажи себя:

```json
"reviewStatus": "teacher_reviewed",
"reviewedBy": "Фамилия И."
```

Статусы:

- `draft` — черновик; в production-сборку не попадает;
- `machine_checked` — прошёл автоматическую валидацию;
- `teacher_reviewed` — проверен человеком.

Если упражнение нужно временно убрать из курса, не удаляя, добавь причину:

```json
"blockedReason": "no_asset"
```

Такое упражнение исключается из сборки с предупреждением.

## Как пересобрать и проверить курс

Из корня репозитория:

```
cd tools/course_build
go run . -out frontend/assets/course/course_bundle.json
```

Команда сначала валидирует контент, и только при отсутствии ошибок собирает
файл для приложения. Если есть хоть одна ошибка — сборка не выполняется.

Проверить, ничего не собирая:

```
go run .
```

Вывод выглядит так:

```
WARN  course.json → finalExam : blueprint пуст
units: 1/1 загружено, lessons: 4, objectives: 5 | warnings: 1, errors: 0
```

Каждая строка ошибки содержит путь до конкретного элемента:

```
ERROR units/u_padezi.json → skill sk_vokativ → lesson l_padezi_3 →
      exercise ex_vok_4 : нет правильного варианта
```

## Что проверяет валидатор

Сборка падает при:

1. повторяющихся ID;
2. ссылке на несуществующий предыдущий урок или цикле в них;
3. пустом уроке;
4. отсутствии правильного ответа;
5. совпадении правильного варианта с неправильным;
6. отсутствующем файле изображения;
7. неверном `sourceRef` (пустые поля, анкор за пределами книги);
8. неизвестном типе упражнения;
9. ссылке на несуществующую учебную цель;
10. учебной цели, не покрытой ни одним упражнением;
11. итоговой контрольной, не покрывающей раздел;
12. черновике в production-сборке;
13. нарушении настроек письменности.

Предупреждения (не ломают сборку, но требуют внимания): урок вне диапазона
6–12 упражнений, несовпадение хеша книги, `draft`-контент.

## Как добавить новый раздел

1. Создай `course_content/units/u_<имя>.json` по образцу существующего.
2. Добавь `"u_<имя>"` в массив `units` в `course.json` — порядок в массиве
   задаёт последовательность прохождения.
3. Пропиши `prerequisites` у первого урока нового раздела, чтобы он
   открывался после предыдущего.
4. Запусти валидатор.

Валидатор падает на раздел, объявленный в `course.json`, но не имеющий файла.
Поэтому добавляй ID в индекс только вместе с готовым файлом.

## Чего делать не нужно

- Не редактируй `course_bundle.json` — правки затрутся при пересборке.
- Не ставь `teacher_reviewed` пакетно, не открыв источник.
- Не переноси сербские формы из OCR копипастой.
- Не удаляй `sourceRef`, даже если формулировка стала авторской: происхождение
  правила должно оставаться прослеживаемым.
