# Персональная колода уроков — состояние реализации

## Рабочий сценарий

- React: `/personal`, ленивый экран `web/src/pages/PersonalLessons.tsx`.
- Flutter: «Ещё → Учиться → Урок дня», `personal_lessons_screen.dart`.
- Пользователь выбирает CEFR и отвечает на 10 серверных вопросов. Список
  вопросов не дублируется в клиентах. Начальный уровень берётся из аккаунта.
- `POST /v1/personal` ставит задачу в PostgreSQL и возвращает id. Повторный
  запрос в течение 30 календарных дней возвращает существующую колоду.
- `internal/personal` использует имеющиеся `DailyAIKey`/`DailyAIURL`, но свою
  модель **deepseek/deepseek-v4-flash-0731**. На другой slug молча не переключается.
  Реальный платный запрос к шлюзу при разработке не выполнялся.
- Рабочий процесс составляет план и 30 отдельных уроков. Готовые дни доступны
  сразу; последующие открываются по календарной дате в часовом поясе плана.
  `month` вычисляет сервер в этом же поясе, не часы устройства.
- JSON содержит текст, правила, табличную схему и 4–8 заданий choice/fill/translate.
  HTML и исполняемые схемы не используются. Грамматика валидируется структурно,
  но экспертная корректность ответа модели этим не гарантируется.
- Редактор доступен только владельцу, передаёт revision. Конфликт — 409, а не
  молчаливое затирание. У пройденного урока сохраняются completed_content,
  completed_revision, ответы, score и total; дальнейшая правка их не меняет.
- Завершение — отправлены ответы на все задания, независимо от процента.
  Повторное завершение возвращает сохранённый результат и не выдаёт новую серию.
- Три отрицательные оценки среди последних пяти новых оценок предлагают
  пересоставить оставшиеся занятия. Нужен текстовый отзыв. Пройденные и
  отредактированные карточки сохраняются. Старые оценки после принятого отзыва
  не вызывают следующее предложение. Защита расходов: 3 пересоставления и
  3 ручных повтора ошибочной задачи на колоду; не платная механика.

## Очередь и инварианты

Миграции `0044_personal_lessons.sql`, `0045_study_streak.sql`. Worker получает
двухминутную аренду и случайный lease_token; просроченный worker не может
сохранить ответ после передачи задачи другому серверу. Каждый готовый урок
сохраняется сразу. Автоматически выполняются до трёх попыток с минутной паузой.
Остановка API отменяет сетевой запрос; после истечения аренды другой запуск
продолжает недостающие уроки. В каждый момент работает одна генерация на процесс.
При росте очереди потребуется отдельный масштабируемый worker, не увеличение
количества goroutine без ограничения бюджета.

`GET /v1/personal` — доступность, вопросы, последняя колода и `history` (id,
startedAt, level только текущего владельца). Архив доступен через выбор «Моя
колода» на React и Flutter. Возврат из старого урока сохраняет выбранную колоду.
Остальные ручки:

- `GET /v1/personal/{plan}` — метаданные и прогресс всех дней без будущего текста;
- `GET|PUT /v1/personal/{plan}/days/{day}` — получить/изменить открытый урок;
- `POST .../days/{day}/complete` — revision + answers;
- `PUT .../days/{day}/rating` — rating -1/0/1;
- `POST .../{plan}/regenerate` — feedback;
- `POST .../{plan}/retry` — возобновить ошибочную задачу.

Все ручки требуют аккаунт и проверяют владельца. Старые `/v1/daily` остаются
отдельным окном слов дня: их данные и поведение не подменяются.

## Серия и две бесплатные заморозки

`internal/study` — чистая календарная логика, `store/study.go` — атомарное
хранение. Начальный запас **2**, без неоговорённых покупок или автопополнения.
Замораживаются только закончившиеся пропущенные сутки. Заморозка сохраняет
серию, но не увеличивает число дней занятий; по исчерпании запаса серия обнуляется.
Повторные запросы и параллельные устройства списывают запас только один раз.
Часовой пояс пока закрепляется после первого занятия; его произвольная смена
не позволяет получить два зачёта за сутки. DST считается по датам, не по 24 часам.

`GET /v1/study` возвращает current/longest/freezes/activeDays/todayActive и календарь
за последний год. `PUT /v1/study` задаёт timezone до первого занятия.
Публичной ручки «начисли день» нет; зачёт вызывает сервер после сохранения результата.

**Пока подключено только завершение персонального урока.** Ещё предстоит:

- подключить обычный курс, тренажёрку и SRS к той же серии, сохранив старую историю;
- заменить старые счётчики в профиле, окне слов дня и Android-виджетах;
- добавить общий одноразовый эпизод с Читавуком, зажигающим печку;
- подключить существующий TTS к урокам типа listening;
- добавить варианты допустимых свободных ответов и пользовательское добавление/
  удаление правил и упражнений в редакторе (сейчас редактируются существующие);
- завершить UX-полировку колоды: осмысленная анимация раскрытия, управление
  клавиатурой, предупреждение об уходе с несохранёнными правками, визуальная QA;
- сжатые web-варианты фоновых PNG через штатную подготовку ассетов.

До завершения этих пунктов не объявлять всю большую задачу или новую единую
серию готовой, не выпускать приложения автоматически.

## Месячные иллюстрации

### Оформление карт (9 сентября)

React использует `PersonalPlayingCard` и `PlayingCardFrame`, Flutter —
`PersonalPlayingCard`. После обратной связи ручная геометрическая рамка заменена
на скачанную гравюру; на рубашке расположен медальон с мотивом Раваницы.
Происхождение, лицензии и преобразования перечислены в
`design/card-assets/CREDITS.md`. Угловые индексы сохранены. Масти обозначают тип:
чтение/письмо — пики, грамматика — трефы, лексика — бубны, аудирование — червы.
Это оформление учебной колоды, не попытка воспроизвести историческую сербскую
карточную систему. Название и действие находятся на затемнённой нижней части.
Точки-разделители в заголовках заменены отдельными подписями. Палитра карт
винно-красная/синяя/золотистая, с одинаковым контрастом в обеих темах.
Рамка статическая; лаковый блик и готовые CC0-частицы Kenney учитывают reduced
motion. Flutter кеширует статическую поверхность через RepaintBoundary.

12 PNG в `web/public/personal/months/01.png` … `12.png`, встроенный imagegen,
промпты и исходный референс в `docs/personal-month-art.json`. Это художественная
стилизация, а не документальное изображение объектов. В приложение не бандлятся
все 12: загружается один месяц по HTTPS с сайта; ошибка изображения не блокирует
урок. Публиковать статику нужно до выпуска Flutter-клиента.

## Проверки

Go-тесты проверяют DST, повторные зачёты, расход двух заморозок, длинный перерыв,
владение колодой, закрытые дни, конфликт revision и конкурирующие завершения.
Интеграционные тесты запускаются на отдельном PostgreSQL с pgvector через
`CITAVUK_TEST_DATABASE_URL`, не на production. Есть Flutter-тест анкеты на 360 dp
и тесты снимка сессии/сохранения. Web-тесты проверяют контракт завершения и 409.

Прежний сбой `PerfWitnessServer._shutdown` устранён обновлением SDK до
Flutter 3.47.2 / Dart 3.13.2. 9 сентября 2026 `dart analyze lib` завершился
с `No issues found!` после удаления мёртвых веток прежней шапки, обновления
TickerMode и исправления замечаний линтера. Правила анализа не отключены.
