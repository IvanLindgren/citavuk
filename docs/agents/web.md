# Веб-версия (`web/`)

Подробности сборки — `web/README.md`.

## Устройство

Сайт citavuk.ru. Отдельное приложение, не Flutter Web: тот собирает веб через
CanvasKit — несколько мегабайт wasm до первой отрисовки, текст рисуется на канве
и потому плохо выделяется и хуже читается дикторами. Приложение остаётся на
Flutter, там эти минусы не проявляются.

**Важно:** `frontend/web/` — служебная папка Flutter (`sqlite3.wasm`,
`sqflite_sw.js`). React живёт в `web/` в корне репозитория, рядом с `server/`.

Ключевые решения — подробности в `web/README.md`:

- **Свой роутер** вместо библиотеки: маршрутов меньше десятка, нужны только
  переход и параметр пути. Разбор путей покрыт тестами.
- **Смещения слова уходят в байтах UTF-8.** JavaScript индексирует строку в
  UTF-16, для кириллицы числа не совпадают. Пересчёт — `utf8ByteOffset`.
- **Ассеты пересобираются** скриптом `web/scripts/prepare-assets.py`: шрифты в
  WOFF2, картинки в WebP двух плотностей (12,1 МБ → 1,5 МБ). Результат в
  репозитории не хранится.
- **Тема применяется до первой отрисовки** скриптом в `index.html`, иначе на
  тёмной теме мигает светлый фон.
- **Каждая анимация спрашивает `useReducedMotion`.**

**Синхронизация** (`web/src/api/sync.ts`) повторяет модель приложения:
отправить своё → забрать чужое → догрузить тексты. В общем sync cursor идут
книги, словарь и SRS reviews. Хранилище — IndexedDB
(`web/src/lib/db.ts`), а не localStorage: тот ограничен ~5 МБ и синхронен, а
книги с других устройств его переполнят. Метаданные и текст лежат в разных
хранилищах — список книг не должен вытаскивать в память сами книги.

Инварианты те же, что в приложении: удаление оставляет надгробие, флаг `dirty`
снимается только после подтверждения сервером, текст качается при открытии
книги, а не при синхронизации. При снятии `dirty` обязательно сравнивается
отправленный `updated_at`, чтобы параллельная локальная правка не потерялась.

React-маршруты `/course` и `/course/lesson/:id` используют тот же
`frontend/assets/course/course_bundle.json`, атласы и звуки, что Flutter.
`web/scripts/prepare-course-assets.mjs` переносит их в production assets.
В React упражнения перемешиваются внутри уровня сложности при каждой попытке,
matching нельзя проверить до заполнения всех пар, а статус `completed` ставится
только при достижении `passThreshold`. Для свободного ввода используется
экранная клавиатура сербских спецсимволов. Пока исходный атлас неровный,
`CourseSprite` намеренно показывает один увеличенный кадр без анимации.

Курс обязан открываться без сети. Во Flutter `CourseContentLoader` сначала
показывает встроенный bundle, а серверную публикацию проверяет в фоне; валидная
публикация применяется при следующем открытии. На React серверный запрос
ограничен коротким таймаутом и параллельно загружается bundled JSON. Не
возвращать последовательность «сначала сеть, затем asset»: при недоступном API
первый урок выглядит как чёрный экран.

Страницы курса являются lazy chunks. `main.tsx` слушает `vite:preloadError` и
один раз обновляет устаревшую вкладку, а `PageErrorBoundary` показывает
восстановление вместо пустого фона. `web/deploy/deploy.sh` сохраняет
хешированные assets предыдущих сборок 14 дней. Не удалять их сразу после
подмены `index.html`: открытая до выкладки вкладка может запросить chunk только
после клика по «Курс».

Маршруты `/listening` и `/listening/:id` получают каталог из Go
`/audio/lessons`. Настоящие расшифровки лежат статикой в
`web/public/transcripts/`, сопоставление аудио с файлом — `index.json`.
`web/scripts/transcribe-podcasts.py` отправляет само аудио в Groq
`whisper-large-v3-turbo` и сохраняет пословные тайминги; MP3 режется по кадрам,
M4A конвертируется через указанный `--ffmpeg`. Никогда не возвращать старый
алгоритм «описание RSS → фразы → время пропорционально длине»: такой текст не
совпадает с речью. Если транскрипта нет, `cues` должны быть пустыми, а аудио
доступным. Длинный транскрипт рендерится лениво через `content-visibility`.

Авторизация веба живёт в `web/src/state/auth.tsx`. `/verify-email` завершает
регистрацию по ссылке из письма, `/auth/yandex` обменивает одноразовый код
callback на сессию. Не записывать токен сессии в query string: URL попадает в
историю, логи прокси и `Referer`.

Временные события веба живут на `/events`; конкретное событие открывается
отдельным lazy route и может требовать аккаунт. «Одиссея» (`/events/odyssey`)
доступна с 1 августа до 1 сентября 2026 года. Её 24 песни собираются скриптом
`web/scripts/prepare-odyssey-event.py` из public-domain перевода Томо Маретича
1915 года, переводятся в сербскую кириллицу и бандлятся отдельным JSON-чанком.
Прогресс хранится локально по `account.id` и объединяется с серверным документом
`event-odyssey-2026` через `/v1/course/progress/{courseId}`. Песни закрываются
только по порядку; все 24 открывают тему читалки `odyssey`. Тема не применяется,
если награда не принадлежит текущему аккаунту. Мобильное меню разделов —
сгруппированная двухколоночная панель, а не длинный вертикальный список.

Импорт библиотеки поддерживает TXT, Markdown, DOCX и PDF. Mammoth и PDF.js
подгружаются динамически. Текстовый слой PDF извлекается в браузере; PDF-скан
отправляется в `/documents/extract`, где Tesseract использует `srp` и
`srp_latn`. Не переносить OCR-модели в основной web-bundle.
При недоступном Space Tesseract.js обрабатывает не более 12 страниц одним
worker; лимит защищает вкладку от роста памяти.

**Worker PDF.js лежит в `public/pdf.worker.js`**, копируется при сборке
(`npm run prepare:worker`). Не возвращать сборку worker'а через Vite: тот даёт
имя с расширением `.mjs`, которого нет в `mime.types` nginx, файл уходит как
`application/octet-stream`, и браузер отказывается исполнять модуль. Хуже того,
имя содержит хеш и не меняется — один раз закешированный неверный ответ с
`immutable` не исправить ничем. Собирать сайт только через `npm run build`, а не
`vite build`: иначе worker в `dist/` не попадёт, и импорт PDF молча отвалится.

## Пререндер сайта (`web/scripts/prerender.mjs`)

Статические разделы отрисовываются headless-браузером на сборке и сохраняются
плоскими файлами: `/course` → `dist/course.html`. Раскладка именно плоская —
`dist/course/` уже занят ассетами курса, и вариант с каталогом ломает страницу
(см. комментарий в `web/deploy/nginx-site.conf`). nginx разводит их правилом
`try_files $uri $uri.html /index.html`.

Один документ для человека и для робота: разделение по User-Agent — клоакинг,
и делать его нельзя. Список адресов берётся из `dist/sitemap.xml`, второго
списка маршрутов заводить не нужно — он разойдётся с первым.

Уроки преподавателей публикуются между выкладками сайта, поэтому их карту
(`/sitemap-lessons.xml`) и разметку `/lessons/{slug}` отдаёт Go: он берёт
`index.html` из `CITAVUK_WEB_ROOT` и подставляет заголовок, описание,
канонический адрес и текст теории. Заготовка перечитывается по времени
изменения файла — иначе после выкладки сайта сервер отдавал бы ссылки на
удалённые бандлы. Несуществующий урок обязан отвечать 404, а не 200 с пустой
страницей: «мягкие 404» подрывают доверие поисковика к разделу.

Заголовок кеширования стоит в `location /`, а не только в блоке `\.html$`:
`try_files` отдаёт `$uri.html` внутренним переходом, не перезаходя в подбор
`location`.

## Читалка веба (`web/src/pages/Reader.tsx`)

Оформление задаётся `web/src/lib/readerSettings.ts` и повторяет
`ReaderSettings` приложения по именам полей: кегль, интерлиньяж, разрядка,
шрифт, отступ абзаца, красная строка, выключка, ширина колонки, цвет страницы,
уровень выделения основы слова и режим `flow = pages | scroll`.

Непрерывный web-режим строится через `react-virtuoso` с `useWindowScroll`:
логические страницы остаются единицами прогресса и обсуждений, но в DOM
находится только видимое окно. Не заменять его на `pages.map(...)` — книга на
тысячи страниц снова повесит вкладку. Длинные токены обязаны переноситься через
`overflow-wrap`, а контейнер страницы — иметь `min-width: 0` и не создавать
горизонтальную прокрутку на мобильном.

Карточка слова и панель перевода выделенной фразы из `WordReader` рендерятся
через React Portal непосредственно в `document.body`. Не возвращать их внутрь
`motion.article`: CSS `transform` страницы меняет containing block для
`position: fixed`, и координаты `getBoundingClientRect()` тогда дополнительно
смещаются относительно листа вместо viewport.

- **Хранятся в localStorage, не в IndexedDB и не на сервере.** Настройки нужны
  синхронно при первой отрисовке, иначе книга мигнёт чужим шрифтом. Между
  устройствами они намеренно не переносятся: комфортный кегль на телефоне и на
  мониторе разный.
- **Разбор прочитанного обязан быть устойчив** (`sanitize`): в хранилище может
  оказаться что угодно, а читалка обязана открыться.
- **Отступ абзаца — переменная `--reader-gap`, а не `marginBottom` в строчном
  стиле.** Строчный перебивает любое правило и оставляет лишний отступ под
  последним абзацем.
- **Звук перелистывания синтезируется** (`web/src/lib/pageTurn.ts`), файла нет:
  шелест — это отфильтрованный шум, и кодом он короче, чем килобайтами. Контекст
  создаётся при первом воспроизведении: до действия пользователя браузер держит
  `AudioContext` в `suspended`.

## Папки библиотеки (`web/src/lib/folders.ts`)

Папка — это поле `folder` у книги, а не отдельная сущность. Поле с первого
выпуска ходит в протоколе синхронизации (`books.folder` в `0001_init.sql`),
поэтому раскладка едет между устройствами без новой таблицы и версии протокола.
Плата: пустую папку хранить не в чем, она живёт в localStorage этого браузера
до первой книги — и раздел говорит об этом прямо.

## Словарь и карточки (`web/src/pages/Cards.tsx`, `web/src/lib/srs.ts`)

Раздел `/cards` отвечает на вопрос «куда девается сохранённое слово». Расчёт
срока — копия `UserDb.gradeCard` из приложения, и **совпадать он обязан**:
карточки синхронизируются, и слово, оценённое на телефоне и в браузере, должно
получить один и тот же следующий срок.

### Метки словаря (`web/src/lib/vocabTags.ts`, `frontend/lib/services/vocab_tags.dart`)

К сотне записей список по книгам перестаёт быть словарём. Из читалки сюда
уходит и выделенная фраза целиком, поэтому запись прежде всего делится на
**слово и фразу** — вперемешку они мешают и читать, и повторять. Остальные метки
складываются в ряд фильтра: часть речи, письмо, ход запоминания, тема.

- **Метка не хранится, а считается.** Хранимая разошлась бы с состоянием
  повторения на следующий же день, а старым записям потребовалась бы миграция
  ради подсказки. Расчёт общий для сайта и приложения и обязан совпадать: словарь
  синхронизируется.
- **Тема — единственное, что не выводится из самой записи.** Берётся из
  Путешествия: там уже почти тысяча слов разложена человеком по 66 видам мест.
  `tools/build_word_index.py` сводит их в одиннадцать тем и генерирует указатель
  для обеих платформ. Слово, попавшее больше чем в две темы (`рачун`, `молим`),
  темы не характеризует и остаётся без метки — иначе «еда» набралась бы из счетов
  и приветствий.
- **Ключ указателя — латиница.** Сохранить слово можно из книги на любом из двух
  писем, и «хлеб» с «hleb» обязаны попасть в одну тему. По той же причине поиск
  сравнивает в латинице: `kuća` находится запросом `кућа`.
- **Числа у меток считаются после поиска и вида, а не по всему словарю.** Метка с
  числом, не совпадающим с длиной списка после нажатия на неё, — обман.
- **Метки складываются, а не пересекаются.** «Глагол» и «еда» вместе означают
  «покажи и то, и другое»: пересечение разных разрядов почти всегда пусто, и
  человек решил бы, что фильтр сломан.
- **Показываются только встретившиеся метки.** Пустая метка обещает раздел,
  которого нет.
- Список группируется **по названию книги, а не по её id**: книгу можно удалить,
  а слова остаются, и при группировке по id каждая исчезнувшая книга давала
  отдельный раздел «Без книги».

### Пример из книги (`web/src/lib/vocabContext.ts`, `frontend/lib/services/vocab_context.dart`)

Карточка без предложения, из которого слово взято, через месяц не значит уже
ничего: «kraj» — и «конец», и «край». На сайте поле контекста заполняется не у
всех записей (у старых оно пустое), в приложении его нет вовсе. Книга при этом
лежит рядом.

- **Найденное не записывается в карточку.** Иначе ради подсказки, которую всегда
  можно собрать заново, понадобились бы миграция и отправка на сервер.
- **Слово ищется целым словом**, а не вхождением подстроки: «rad» иначе
  находился бы в «radost» и «gradu», и пример вставал бы к чужому слову — это
  хуже, чем никакого примера. Сравнение в латинице: «кућу» находится по «kuća».
- **Длинное предложение (свыше 220 знаков) пропускается**, и поиск идёт дальше:
  обрывать его на полуслове значит спрятать как раз то место, ради которого
  искали, а слово в книге встречается не по одному разу.
- **Много слов — один проход по книге** (`findSentences`). Поштучный поиск на
  каждое слово словаря — сотни проходов по всему тексту. В приложении примеры
  ищутся книга за книгой уже ПОСЛЕ показа списка: в памяти не задерживается ни
  одна книга целиком, а от неё остаётся по одному предложению на слово.

### Повторение фразы (`web/src/lib/phraseBuilder.ts`, `frontend/lib/services/phrase_builder.dart`)

Спрашивать у фразы перевод — упражнение совсем другого веса: это «переведи
предложение», а не «вспомни слово». Письмом фразы не повторяются намеренно
(см. `lib/writing.ts`). Поэтому у фразы показывается перевод, а сербскую фразу
надо выложить из перемешанных слов: порядок слов в ней и есть трудное место.

- **Перемешивание проверяется на результат.** Легла фраза в исходном порядке —
  перемешать заново (до восьми заходов): упражнение выродилось бы в «нажми всё
  подряд». Из фразы в одно-два слова перемешать нечего, она отдаётся как есть.
- **Регистр и знаки на концах слов прощаются**: упражнение про порядок слов, а
  не про заглавную букву в начале.
- **Пробел не открывает ответ у фразы.** Случайное нажатие сорвало бы сборку,
  которую человек ещё не закончил; на карточке слова пробел работает как прежде.
- Выложено последнее слово — **ответ дан сразу**, отдельного «проверить» нет.

### Выгрузка словаря (`web/src/lib/vocabExport.ts`, `web/src/components/VocabPrintSheet.tsx`)

Часть людей учит в Anki, часть — по бумажным карточкам. Таблица уходит в CSV,
бумага печатается средствами браузера: «Сохранить как PDF» есть в диалоге печати
на всех трёх системах, а своя генерация PDF стоила бы полутора мегабайт
библиотеки ради встроенного.

- **Выгружается видимое.** Отфильтровав словарь до «#еда», человек ждёт карточки
  по еде, а не весь словарь.
- **На бумагу идут только слова** (`printableRows`). Дело не в том, что фраза не
  влезает в 63×69 мм: карточку берут, чтобы вспомнить слово по одной стороне, а
  предложение не вспоминают — его читают, и лицевая сторона выдаёт ответ раньше,
  чем её успевают перевернуть. Фразам своё упражнение — сборка из слов; в CSV они
  уходят целиком. Сколько фраз пропущено, написано над листом: молча выкинуть
  половину выборки нельзя. Кнопки печати на одних фразах нет вовсе.
- **Оборот зеркалится по строкам.** Печать переворачивает лист по длинному краю,
  и левый столбец лица оказывается напротив ПРАВОГО столбца оборота. Без зеркала
  перевод печатается не на своём слове, и понять это можно, только разрезав
  лист, — то есть слишком поздно.
- **Неполный лист добивается пустыми местами**: сетка обязана остаться той же,
  иначе последний лист разрежется по другим линиям.
- **Всё, что рисует линии и ромб, сделано рамками, а не заливками.** «Фоновая
  графика» в диалоге печати выключена по умолчанию, и `background` на бумагу
  просто не попадёт; `border` печатается всегда.
- **Рамка карточки — пунктир по всем сторонам.** Соседние карточки делят одну
  линию реза, и сплошная рамка удвоила бы её толщину на каждом стыке.

## Всплывающие слои веба (`web/src/lib/overlay.ts`)

- **Замок прокрутки — счётчик, а не флаг** (`useScrollLock`). Каждый слой
  запоминал прежнее значение `body.style.overflow` сам, и два слоя внахлёст
  ломали друг друга: закрывался верхний и отпускал прокрутку под всё ещё
  открытым нижним, а обратный порядок оставлял страницу заблокированной до
  перезагрузки.
- **Фокус удерживается внутри слоя** (`useFocusTrap`) и возвращается на
  открывшую кнопку. Без этого Tab уводил из шторки в ссылки ПОД ней: человек с
  клавиатуры оказывался в контенте, которого не видит. Шторки помечены
  `role="dialog"` + `aria-modal` — иначе скринридер продолжает читать страницу
  под слоем.
- **Панель «Ещё» открывается кликом, а не наведением.** У `onMouseEnter` нет
  клавиатурного соответствия, и до трёх колонок ссылок нельзя было добраться
  табом вовсе. Вдобавок `onMouseLeave` закрывал панель, когда курсор шёл к
  дальней колонке по диагонали и на миг выходил за границу.

- **Слои разбора выше всех шторок**: панель «перевести выделенное» — `z-[85]`,
  карточка слова — `z-[90]`. Разбор вызывается ИЗ шторки (Вукоток, урок), и на
  прежнем `z-40` панель уходила под ту самую шторку, в которой её и вызвали.
  Новым слоям приложения выше `z-[80]` подниматься нельзя.
- **Подложка шторки закрывается только своим нажатием.** Выделение фразы,
  доведённое пальцем до края шторки, отпускалось уже на подложке — `click`
  всплывал до общего предка, и шторка захлопывалась вместо показа перевода.
  Признак пишется в `onPointerDown` (`event.target === event.currentTarget`).

## Карточка слова — одна на весь сайт (`WordReader.tsx`)

Разбор и перевод грузит `useWordLookup`, показывает `WordCard`. Вне читалки для
этого есть `WordLookupCard`: он нужен там, где текст выводится своей вёрсткой —
в караоке подкаста строка подсвечивается по ходу звука, и заменить её на
`WordReader` целиком нельзя.

Своей карточки заводить нельзя. У подкаста такая была: без разбора формы, без
таблиц склонения, без произношения и без выбора, что сохранить в словарь. Одно и
то же действие давало разный результат в зависимости от раздела, и это выглядит
поломкой, а не задумкой.

Заголовки Вукотока (карточка и шторка) — тоже `WordReader` внутри
`div role="heading"`, а не `h2`: внутри `WordReader` абзацы, а абзац внутри
заголовка — невалидная разметка.

## Читавук в вебе гладится (`Mascot.tsx`)

Нажатие на маскота меняет позу и показывает ответ — как `wolf_mascot.dart` в
приложении с самого начала. Это единственное место, где продукт про грамматику
позволяет себе просто порадовать, и терять его на вебе незачем. Слухао — орёл, и
поглаживание к нему не относится: позу «zdravo» он бы всё равно не показал.

## Высота шапки — переменная, а не число (`--header-height`)

Шапка ужимается при прокрутке (64 → 56) и может нести полосу поддержки, которая
на телефоне занимает две-три строки. Полоса прогресса книги была прибита к
`top-16` и почти никогда с шапкой не совпадала: висела в воздухе или оказывалась
посреди неё. Со стороны это читалось как отрыв красной черты и подтормаживание
шапки — она свою высоту анимирует, а прибитая полоса за ней не поспевала.
`Header` ставит настоящую высоту в `--header-height` через ResizeObserver; всё,
что обязано стоять вплотную под шапкой, держится за неё.

## Поисковая выдача: пререндер, карта сайта, IndexNow

- **Список разделов в `scripts/build-sitemap.py` — источник правды и для карты
  сайта, И ДЛЯ ПРЕРЕНДЕРА.** Раздел, забытый там, своего HTML не получает, и
  nginx отдаёт на его адресе `index.html` — побайтовую копию главной с её
  заголовком. Для робота без JS это дубль. Так было с `/lessons`, `/about`,
  `/privacy` и `/vukotok`: четыре копии одной страницы.
- **Переименованный адрес отдаёт 301, а не второй рабочий адрес.** `/micro-feed`
  → `/vukotok` в `deploy/nginx-site.conf`. Два адреса с одинаковым содержимым
  делят вес страницы, а `canonical` здесь не спасает: прежний адрес не
  пререндерится и без JS отдаёт копию главной. Редирект решает вопрос до всякого
  JS и сохраняет чужие ссылки.
- **`useSeo({ canonical })`** нужен там, где у страницы всё же два адреса.
- **Показы автоматических браузеров в ленту не идут** (`navigator.webdriver` в
  `api/microFeed.ts`). Пререндер прогоняет Вукоток на каждой сборке, и без этой
  проверки каждая выкатка подмешивала бы в рекомендации «дочитывания» робота.
- **IndexNow** (`scripts/indexnow.mjs`, шаг в `deploy/deploy.sh`) зовёт роботов
  сразу после выкатки, вместо ожидания от суток до недель. **Google протокол не
  поддерживает** — он тестировал его с 2021 года и не внедрил; участники —
  Яндекс, Bing, Naver, Seznam. Ключ лежит файлом в `public/` и секретом не
  является: он публичный по устройству протокола, чужой сайт им не подтвердить.
  Оповещение идёт ПОСЛЕ проверок выкатки — звать робота на страницу, которая
  может не открыться, значит получить в индексе ошибку вместо страницы.
