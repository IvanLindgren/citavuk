# Выкатка

Скрипты, грабли общей машины и сборка настольных версий.
Доступы и порядок релиза — `docs/release.md`.

## Скрипты и грабли общей машины

Для vhost сайта включены HTTP/2 (`http2 on`, nginx >= 1.25.1) и
`ssl_buffer_size 4k`. Изменяя рабочий vhost, сохранять блок TLS Certbot,
проверять `nginx -t` и держать копию для отката. `deploy.sh --publish-built`
публикует уже проверенный `dist` без повторной сборки; использовать только
после успешных проверок текущих исходников и production build.

VPS `85.137.89.21` — **общая машина**: там же ISPmanager, чужие сайты, почта
(exim4/dovecot), DNS (BIND) и mysql. Скрипты трогают только `/opt/citavuk`,
`/var/www/citavuk`, `/var/www/citavuk-files` и свои файлы в `conf.d`.

- `server/deploy/deploy.sh [--nginx]` — Go-сервер.
- `web/deploy/deploy.sh [--nginx]` — сайт.
- `web/deploy/publish-apps.sh` — APK, установщик Windows, портативный zip, архив
  Linux и `latest.json` (манифест автообновления настольных сборок; текст «что
  нового» берётся из `frontend/deploy/release-notes.txt`).

## CI и выкатка сайта

`.github/workflows/ci.yml` — обязательный CI для web и Go-сервера. На push в
`main` и pull request по затронутым каталогам он запускает два параллельных
job:

- web: `npm ci`, typecheck, весь Vitest и production build с пререндером;
- server: `go vet ./...` и `go test ./...`.

Повторный push в ту же ветку отменяет устаревший прогон через `concurrency`.
Этот workflow **ничего не выкладывает**: production-деплой пока остаётся
осознанным локальным запуском `web/deploy/deploy.sh`. По указанию владельца
с 01.10.2026 сайт и Go API не ждут GitHub CI: обязательны локальные проверки
своей зоны и сборка, затем прямой деплой. Приложения сохраняют CI-gate.

Сайт передаётся на VPS **одним `tar.gz`**, а не рекурсивным `scp` сотен файлов.
Сервер распаковывает архив в `/var/www/citavuk.new`, переносит туда ещё нужные
старые hashed chunks (не старше 14 дней), затем атомарно меняет каталоги. Это
важно и для скорости, и для уже открытых вкладок: `index.html` никогда не должен
указывать на наполовину загруженный набор chunks.

После подмены скрипт проверяет главную, `/materials`, lazy-маршрут
`/trainer/translation-duel` и `/fonts/Lora-Regular.woff2`, включая ожидаемый
Content-Type, а затем отправляет IndexNow. Добавляя критичный runtime-ассет или
новый базовый маршрут, дополняй этот smoke-набор.

Четыре шрифта `Lora-{Regular,Bold}.woff2` и `NotoSans-{Regular,Bold}.woff2` в
`web/public/fonts/` намеренно отслеживаются Git. Локальная папка могла маскировать
их отсутствие, но чистый CI и production build сами эти файлы не создают. Не
возвращать общее игнорирование `web/public/fonts/`, иначе сайт тихо уйдёт на
системные fallback-шрифты после следующей чистой выкладки.

Грабли, на которые уже наступали:

1. **`types { … }` в nginx ЗАМЕНЯЕТ таблицу типов, а не дополняет её.** Правка
   MIME для `.mjs` на уровне `server` увела `index.html` в
   `application/octet-stream`, и браузеры начали скачивать сайт вместо показа.
   Точечно чинится только через `default_type` в отдельном `location`.
   Поэтому `deploy.sh` проверяет **Content-Type**, а не только код ответа: по
   кодам такое незаметно, там честные 200.
2. **Простой `scp` конфига nginx затирает TLS-блок certbot** — сайт остаётся
   без HTTPS. `--nginx` делает копию, кладёт шаблон, заново запускает
   `certbot --nginx`, проверяет `nginx -t` и при неудаче возвращает прежний
   файл. На общей машине битый конфиг кладёт заодно почту и чужие сайты.
3. **Сборки приложений лежат вне `/var/www/citavuk`.** Выкатка сайта подменяет
   этот каталог целиком; файлы внутри исчезали бы при каждом деплое.
4. **Заливка рвётся посередине: `message authentication code incorrect`.**
   Канал бьёт пакеты, и ssh закрывает сессию — примерно через две минуты
   передачи, на каком байте придётся. `scp` после такого начинает файл заново
   и упирается в то же место, сколько ни повторяй. Поэтому `publish-apps.sh`
   льёт через `sftp reput` (докачка с последнего долетевшего байта, до 12
   заходов); такой же режим используется для архива сайта и Go-бинарников.
   Сайт дополнительно сверяет SHA-256 архива перед распаковкой. Причину видно в `auth.log` на
   сервере, а не в выводе scp — там только «lost connection».
5. **«Не открывается citavuk.ru, ошибка сертификата» — почти всегда кеш DNS.**
   Апекс когда-то указывал на парковку reg.ru (`95.163.244.138`), TTL 86400, и
   старый ответ живёт в кеше провайдера сутки; на парковке сертификат чужой,
   отсюда и предупреждение. Прежде чем чинить TLS, сверь фактический адрес:
   `curl -sv https://citavuk.ru/` показывает, куда реально пошло соединение.
   Авторитетно проверять через `dig A citavuk.ru @ns1.reg.ru`.
6. **Публичные настройки бандла лежат в файлах, которых нет в репозитории.**
   Ключ карты — в `web/.env.local`, `GOOGLE_CLIENT_ID_WEB` — в корневом `.env`.
   Выкатка идёт из чистого клона, там их не бывает, а Vite на отсутствие
   переменной не ругается: подставляет пустую строку. Сайт выкатывается зелёным
   и без карты (18 августа) или без кнопки «Войти через Google» (24 августа).
   `deploy.sh` берёт обе из окружения или из этих файлов, без любой из них не
   собирает и после сборки проверяет, что они доехали до `dist/assets`.
   Появилась третья такая настройка — заводи её тем же способом.
7. **Правка `deploy.sh` редактором, который трогает концы строк.** В smoke-
   проверке стоял литеральный CR (`tr -d`), и правка через Python в режиме
   универсальных переводов строк превратила его в `\n`. Заголовки склеились в
   одну строку, Content-Type у всех страниц стал пустым, и выкатка падала уже
   после заливки. Теперь там `$'\r'`, который так не испортить.

## Изолированное распознавание речи на VPS

`backend/transcription_app.py` использует общий ASR-движок без CLASSLA.
Рабочий каталог `/opt/citavuk/audio`, отдельный venv с
`backend/requirements-transcription.txt`; нужен системный ffmpeg для длинных
контейнеров. Сервис `backend/deploy/citavuk-audio.service` слушает **только
127.0.0.1:8092**, не публиковать этот порт через nginx или firewall.

В каталог копируются `audio_transcription.py` и `transcription_app.py`,
зависимости ставятся в `.venv`, unit — в `/etc/systemd/system/`.
Общий ключ Polza и upstream secret читаются из существующего `/opt/citavuk/.env`.
Дополнительный Groq можно хранить в `/opt/citavuk/audio/provider.env`
(`GROQ_AUDIO_TRANSCRIPTION_KEY=...`, владелец citavuk, права 600).
Этот файл никогда не копируется в репозиторий или webroot.

После `systemctl daemon-reload` и запуска `citavuk-audio` локальный `/health`
должен показывать `configured=true`; проверить реальный сербский файл с
совпадающим `X-Citavuk-Proxy-Secret` и ответ `srp` с непустыми words.
Только затем установить `backend/deploy/audio-upstream.conf` как
`/etc/systemd/system/citavuk-api.service.d/audio.conf`, выполнить daemon-reload
и выкатить Go штатным скриптом. Откат маршрута — убрать этот drop-in и
перезапустить только citavuk-api. Не трогать соседние сервисы/порты общей машины.

Обновление Python-кода worker требует перезапуска только `citavuk-audio`.
Space обновляется отдельно файлами `backend/main.py` и
`backend/audio_transcription.py`; наличие секретов в панели HF само по себе
не доказывает, что работающий процесс читает их. Не просить пользователя
заново добавлять уже заполненные ключи без проверки фактического ответа.

## Сборка под Linux (`frontend/deploy/linux/`)

`./deploy/linux/build.sh` из каталога `frontend/` собирает приложение в
контейнере и кладёт `build/citavuk-linux-x64.tar.gz` — оттуда его забирает
`publish-apps.sh`.

- **Контейнер, а не машина разработчика.** Flutter собирает Linux только на
  Linux, а результат зависит от версии glibc того хозяина, где его собрали.
- **База — Ubuntu 22.04, а не последняя.** glibc 2.35: бинарник, собранный на
  24.04, на 22.04 не запустится вовсе («GLIBC_2.38 not found»), обратное
  направление работает. Плюс `desktop_webview_window` просит через pkg-config
  именно `webkit2gtk-4.0`, которого в 24.04 уже нет.
- **Список пакетов повторяет `linux/flutter/generated_plugins.cmake`**:
  gstreamer нужен `audioplayers_linux`, webkit2gtk — `desktop_webview_window`.
  Появился плагин — список надо дополнить, иначе сборка падает на конфигурации
  CMake.
- **Версия Flutter берётся из локальной установки.** Собирать релиз другой
  версией, чем та, которой прогнали тесты, — верный способ получить расхождение,
  которое найдётся только у пользователя.
- Установка на стороне пользователя — `install.sh` в архиве: всё уходит в
  `~/.local`, root не нужен.

## Сборка Android

- Android release использует AGP 8.11.1, Gradle 8.14.3 (этого требует Flutter
  3.47) и R8 (`minify` + `shrinkResources`). AGP 9 пока нельзя: он удалил
  `Project.exec`, которым ещё пользуется CargoKit (`super_clipboard`).
  `file_picker` получает legacy KGP точечно в `android/build.gradle.kts`.
- Плагин `super_clipboard` собирает Rust: локальная сборка Windows и Android и
  контейнер Linux ставят его тулчейн через CargoKit сами, первый прогон долгий.
