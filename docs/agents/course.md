# Курс, тренажёрка и упражнения

Движок заданий общий у курса, тренажёрки, уроков преподавателей и дуэли
переводов. Второго формата упражнений в проекте нет.

## Курс грамматики (`lib/course/`)

Раздел «Грамматика» на главной — игровой курс, а не список карточек. Старый
`GrammarCardsScreen` остался справочником и открывается из шапки курса.
`GrammarScreen` из читалки и `GrammarEngine` не затронуты.

### Слои

```
course_content/           исходный контент (JSON, редактируется руками)
tools/course_build/       Go: валидация + сборка bundle
tools/sprite_build/       Go: удаление фона, atlas, manifest
animations/source/        исходные PNG-кадры (НЕ входят в приложение)
animations/qa/            листы визуальной проверки спрайтов
frontend/lib/course/
  models/     Exercise (sealed), Course/Unit/Skill/Lesson, Answer, progress
  services/   answer_evaluator, serbian_text, mastery_engine, загрузчики
  state/      LessonController, CourseController
  widgets/    ExerciseHost + по виджету на тип упражнения, CitavukSprite
  screens/    CoursePathScreen, LessonScreen
```

### Правила, которые легко нарушить

- **Контент не парсится из книги в рантайме.** Книга → `course_content/*.json`
  руками → валидатор → `frontend/assets/course/course_bundle.json`. Правка
  bundle бессмысленна: он перезаписывается.
- **Исходный JSON пишется кратко.** `normalize.go` дописывает `id`, `unitId`,
  `skillId`, `lessonId`, `difficulty`, `serbianScript` и наследует `sourceRef`
  от unit к упражнению до валидации. Все прежние правила проверяются уже на
  полных объектах. Таблица умолчаний — в `course_content/SCHEMA.md`.
- **Цель обучения от skill подставляется только когда она там одна.** Иначе
  правило «каждая цель покрыта упражнением» закрылось бы само собой; при
  нескольких целях автор перечисляет их в `lesson.objectives`.
- **`č`/`ć` и `dž`/`đ` не нормализуются.** `normalizeAnswer` трогает только
  пробелы, регистр, терминальную пунктуацию и разложенные диакритики.
  Схлопывание этих букв обессмыслит упражнения.
- **Порядок слов проверяется по-настоящему.** `sentence_builder` не принимает
  произвольную перестановку тех же токенов — только подпоследовательность
  допустимого порядка с пропуском необязательных токенов.
- **Разбиение на буквы должно совпадать в Go и Dart.** `splitLetters` есть в
  `tools/course_build/validate.go` и `lib/course/services/serbian_text.dart`.
  Правишь одно — правь второе, иначе валидатор и клиент разойдутся.
- **Исходные PNG лежат вне `frontend/`.** Иначе 15 МБ кадров попадут в APK.
  В приложение входит только `assets/animations/generated/`.
- **Прогресс переживает обновление контента.** `CourseController._reconcile`
  отбрасывает записи об исчезнувших уроках, но не стирает остальное;
  незавершённая попытка снимается при смене `contentChecksum`.
- **Игровые диалоги используют тот же документ прогресса.** Общие сценарии
  лежат в `frontend/assets/course/dialogues/`; React копирует их через
  `prepare-course-assets.mjs`. Поле `dialogues` хранит текущий узел, историю
  выборов, статус и `updatedAt`. При слиянии клиентов побеждает более новая
  запись конкретного диалога. На React диалоги живут в отдельном разделе
  `/dialogues`, первый сценарий открывается по `/dialogues/drinkit`; старый
  `/course/dialogue/drinkit` оставлен только для совместимости ссылок. В курсе
  должна оставаться компактная кнопка на раздел, а не сам каталог диалогов.
  Реплики рендерятся через `WordReader`, поэтому перевод и сохранение слов не
  должны дублировать механизм читалки. Озвучка идёт через `/audio/tts`.
  Первый сценарий доступен гостю локально, а после входа синхронизируется через обычный
  `/v1/course/progress/{courseId}`.

### Типы упражнений

`multiple_choice`, `matching`, `fill_blank`, `sentence_builder`,
`ending_picker`, `letter_unscramble`, `image_description`, плюс два для работы
с текстом:

- **`reading_qa`** — связный текст и вопросы к нему. Текст остаётся на экране,
  пока идут ответы: проверяется понимание прочитанного, а не память. Ответ
  засчитывается целиком.
- **`form_hunt`** — найти в тексте все формы заданного признака. Текст хранится
  списком токенов, а не строкой: делить сербский текст на слова пришлось бы
  одинаково в Go, Dart и TypeScript, и любое расхождение разошлось бы с
  проверкой ответа.

Добавление типа затрагивает четыре места: `tools/course_build/{model,validate}.go`,
`lib/course/models/exercise.dart` + виджет + `answer_evaluator.dart` +
`exercise_host.dart`, `web/src/course/{types.ts,data.ts}` и `ExerciseView` в
`web/src/pages/CourseLesson.tsx`.

### Тренажёрка

Практика по темам вне порядка курса: `lib/course/screens/trainer_screen.dart`
и `web/src/pages/Trainer.tsx` (маршрут `/trainer`, ссылка в шапке и подвале).
Во Flutter вход тоже в шапке курса (иконка гантели), а не только карточкой
внизу карты: сюда приходят в произвольный момент, и заставлять пролистывать
весь курс ради этого незачем.
Каталог `assets/course/trainer_catalog.json` / `public/course/trainer_catalog.json`
собирается `tools/build_trainer_catalog.py` из тех же 75 тем, что и дорожная
карта. Режимы: `Gramatika`, `Čitanje`, `Pisanje`; внутри темы разложены по CEFR.
К A1-B2 добавлена минимум одна проверка понятия, C1-C2 пока не получают
искусственных упражнений. Существующие задания курса подключаются по `skillId`.

Прогресс уроков Тренажёрка **не пишет**: иначе «пройденный» урок означал бы то
разобранную теорию, то удачную серию ответов. Зато грамматический заход на 100%
ставит галочку одноимённому `roadmap_item` с `source=trainer`. Экран прохождения
переиспользуется (`LessonScreen`, `ExerciseView`), своя копия разошлась бы с
курсом на первой же правке.

### Профиль и достижения

`GET /v1/profile/stats` — общий контракт web и Flutter: количество добавленных,
выученных и просроченных слов, 14 дней активности, серия, прогресс к
`roadmap_target_level` и достижения. Слово считается выученным при `reps >= 3`
и `interval_days >= 7`. Миграция `0028_profile_achievements.sql` добавляет
`vocabulary.created_at` и идемпотентные `user_achievements`.

Новые достижения проверяются после sync, после отметки карты и при открытии
профиля. Каждое создаёт обычную запись `user_notifications` с детерминированным
UUID, поэтому параллельные устройства не присылают дубль. Клиенты после
идеального прохождения обновляют общий центр уведомлений.

### Команды

```
cd tools/course_build && go run .                    # валидация + сверка с лексиконом
cd tools/course_build && go run . -out frontend/assets/course/course_bundle.json
cd tools/course_build && go test ./...               # тесты ридера SQLite и сверки
cd tools/sprite_build  && go run .                   # пересборка спрайтов + QA
cd tools/sprite_build  && go run . -check            # atlas устарел?
cd tools/sound_build   && go run .                   # пересборка звуков
cd frontend && flutter test                          # 162 теста
```

Валидатор читает `lexicon.db` собственным минимальным ридером формата SQLite
(`tools/course_build/sqlite_reader.go`) — без CGO и внешних зависимостей.
Конфликт формы с лексиконом даёт предупреждение, отсутствие формы — нет:
словарь покрывает лишь часть языка.

Сборка bundle всегда идёт в strict-режиме: повреждённый контент в production
не попадёт. Модули Go лежат в своих каталогах и сами находят корень репозитория,
поэтому запускать можно откуда угодно.

### Что ещё не сделано

- Регистрация и PostgreSQL реализованы в `server/`; прогресс курса
  синхронизируется через `GET/PUT /v1/course/progress/{courseId}`. Локальная
  копия остаётся обязательной для офлайн-запуска.
- Итоговая контрольная — `blueprint` пуст. Заглушки на карте курса больше нет:
  обещание, которое видно каждый раз и не наступает, стояло ровно там, где
  должно быть чувство завершения. Появится контент — вернём карточку.
- `image_description`: режимы `choose` и `free` реализованы, `build`/`fill`
  требуют расширения схемы (у них нет полей tokens/blanks).
- Курс переписан целиком под программу из 7 частей: 8 units, 48 уроков,
  299 упражнений. Прежние `u_imenice_rod` и `u_padezi` удалены, их темы
  разошлись по `u_imenice`. См. таблицу в `course_content/SCHEMA.md`.

## Упражнения — тот же движок, что у уроков

Формат `LessonExercise` общий: второй формат означал бы второй редактор и по
второму проигрывателю на каждой платформе. Во Flutter проигрыватель вынесен из
экрана урока в `widgets/exercise_player.dart` (`ExerciseView` +
`ExerciseAnswers`); ответы живут **вне** виджета, потому что задания
показываются по одному и переход к следующему иначе стирал бы написанное.
Разбор слова по нажатию — `widgets/clickable_serbian_text.dart`, тоже общий.

Набор засчитывается **долей верных ответов**, а не фактом открытия: иначе
«пройдено» означало бы «развернул и закрыл». Исход первой проверки уходит
наверх через `ExerciseResultContext` (веб) и `onChecked` (Flutter); повторные
нажатия молчат, иначе долю можно набить, тыкая по показанному ответу.

Добавлены два вида: `word_drill` (перевод → слово по памяти, не выбор из
вариантов: узнать и вспомнить — разные умения) и `translator_duel`. Машинный
перевод у дуэли **хранится в задании**, а не запрашивается на лету: иначе «вы
совпали с переводчиком» значило бы разное в разные дни. Список допустимых видов
дублируется в `api/teacher_lesson_handlers.go` — разойдись он с клиентом,
преподаватель не смог бы собрать задание, которое карта уже показывает.

`translator_duel` — не та игра, что живёт на `/trainer/translation-duel` (§5d):
там матч из трёх раундов против DeepL, здесь одна фраза внутри урока. Вид у него
намеренно спокойный: в уроке подряд идёт десяток заданий, и таймер с тряской на
одном из них сбивал бы с чтения.

**Пунктуация в ответе не проверяется нигде.** Знаки `. , ! ? ; : …`, кавычки и
тире между словами снимаются перед сравнением; дефис и апостроф внутри слова
остаются. Правило одно на четыре проверки — уроки и курс, веб и приложение:

| | |
| --- | --- |
| Веб | `web/src/lib/answerMatch.ts` → `LessonPlayer.tsx`, `course/data.ts` |
| Приложение | `frontend/lib/course/services/serbian_text.dart` → `exercise_player.dart` |

Раньше срезалась только точка в конце, и пропущенная запятая внутри фразы
отменяла верный перевод. Так делать нельзя: упражнения проверяют слова, формы и
порядок слов, а расстановка запятых — отдельное умение, которому Читавук не
учит; в переводе запятая к тому же часто ставится по выбору пишущего, а эталон
в задании один. Судье Gemma в игре про переводчика это сказано прямым текстом в
`internal/translationgame/judge.go`.

Две ловушки в самом правиле, обе закрыты тестами:

- Знак заменяется **пробелом**, а не удаляется. Иначе «да,нет» без пробела
  склеивается в «данет», и строгость к запятой сменяется строгостью к пробелу.
- `keepTerminalPunctuation` во Flutter — задел на упражнение, где знаки как раз
  и проверяются: с ним пунктуация сохраняется целиком. Сейчас его никто не
  включает.

## Игра «Ты против переводчика»

- Web: `/trainer/translation-duel`; Flutter:
  `course/screens/translation_duel_screen.dart`. Вход находится в Тренажёрке.
- Матч — три раунда по пять серверных фраз выбранного уровня A1–C2. Ручка
  `/v1/translation-game/round` переводит их выбранным `deepl|google`; ключи и
  заранее сделанный перевод в клиент не попадают.
- **Два направления: `sr-ru` и `ru-sr`** (`direction`, пока только веб). Пустое
  поле означает сербский→русский — приложение второго направления не знает и
  ничего не шлёт. Русские фразы написаны заново, а не переведены с сербских:
  возьми мы те же предложения, машине досталась бы задача вернуть текст, из
  которого он и сделан, а игрок получил бы второй раз тот же материал; тест
  `TestBanksDoNotShareSentences` это стережёт. Промпт судьи тоже зависит от
  направления — судья, которому сказали «переводим на русский», оценивал
  сербские ответы как ломаный русский и отдавал раунд машине.
- Победителя каждой пары выбирает пользователь или `/v1/translation-game/judge`.
  Весь раунд уходит одним запросом. Судья по умолчанию —
  `google/gemma-4-31b-it` через Polza AI; env начинаются с
  `CITAVUK_TRANSLATION_GAME_AI_`, AI-ручка защищена quiz limiter.

### Комнаты и подбор соперников

- `/trainer/translation-duel/:code` — комната на 2–6 мест. В неё входят по
  ссылке без аккаунта: гостю сервер выдаёт подписанный `X-Duel-Player`, браузер
  хранит его вместе с именем. DeepL и Google Translate — обычные места за
  столом, их добавляет хозяин.
- `server/internal/duel/` — чистый автомат комнаты и подбора без HTTP и БД.
  Время всегда передаётся аргументом, поэтому таймауты, уход игрока,
  голосование и три раунда проверяются детерминированными тестами.
- `duel_rooms` хранит JSON состояния с optimistic version; подбор берёт
  PostgreSQL advisory lock, поэтому два опроса не могут посадить одного игрока
  в две комнаты. Клиент опрашивает комнату обычным GET: вебсокетов в проекте
  нет и nginx для игры менять не нужно.
- Очередь живёт в `DuelSearchProvider` выше роутера. Через 45 секунд экран
  предлагает пока сыграть с DeepL, но поиск продолжается. Когда стол собран,
  в браузере появляется вызов поверх любой страницы, а вошедшему дополнительно
  создаётся `user_notification` со ссылкой на комнату.
- До конца раунда сервер отдаёт участнику только собственные ответы. Если
  Gemma недоступна, переводы открываются без авторов и игроки голосуют; нельзя
  голосовать за себя. Имена появляются только в разборе. Наружу уходит ещё
  `progress` (сколько фраз сосед перевёл) и `voted` — числа, а не тексты: на
  них держится азарт стола.
- Черновик уходит сам раз в пару секунд (`POST /v1/duel/rooms/{code}/answers`,
  ядро — `Room.AnswerMany`). Раньше переводы отправлялись только по кнопке
  «Сдать», и не успевший нажать терял весь раунд. Фразы не из текущего раунда
  ручка молча пропускает: черновик мог уйти в момент смены раунда.
- Опрос, который ничего не сдвинул, остаётся чтением: `Tick` метит `UpdatedAt`
  только при настоящем изменении, `Touch` запоминает присутствие раз в
  `SeenStep`, а `duelChange` сверяет метку и не пишет комнату зря. Иначе шесть
  игроков переписывали бы одну строку по три раза в секунду и сталкивались
  версиями на ровном месте.
- И судья, и переводчики за машинными местами вызываются **после** записи
  комнаты, из горутины: `ClaimJudge` и `ClaimMachines` отдают право одному
  запросу, остальные его не дублируют. До этого DeepL переводил прямо в
  запросе — раунд открывался на полминуты позже собственных часов, а при
  столкновении версий перевод покупался заново.
- Миграция: `server/internal/store/migrations/0040_duel_rooms.sql`. Сервер
  выкатывается раньше сайта, иначе новый клиент увидит 404 на `/v1/duel/*`.

### Матч, а не форма

Игра была списком из пяти полей ввода. Стало: фразы идут по одной под часы, а
разбор пяти переводов открывается по одному, с паузой. Причина не в
украшательстве — это единственное место в Читавуке, где человек не выполняет
упражнение, а соревнуется; и пять сравнений, показанных разом, читатель не
читает, а пролистывает.

| Что | Где |
| --- | --- |
| Правила счёта | `web/src/lib/duelScore.ts`, `frontend/lib/course/duel_score.dart` |
| Спрайт и счётная полоса | `web/src/components/DuelArena.tsx`, `frontend/lib/course/widgets/duel_arena.dart` |
| Ход матча | `web/src/pages/TranslationDuel.tsx`, `frontend/lib/course/screens/translation_duel_screen.dart` |
| Комната на несколько человек | `web/src/components/MultiplayerDuel.tsx`, `frontend/lib/course/screens/duel_room_screen.dart` |
| С кем играть: подбор, код, машина | `frontend/lib/course/screens/duel_menu_screen.dart` |
| Часы, стол, занавес, пьедестал | `web/src/components/DuelStage.tsx`, `frontend/lib/course/widgets/{duel_stage,duel_table}.dart` |
| Клиент комнаты | `web/src/api/duel.ts`, `frontend/lib/course/services/duel_room_service.dart` |
| Кто сейчас играет (админка) | `web/src/components/AdminOpsPanels.tsx`, `server/internal/store/admin_live.go` |
| Звук | `web/src/lib/duelSounds.ts`, `frontend/lib/services/duel_sounds.dart` |
| Сборка звука | `tools/build_duel_sounds.py` → `web/public/sounds/duel/`, `frontend/assets/sounds/duel/` |
| Сборка спрайтов | `tools/build_duel_sprites.py` → `web/public/img/citavuk_duel_sprites.webp` |

**Оформления у страницы своего нет** — и это главное правило. Панели, шрифты и
цвета те же, что у читалки и урока: сторона человека берёт `--accent`, сторона
машины — `--machine` (индиго палитры; во Flutter `duelMachineOf`). Первая версия
была тёмной ареной с неоном, искрами, тряской экрана и CRT-разводами: она
выглядела как чужая игра, вставленная в Читавук, и была выброшена целиком.
Азарт держат темп, часы и звук, а не подсветка. Если снова захочется «сделать
поживее» — добавлять надо в темп и звук, а не цвета.

**Обстановка у обоих режимов общая.** Часы-кольцо, занавес фазы, тасуемая
колода судьи и пьедестал с конфетти лежат в `DuelStage.tsx` и берутся как игрой
с DeepL (`pages/TranslationDuel.tsx`), так и столом на несколько человек. Первый
заход сделал всё это только за столом — и человек, зашедший играть с машиной,
изменений не увидел вовсе: он до стола просто не доходил. Поэтому компоненты
принимают простые числа (`DuelClock` — `seconds` и `total`, `Podium` — список
мест), а не комнату целиком.

**Полосы — это счёт, и ничего кроме.** Выигранная фраза снимает с соперника
фиксированные двадцать, проигранная столько же с вас, ничья задевает обоих
поровну; пять фраз по двадцать — ровно сто. Цифрами показываются выигранные
предложения (`3 : 1`), а не внутренние очки полос. Темп от быстрого набора идёт
в отдельную величину — «стиль», из неё берётся ранг S/A/B/C и признак
критического звука.

Так сделано не сразу. Сначала темп усиливал урон — и тест поймал, что при
быстром наборе две выигранные фразы из пяти отдавали раунд человеку, который
его проиграл. Зрелище начало спорить со счётом. Оба теста (`duelScore.test.ts`,
`duel_score_test.dart`) перебирают все 243 расклада раунда при трёх уровнях
темпа и требуют совпадения итога по полосам с итогом по числу побед; трогая эти
константы, смотрите на них.

По той же причине часы не снимают счёт. Когда время фразы вышло, сгорает две
трети темпа — давление есть, счёт цел.

**Спрайты.** Двадцать поз Читавука лежат одним листом 5×4
(`frontend/assets/imgs/citavuk_sprites_gamevsperevodchik.png`, 2 МБ). Для веба
`tools/build_duel_sprites.py` режет его по сетке и обрезает **общей** рамкой
содержимого, а не по каждой клетке отдельно: обрезанная вплотную и растянутая
поза меняла бы рост персонажа при каждой смене. Порядок поз в `POSE` /
`DuelPose` задан листом — во Flutter это прямо порядковый номер значения enum,
поэтому переставлять значения нельзя.

**Звук** синтезирован (как `tools/sound_build`, `tools/make_page_turn.py`), не
взят из чужих паков: понятная лицензия, предсказуемая громкость, весь набор —
196 КБ. Частота 22 050 Гц: на ударах и кликах верхняя половина спектра пустая.
Клик клавиши — восемь файлов, по одному на ступень серии; `playbackRate` на
коротких звуках заикается. Грузится набор не при загрузке сайта, а по наведению
на кнопку начала матча.

**Доступность.** `useReducedMotion` / `MediaQuery.disableAnimationsOf` снимают
проявления и переходы. Звук выключается кнопкой в шапке (`citavuk-duel-muted`).

Ловушки этого экрана:

- Побочные эффекты внутри функции обновления состояния. `setTimeLeft((left) => {
  … playDuel('alarm') … })` React вправе вызвать дважды — сирена звучала парой.
  Звук и перехват вынесены в отдельный эффект по `timeLeft`.
- Каталоги ассетов Flutter не рекурсивны: `assets/sounds/` не включает
  `assets/sounds/duel/`, для него нужна своя строка в `pubspec.yaml`.
- `pumpAndSettle` в тесте экрана виснет: с началом раунда работает
  `Timer.periodic` на 100 мс. Нужны явные `pump(Duration(...))`.
- У `Enum` в Dart уже есть `index` — своё поле с этим именем не заводится
  (`illegal_concrete_enum_member`). Место в атласе и есть порядковый номер.
- Атлас — производный файл, `public/img/*` в репозитории не хранится. Поэтому
  `web/scripts/prepare-assets.py` дёргает `tools/build_duel_sprites.py` сам:
  иначе после пересборки ассетов Читавук пропадал бы со страницы, и увидеть это
  можно было бы только на живом сайте. Звуки, наоборот, лежат в репозитории —
  как и `page_turn.wav` до них.
