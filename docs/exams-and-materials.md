# Как добавлять материалы и тесты на сайт

Инструкция для агента. Три разных вещи с тремя разными путями — не путай их,
иначе задание уедет в движок, который его не покажет.

| Что добавляешь | Куда | Кто правит |
| --- | --- | --- |
| Пособие, сборник, официальный PDF | `web/scripts/build-materials.py` | агент, правкой кода |
| Тест по такому документу | генерируется моделью, лежит в базе | никто руками |
| Задание курса, тренажёрки, экзамена | `course_content/*.json` или админка | агент или автор на сайте |

---

## 1. Материал: пособие или сборник

Каталог материалов — **указатель, а не хранилище**. Мы не держим чужие PDF у
себя: в записи только описание и ссылка на источник, а скачивание идёт по
явному нажатию через `GET /v1/documents/fetch`.

Добавление — одна запись в `SOURCES` в `web/scripts/build-materials.py`, потом:

```bash
cd web && python scripts/build-materials.py
```

Скрипт пишет **две копии сразу** — `web/src/materials/` и
`frontend/assets/materials/`. Не правь их руками: они перезаписываются.

Правила, которые скрипт проверит за тебя, но лучше знать заранее:

- **Каждая ссылка проверяется при сборке** — код ответа, сигнатура `%PDF-`,
  размер. Битая ссылка на учебник хуже отсутствующей: она тратит время ровно
  тогда, когда человек готовится к экзамену.
- **Предмет проверяется по содержимому файла, а не по названию факультета.**
  Открой PDF и посмотри первую строку.
- **Источник, отдающий HTML вместо PDF, не добавляем.** Проверка всё равно
  отбросит его файлы, а запросы останутся на каждой сборке.
- Адреса с пробелами в пути скрипт чинит сам (`normalize_url`).

## 2. Тест по материалу

Руками не пишется. Тест делает модель из текста документа: `POST /v1/quizzes`
(ручка под `quizLimit`, только вошедшим). Готовый тест открывается по
`/tests/:id`, попытки и повторение считает сервер.

Формат вопроса жёсткий и простой — `web/src/api/quizzes.ts`:

```ts
{ question, options: string[], answer: number, explanation, wrongHint }
```

Один вопрос — один верный вариант. **Ничего, кроме выбора из вариантов, этот
движок не умеет.** Нужен пропуск, сопоставление или разбор текста — это другой
движок, пункт 3.

Зато только здесь есть попытки, лучший результат, интервальное повторение и
статистика (`GET /v1/quizzes/stats`). Для «прорешать экзамен и увидеть балл»
подходит именно он.

## 3. Задание: курс, тренажёрка, экзамен

Движок заданий общий у курса, тренажёрки и уроков преподавателей. Девять типов,
`web/src/course/types.ts` и `frontend/lib/course/models/exercise.dart`:

| Тип | Что проверяет |
| --- | --- |
| `multiple_choice` | выбор одного или нескольких вариантов |
| `fill_blank` | пропуски в предложении, свободный ввод со списком принимаемых ответов |
| `ending_picker` | окончание слова в контексте |
| `matching` | сопоставление пар с лишними вариантами справа |
| `sentence_builder` | порядок слов; проверяется по-настоящему, а не как набор токенов |
| `letter_unscramble` | сборка слова из букв, диграфы можно держать единицей |
| `image_description` | описание картинки: выбор или свободный ответ |
| `reading_qa` | текст и вопросы к нему; текст остаётся на экране |
| `form_hunt` | найти в тексте все формы заданного признака |
| `listening_qa` | **только веб**: запись звучит, текста нет, вопросы как у чтения |

Куда класть:

- **Уроки курса** — `course_content/*.json` руками, затем
  `cd tools/course_build && go run .` (валидация) и с `-out` — сборка bundle.
  Правка `frontend/assets/course/course_bundle.json` бессмысленна: он
  перезаписывается.
- **Темы тренажёрки** — `tools/build_trainer_catalog.py`, те же 75 тем, что и у
  дорожной карты; существующие задания подключаются по `skillId`.
- **Пункты дорожной карты** — не в коде: `/admin` → вкладка «Дорожная карта»,
  по клетке за раз.

Правила, которые легко нарушить:

- **Добавление нового типа задания трогает четыре места:**
  `tools/course_build/{model,validate}.go`, `lib/course/models/exercise.dart` +
  виджет + `answer_evaluator.dart` + `exercise_host.dart`,
  `web/src/course/{types.ts,data.ts}` и `ExerciseView` в
  `web/src/pages/CourseLesson.tsx`. Плюс список видов в
  `api/teacher_lesson_handlers.go` — разойдись он с клиентом, урок не примут.
- **`č`/`ć` и `dž`/`đ` не нормализуются.** Схлопывание этих букв обессмыслит
  упражнение.
- **Разбиение на буквы обязано совпадать в Go и Dart** (`splitLetters`).
- **Набор засчитывается долей верных ответов**, а не фактом открытия.

## Экзамены: что уже готово и чего не хватает

Каркас раздела — `web/src/exams/catalog.ts`, страница — `web/src/pages/Exams.tsx`,
маршрут `/exams`. Уровни и разделы испытания лежат в коде: они не меняются от
правки к правке. Сроки, стоимость и проходной балл в каркас **не вписаны
намеренно** — они меняются каждый набор, и устаревшее число хуже отсутствующего.

Сопоставление разделов испытания с движками:

| Раздел | Чем собирается |
| --- | --- |
| Понимание прочитанного | `reading_qa` |
| Грамматика и лексика | `multiple_choice`, `fill_blank`, `ending_picker`, `matching`, `form_hunt` |
| Письменное изложение | частично: `sentence_builder` и свободный ввод |
| Понимание на слух | `listening_qa` — **только веб** |
| Устная речь | не делаем |

**Понимание на слух закрыто типом `listening_qa` — но только в вебе.**
Запись звучит через `/audio/tts`, текста на экране нет, число прослушиваний
ограничено (без предела это чтение с озвучкой, только медленнее), расшифровка
открывается лишь после проверки ответа.

Тип добавлен **не во все четыре места намеренно**: его нет ни в
`tools/course_build`, ни во Flutter, ни в списке видов
`api/teacher_lesson_handlers.go`. Это защита, а не недосмотр — валидатор курса
отвергает неизвестный тип (`validate.go`, «неизвестный exercise type»), поэтому
`listening_qa` физически не может попасть в `course_bundle.json` и сломать
телефон. Когда дойдут руки до Flutter, тип нужно провести по всем четырём
местам разом.

Устной речи не будет по той же причине, по которой её нет на дорожной карте:
через интернет она не развивается, и место под неё вводило бы в заблуждение.

Пока пробных тестов нет, страница честно говорит «Готовится» и отправляет в
дорожную карту, тренажёрку и материалы. Не заменяй эту формулировку на
«скоро»: обещание, неотличимое от готового раздела, обходится дороже пустоты.
