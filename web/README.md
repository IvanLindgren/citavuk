# Веб-версия Читавука

Сайт citavuk.ru: React + TypeScript + Vite. Работает с тем же сервером, что и
мобильное приложение (`server/`), — аккаунты, синхронизация и перевод общие.

## Почему не Flutter Web

Flutter собирает веб через CanvasKit: несколько мегабайт wasm до первой
отрисовки, текст рисуется на канве и потому плохо выделяется и хуже читается
экранными дикторами, а поисковые роботы видят пустую страницу. Для сайта, куда
человек попадает по ссылке и решает за первые секунды, оставаться ли, это
неподходящий инструмент.

Приложение остаётся на Flutter — там эти минусы не проявляются.

## Запуск

```powershell
cd C:\citavuk\web
npm install
python scripts/prepare-assets.py   # разово: готовит шрифты и картинки
npm run dev                        # http://localhost:5173
```

В режиме разработки запросы `/v1/*` проксируются на боевой сервер, поэтому
`npm run dev` работает сразу, ничего поднимать рядом не нужно. Если правите сам
сервер, поменяйте `target` в `vite.config.ts` на `http://127.0.0.1:8090` и
запустите его локально:

```powershell
cd C:\citavuk\server
go run ./cmd/citavukd -env ../.env
```

Проверки:

```powershell
npm run lint    # проверка типов
npm run test    # модульные тесты
npm run build   # production-сборка
```

## Ассеты

Картинки маскотов и шрифты лежат в приложении и рассчитаны на упаковку в APK,
где их размер не влияет на скорость первого показа. В вебе всё иначе, поэтому
`scripts/prepare-assets.py` переводит шрифты в WOFF2, а картинки — в WebP двух
плотностей. На текущем наборе это 12,1 МБ против 1,5 МБ.

Готовые файлы не хранятся в репозитории: они производные и пересобираются одной
командой.

## Устройство

```text
src/
├── api/          клиент сервера: запросы, аккаунт, перевод
├── components/   общие элементы: кнопки, орнамент, маскот, читалка слов
├── course/       модели, проверка ответов, спрайты и звуки курса
├── listening/    модели аудиоуроков и эвристика сложных на слух слов
├── lib/          роутер, токенизатор, IndexedDB, адрес текста книги
├── pages/        экраны
└── state/        контексты аккаунта, синхронизации и темы
```

### Роутер

Своя реализация на History API вместо библиотеки: маршрутов меньше десятка,
вложенных нет, а из возможностей нужны только переход, параметр в пути и текущий
адрес. Взамен — нулевой вес, полный контроль над анимацией переходов и одной
зависимостью меньше. Разбор путей покрыт тестами: ошибка там даёт пустой экран
вместо внятного сбоя.

### Перевод слова

Ядро продукта — `components/WordReader.tsx`. Нажатие на слово отправляет на
сервер **предложение целиком** с границами слова, а не одно слово. Причина
описана в `server/README.md`: DeepL хорош на связном тексте и разваливается на
отдельных словах — «kuća» в отрыве от фразы он переводит как «собака», а внутри
предложения верно, «дом».

Сервер помечает ответ признаком `aligned`. Если выравнивание не удалось,
интерфейс это показывает, а не выдаёт догадку за словарную статью.

Смещения слова передаются **в байтах UTF-8**. JavaScript индексирует строку в
единицах UTF-16, и для кириллицы это разные числа — пересчёт делает
`utf8ByteOffset`, на него есть тесты. Сервер дополнительно отказывается резать
строку посреди символа: уверенный неверный перевод хуже отказа.

### Тема

Выбор темы применяется скриптом в `index.html` **до** первой отрисовки. Если
делать это в React, между показом страницы и загрузкой бандла успевает мигнуть
светлый фон — на тёмной теме это заметно.

### Анимации

`framer-motion`, но каждая анимация спрашивает `useReducedMotion`, а в CSS
продублировано глобальное правило. Движение здесь — часть оформления, а для
части людей оно вызывает физический дискомфорт, поэтому системная настройка
обязана работать.

## Что уже есть и чего нет

Готово: главная с живым демо перевода, вход по почте и через Google,
библиотека с импортом TXT, Markdown, PDF и DOCX, читалка с постраничным чтением,
нативным выделением и переводом фраз, разбор слов, игровой курс грамматики с теорией,
упражнениями, статичным кадром маскота и звуками, аудирование с транскриптом,
скоростью `0.5x–2x` и подсветкой слов, экран аккаунта, тёмная тема и адаптивная
вёрстка.

Синхронизируются книги, словарь, расписание SRS и прогресс курса. Mammoth и
PDF.js подгружаются только после выбора документа. Если у PDF нет текстового
слоя, файл отправляется в `/documents/extract`: Python рендерит только
страницы-сканы и распознаёт сербскую кириллицу и латиницу официальными моделями
Tesseract `srp` + `srp_latn`.
Если Space недоступен, до 12 страниц распознаются последовательно одним
Tesseract.js worker в браузере; более длинный скан не запускает тяжёлый
fallback и просит использовать сервер.

### Админ-панель

`/admin` виден только аккаунтам с серверным флагом `is_admin`. Адреса первых
администраторов задаются в `CITAVUK_ADMIN_EMAILS`; каждый `/v1/admin/*`
повторно проверяет роль в Go.

Панель показывает онлайн и продуктовые счётчики, пользователей и
агрегированные HTTP-инциденты. Редактор курсов хранит черновики отдельно от
опубликованных версий, позволяет добавить урок, проверить JSON и опубликовать
готовый bundle. React и Flutter сначала запрашивают опубликованный основной
курс с API, затем используют локальный bundle как офлайн-fallback.

### Курс

`scripts/prepare-course-assets.mjs` копирует в production-сборку единый Flutter
bundle `frontend/assets/course/course_bundle.json`, атласы спрайтов и звуки.
Не создавайте вторую копию учебного контента в `web/src`: Flutter и React
должны получать одинаковые уроки и одинаково различать `č/ć`, `dž/đ` и порядок
слов. Маршруты `/course` и `/course/lesson/:id` загружаются отдельными чанками.

Внутри одной попытки упражнения перемешиваются по уровням сложности: вводный
материал не прыгает после сложного, но порядок и позиции ответов при повторе
меняются. Matching разрешает проверку только после заполнения всех строк.
Результат ниже `passThreshold` не получает зелёную галочку. Для свободного
ввода есть экранная клавиатура сербских латинских и кириллических букв.
До подготовки ровного атласа `CourseSprite` показывает только первый кадр.

Теория урока доступна без аккаунта, упражнения и синхронизация прогресса требуют
входа. Bundled JSON загружается параллельно с короткой проверкой серверной
публикации, поэтому недоступный API не блокирует первый урок.

Локальный результат сохраняется сразу, затем
`GET/PUT /v1/course/progress/{courseId}` объединяет его с серверным по времени
изменения уроков. Обрыв сети не блокирует уже загруженный курс.

Страницы курса являются lazy chunks. При `vite:preloadError` клиент один раз
обновляет вкладку, а общий error boundary не позволяет оставить пустой фон.
Выкладка сохраняет старые файлы из `/assets/` на 14 дней: вкладка, открытая до
релиза, может запросить прежний chunk только после позднего перехода в курс.

### Аудирование

`/listening` получает каталог из Go-маршрута `/audio/lessons`. Реплики не
берутся из RSS-описания: это не транскрипт, и пропорциональные тайминги там были
выдуманными. Настоящие расшифровки лежат в `public/transcripts/`; сервер
сопоставляет аудио с JSON через `index.json`, а плеер загружает только открытый
эпизод. Если файла ещё нет, аудио остаётся доступным, а сайт честно показывает
«Транскрипция готовится».

Каталог создаёт `scripts/transcribe-podcasts.py`: Groq
`whisper-large-v3-turbo` возвращает пословные тайминги. MP3 режется по границам
кадров, M4A предварительно переводится `ffmpeg` в самостоятельные
пятиминутные MP3-фрагменты. Ключ читается только из `GROQ_API_KEY`; в сайт он не
попадает.

```powershell
$env:GROQ_API_KEY = "..."
python -X utf8 scripts/transcribe-podcasts.py --limit 0 `
  --feed learn-serbian --feed moze-kafa --ffmpeg C:\path\to\ffmpeg.exe
python -X utf8 scripts/transcribe-podcasts.py --normalize-only
python -X utf8 -m unittest scripts/test_transcribe_podcasts.py
```

Чужой MP3 идёт через `/audio/proxy`, иначе CORS подкаста часто запрещает
воспроизведение и перемотку. Длинный транскрипт использует
`content-visibility: auto` и не отрисовывает сотни невидимых реплик.

### Синхронизация

`src/api/sync.ts` повторяет модель приложения: отправить своё → забрать чужое →
догрузить недостающие тексты. В одном курсоре идут книги, словарь и SRS-review.
Запускается при входе, при возврате связи, раз в две минуты и при уходе со
страницы. Прогресс курса синхронизируется отдельным LWW endpoint.

Хранилище — IndexedDB (`src/lib/db.ts`), а не localStorage: тот ограничен
примерно пятью мегабайтами и работает синхронно, а книги с других устройств его
переполнят. Метаданные и текст лежат в разных хранилищах, чтобы список книг не
вытаскивал в память сами книги.

Инварианты, которые нельзя ломать:

1. Удаление оставляет **надгробие**, а не стирает запись: иначе другое
   устройство вернуло бы книгу обратно при следующей отправке.
2. Флаг `dirty` снимается **только после подтверждения сервером** — иначе
   изменения теряются при обрыве связи.
3. Текст книги качается **при открытии**, а не при синхронизации.
4. Скачанный текст сверяется с адресом, за которым мы шли: иначе книга могла бы
   молча подмениться.
5. `dirty` снимается только если локальный `updatedAt` всё ещё равен отправленной
   версии: правка, сделанная во время запроса, обязана остаться грязной.

### События

Временные события живут на `/events`; содержимое первого события, «Одиссеи»,
открывается на `/events/odyssey` только после входа. Баннер показывается с
1 августа до 1 сентября 2026 года. Текст собирается воспроизводимым скриптом
`scripts/prepare-odyssey-event.py` из public-domain издания перевода Томо
Маретича 1915 года и переводится в сербскую кириллицу без модернизации языка.
Иллюстрации в `public/events/odyssey/` взяты с Wikimedia Commons; у каждой
репродукции на странице есть автор и ссылка на источник.

Прогресс хранится локально под ключом аккаунта для офлайн-чтения и объединяется
с авторизованным серверным документом `event-odyssey-2026` через существующий
endpoint `/v1/course/progress/{courseId}`. Песни засчитываются только по порядку.
После всех 24 песен `readerSettings.ts` разрешает фон `odyssey`; без награды
этот фон не применяется, даже если его значение осталось в localStorage от
другого аккаунта.

Мобильная шапка показывает разделы компактной сеткой по группам «Читать»,
«Учиться» и «Читавук». Не возвращайте один длинный вертикальный список: при
росте числа разделов он снова потребует прокрутки до ежедневных действий.

## Выкатка

```bash
./deploy/deploy.sh            # собрать и выложить
./deploy/deploy.sh --nginx    # плюс обновить vhost
```

Файлы кладутся во временный каталог и переставляются одним движением: при
копировании поверх работающего сайта посетитель успел бы получить свежий
`index.html` вместе с уже удалёнными бандлами и увидел бы пустую страницу.

Сервер общий с чужими сайтами, почтой и DNS — скрипт трогает только
`/var/www/citavuk` и свой отдельный файл в `conf.d`.

### Домен

`https://citavuk.ru` и `https://www.citavuk.ru` работают: A-записи ведут на
`85.137.89.21`, сертификат Let's Encrypt выпущен, HTTP редиректит на HTTPS,
продление автоматическое.
